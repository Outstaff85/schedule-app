# Scanner training (how the scanner learns)

The whole training of the scanner in one place: where the examples come from, where they are kept, how a model is trained, checked and handed over, and what the owner does. Approved by the owner on 2026-10-18 (docs/scan-plan.md → S6). The scanner itself is docs/scan.md → The scan window.

## The idea in one line

**The site collects → the owner's PC trains → the lab tries → the site gets the new model.**

```
 site (src/scan/)            Storage / Firestore              owner's PC                 Hugging Face                 lab (/scan-lab/)   site
 users correct corners  ──►  training/scan/, scanTraining ──► /scan-train: pull, train,  ──► OutStaff/scanner-models ──► tried on the ──► set for the site
 and document types          (or the private HF bucket)       exam, publish (on "yes")       tag v<N>, set for the lab   phone           when better
```

- **The site's scanner** is the only source of examples: real scans by the firms' users. The lab collects nothing (no login, no data).
- **The models' home is Hugging Face** (docs/hf-plan.md): the public repo `OutStaff/scanner-models`, one tag per version (`base-v1`, `v2`…), every file of the version in its commit, named by what it does (`edges.onnx`, `edges-lite.onnx`, `face.onnx`, `doctype.onnx`, `doctype-lite.onnx`, the exam reports). The examples are in Firebase (Storage `training/scan/`, Firestore `scanTraining`). A version not moved yet (`move_to_hf.py`) is still read from Storage `models/scan/<version>/` under its old names (`sa24.onnx`, `lite.onnx`, `yunet640.onnx`).
- **The lab and the site never share code or a model file** (CLAUDE.md → Scanner: the lab and the site are apart); each names the model version it uses.

## 1. What is collected (on the site)

In the scan window (docs/scan.md → The scan window):

- **Corners** — a tap on a page opens its photo with the frame the model found; the user drags a corner and taps Apply. The model's corners and the user's are an example.
- **Page kind** — each page shows the kind Haiku gave it (ID card, its back, ספח, passport, contract, other); the user can pick another. Haiku's kind and the user's are an example.

On **Done**, every page the server found is sent in the background to the function `scan_feedback` (`src/scan/server.ts`, `sendFeedback`); with no network the examples wait in a queue on the phone (`localStorage` `scanFeedbackQueue`) and go the next time the scan window opens. A page:

| | sends | kept? |
|---|---|---|
| corners moved (≥ 0.5 % of the photo) | both corners + a 256×256 copy of the part of the photo the model looked at | yes |
| kind changed | both kinds + a 256×256 copy of the page | yes |
| neither — one page in five (`rightSeen`) | its corners and kinds + the same 256×256 copy, marked `keep`, and a 256×256 copy of the page | yes, as "the model was right" (`right: true`) — so the training also learns what the model already does well and does not forget it, and the document type model gets pages of every kind, not only Haiku's mistakes |
| neither — the other four | the corners and kinds only | no — only counted |

**What each page example also carries** (the training audit, 2026-10-24 — so a training can keep one scan and one worker on one side of its exam, and the deletion on request finds a worker's copies): `sessionId` — the scan's session (one per scan: a new scan makes it, `resetScan` → `newScanSession` in `src/scan/server.ts`; "Scan again" keeps it; the full document sent on the save carries the same one), `workerId` — the worker's id when the scan is of a known worker (a rescan from their window), and `turnBy` — who set the turn the page and its copy are at (`face` when the lab page in the window set it upright by its face — the face finder's turn, posted with each page by `scan/embed.js`; the model or Haiku then only types it, as the PC's `docfind.with_doctype` —, else `haiku`, or `model` when Mixed took the document type model's turn). The scanner lab's own page sends its document type examples too (`addKind`, scan-lab/index.html: only a type the owner picked or confirmed): `origin: "lab"` with the lab's model version (kept as sent — a site example is recorded with the site's version), `turnModel` (the model's turn, in clockwise quarter turns) and `turnBy` — `face` when the face finder set the page upright (every page it cut: the shot's first, the other documents found on it, a picked picture's, one cut again by Fix corners), else `model` (the copy is the page as cut: its upright turn is not known, `turnModel` is only the model's guess). `turnFixed` (the turn the owner gave by hand) is taken and kept too, for when the lab shows a turn button. A firm whose collection the super-admin turned off (`collects_documents`) keeps no page copy: its pages are only counted.

**What the document edges model learns from** is the photo as the model saw it — before it was cut, straightened or enhanced — scaled to 256×256, which is exactly the model's input: the copy, where the model put the corners on it, and where they really are. The cut page is not needed for the corners; it is used only for the page kind, which a future kind model reads on cut pages. Never the full photo; only small copies.

## 2. Where it is kept

`scan_feedback` (`functions/main.py`, checks in `functions/feedback.py`, the files through `functions/datastore.py`; a manager login's ID token; its actions: `add` — the examples above, `document` — a full document (below), `attempt` / `attemptOutcome` — every scan attempt (S8, below), `stats`, `mode`, `settings` / `setSettings`). **Where the files go** (docs/hf-plan.md → H7): the **private** Hugging Face bucket `OutStaff/scanner-data` (the secret `HF_DATA_TOKEN`, declared on `scan_feedback` — a token that may only write there; never public); a write the bucket refuses (out of reach, no token) goes to Firebase instead, as before H7, so nothing is lost:

| | the private bucket | Firebase (until the token is there, and what is not moved yet) |
|---|---|---|
| the edges copy | `edges/<YYYY-MM>/<id>.jpg` | Storage `training/scan/<YYYY-MM>/<id>.jpg` |
| the page copy | `doctype/<YYYY-MM>/<id>.jpg` | Storage `training/scan/<YYYY-MM>/<id>-page.jpg` |
| the record | `records/<YYYY-MM>/<id>.json` | Firestore `scanTraining/<id>` |
| a full document (H8a) | `documents/<tenant>/<YYYY-MM>/<id>/page-<n>.jpg`, `record.json` | Storage `training/documents/…` |
| every scan attempt (S8) | `attempts/new/<site\|lab>/<YYYY-MM-DD>/<id>/picture.jpg`, `answer.json`, `outcome-<time>.json`; after a training the folders trained on go to `attempts/used/v<N>/…`, those kept as the exam to `attempts/exam/<site\|lab>/<YYYY-MM-DD>/<id>/` (a real exam that grows: pulled as the exam on every run, never trained on); `attempts/golden/` (a named set of the owner's lab shots, when there is one) is never moved | Storage `training/attempts/…` |

What is in Firebase moves to the bucket with `scripts/scan-train/move_data_to_hf.py --apply` (it creates the bucket private and refuses a public one; run on 2026-10-19 — nothing was there yet); it is kept for an example that lands in Firebase when the bucket refuses, and the pulls read both.

- the copies → (above);
- the record → `edgesModel`, `edgesFixed`, `moved`, `doctypeModel`, `doctypeFixed`, `doctypeBy` (who gave `doctypeModel`: `haiku` or `model`), `right` (a page the model got right, kept as a sample), `source`, `origin` (`site` or `lab`), `model` (the model version that answered: the lab's as it named it, else the site's, `functions/scan_models_version.txt`), `sessionId`, `workerId`, `turnModel`, `turnFixed`, `turnBy` (above; `null` when not sent), `tenantId`, `image`, `pageImage`, `createdAt`, `deleteAt`;
- the counts → Firestore `scanTrainingStats/current`: `edgesSince` (corner corrections since the last training — the kept right pages and the scan window's `page` examples do not count), `kept`, `right`, `movedSum`, `doctypesSince` (the page copies of each kind, by the kind the user left — for the document type model), and after a training `lastTrainedAt`, `lastVersion`, `lastReport`.

**Names (docs/hf-plan.md → H0, 2026-10-19):** the fields say which model they teach — `edges*` the document edges model, `doctype*` the document type model. Before H0 they were `cornersModel` / `cornersFixed`, `kindModel` / `kindFixed` / `kindBy`, `newSince`, `kindsSince`, `lastKindsTrainedAt` / `lastKindsReport`. `scripts/scan-train/rename_fields.py --apply` has run (2026-10-19; nothing was stored under the old names); the old names are still read, for a phone with the old app: `scan_feedback` takes an example under either name (a phone with the old app, a queued example), the counters add the old one to the new (`feedback.edges_since`, `feedback.doctype_counts`), the pulls map an old record (`common.named`), and a publish clears the old counters.

**Full documents for the field reader model (H8a, owner 2026-10-19):** on the save of the worker window after a scan (a new worker, or a rescanned one — `saveWorker` → `ManagerBridge.sendScanDocument`, `scanDocument` in `src/scan-process/session.ts`, `sendScanDocument` in `src/scan/server.ts`), the scan goes to `scan_feedback` (`action: "document"`): the document's own pages as the AI read them (not a contract, not an "Other" page; the primary marked), each page's document type, the AI's read with its `fieldBoxes` (where each field is) and the other pages' reads, the fields the scan filled (`scanned`, `workerFields`) and the fields saved (`saved`) — `corrected` lists where they differ, the AI's mistakes —, the worker's id and the scan's `sessionId` (the same as its page examples'). Never the worker's other fields (rates, phone). **On for every firm by default**; the super-admin turns it off for a firm (`tenants/<id>/settings/scan.collectDocuments: false`, `collects_documents`). The counts: `documentsSince`, `documents`, `fieldsCorrected`. Kept without a time limit; the legal check and the notice to the workers are the owner's.

**Every scan attempt (S8, owner 2026-10-20; docs/scan-plan.md → S8):** `scan_feedback` `{"action": "attempt", "attempts": [...]}` (any manager login, up to 10 per request) takes the scanner's attempts from the site and the lab — none from a firm whose full-document collection is off (`collects_documents`, `feedback.attempts_wanted`; the super-admin, with no firm, always): the picture (a JPEG up to 1.5 MB), the models' corners (none when the picture was taken whole), the corners the user moved (kept only when moved ≥ 0.5 %), the outcome (`kept`, `retaken`, `deleted`), the retake group, the source (`site` / `lab`), how it came in (`camera`, `photo`, `pdf`), the model version, the way it ran and how many pages it was cut into (checks: `feedback.check_attempt`). Each goes to its own folder with `answer.json` (`attempt_record`, with the sender's `tenantId`), and the answer names the folders; a later outcome is `{"action": "attemptOutcome", "dir", "outcome", "page"?, "workerId"?}` — `deleted` (a kept page deleted from its batch; `page`: which of its pages) or `saved` (the worker window saved after the scan, with the worker's id, at most 64 characters — needed) — written beside it as `outcome-<time>.json` `{outcome, page, workerId, at}`; only a login of the attempt's own firm may add one: each kept attempt gets an owner note in Firestore, `scanAttempts/<feedback.attempt_key(folder)>` `{tenantId, dir, createdAt}`, and the note's `tenantId` must be the caller's — else 403 (an attempt kept before the notes: its `answer.json` read back, `datastore.get` — from Firebase, or from the bucket only where the server's write-only token may read; none found: 404; `feedback.check_outcome`). The site's scan window sends `saved` for every attempt of the scan when the worker is saved (`attemptsSaved` in `src/scan/server.ts`: the lab page in the window tells it its attempts' folders as they come back, `scan-attempt-dirs`), so the deletion of a worker's data finds them; pages deleted before the attempt was sent come in it as `deletedPages`; the corners the user moved in the corner editor come as `edgesFixed` (the first document) and `edgesMoreFixed` (the others, `null` where not moved). The phone's side (what is an attempt, when it is decided, the queue): docs/scan.md → The scan window. The count: `attemptsSince` and `attempts`.

**Privacy:** no client can read or write any of it (no Firestore or Storage rule opens them, the bucket is private); only `scan_feedback` writes (an attempt's firm check reads its owner note in Firestore `scanAttempts`, never the bucket), only `/scan-train` on the owner's PC (the owner's own Google account and HF token) reads. The super-admin's per-firm switch (Admin → Scanner, `collects_documents`) stops a firm's full documents, its scan attempts and its page copies alike; the super-admin with no firm (the lab) is always kept.

**Deleting on request:** `scripts/scan-train/delete_data.py --firm <tenantId>` or `--worker <workerId>` — without `--apply` it only lists, and prints the counts per area (never a path: the ids are in them). A blank id is refused (it would match every record without one). A bucket listing or download that fails stops the run before anything is deleted (an expired `hf auth login` must never look like "nothing there"); a file that names an owner but does not parse is counted, and `--apply` is refused while any is:

| | `--firm` | `--worker` |
|---|---|---|
| documents | `documents/<tenantId>/…` in the bucket, `training/documents/<tenantId>/…` in Firebase | each `record.json` whose `workerId` is the worker's — its whole folder, in both |
| page copies | the records (bucket `records/…`, Firestore `scanTraining`) whose `tenantId` is the firm's, with their copies | those whose `workerId` is the worker's (sent once the worker was known), or whose `sessionId` is the scan session of one of the worker's full documents (a new worker's scan, saved), with their copies |
| attempts | `attempts/new`, `used`, `exam` and `golden` in the bucket and `training/attempts/…` in Firebase: each folder whose `answer.json` names the firm; the firm's owner notes (`scanAttempts`) | each folder with an `outcome-*.json` naming the worker (the `saved` outcome), and its owner note |
| on this PC | the pulls' copies of what was found: `templates/<kind>/<document>-<n>.jpg`, `doctypes/<copy>.jpg` (and its turned copy `<copy>-t<k>.jpg`), `img/<copy>.jpg`, `attempts/<attempt>.jpg`, `img/att-<attempt>-<page>.jpg` | the same |

A page copy's record kept in Firestore while its copies went to the bucket (the bucket refused only the record) has its copies deleted from the bucket. With `--apply` it deletes them for real (no history in the bucket). A page copy or an attempt sent before the worker was known and never told (the scan closed without a save, or before this was built), and with no saved full document of the same scan session, carries no worker's id: only `--firm` finds it. `pull_templates.py` also deletes, on its next run, every page it pulled whose document is no longer in the bucket (the owner's `own-*` pages and pages put there by hand stay). Synthetic sets made earlier from a deleted page are not traced; they hold no face or text of it (washed out).

**Time limit:** none in the bucket (owner, 2026-10-19 — the delete-on-request script instead). In Firebase, until moved: each record has `deleteAt` = +365 days and Firestore deletes it (the TTL policy in `firestore.indexes.json`); the copies under `training/` are deleted after 365 days by a Storage lifecycle rule (`scripts/scan/storage_lifecycle.py`, set by the rules deploy; it needs Storage Admin on the deploy's service account — the deploy warns if it could not set it).

## 3. When to train

When **20** new corrections are kept (owner, 2026-10-20: 20 for every model), the super-admin's bell shows **Time to retrain the scanner** (the server counts; the app asks `scan_feedback` `{"action":"stats"}` at most every 6 hours). When every page kind but "Other" has **20** page copies (`doctypesSince`, `feedback.DOCTYPE_AT`), it shows **Enough pages for the document type model** (`doctypesDue`). When **15** new scan attempts are in (`attemptsSince`, `feedback.ATTEMPTS_AT`; S8), it shows **New scan attempts — time to train** (`attemptsDue`). Nothing trains by itself.

## 4. How a model is trained (`/scan-train` on the owner's PC)

The skill `.claude/skills/scan-train/SKILL.md`, run in Claude Code on the owner's PC (RTX 4070), runs `scripts/scan-train/` step by step:

1. **`pull.py`** — downloads every kept corner example to `~/.scan-train/`, and every new scan attempt (S8, `attempts/new/` — in the bucket, or in Firebase where the bucket refused it): its examples by `attempts.py` (a kept page — its moved corners, else the model's — on the photo with the documents found before it painted over in the border's colour (not the one it lies on: an ID card found on its ספח's cut); a deleted page — "nothing here", empty maps; a retaken page with no corners moved — the exam only, as a hard page), and the new folders pulled (`attempts.json`, `{"train": [...], "exam": [...], "hardLeftOut": n}`). About one key in seven is kept apart as the **exam** and never trained on — by the split key (→ Kept apart below): a record by its worker, else its scan session, an attempt by its retake group (the worker's when any attempt of the group was saved with one), never by a record's or an attempt's own id, so every retake of one shot is on one side; a retaken page with no corners moved whose group trains is in neither the exam nor training (counted as `hardLeftOut`); a record kept before the ids were has none and is split by its id as before (`legacy`). The attempts kept as the exam by the publishes before (`attempts/exam/`, bucket and Storage) are pulled on every run too, always as the exam, and every example with their keys goes with them (`pull.kept_exam_keys` → Kept apart). A bucket listing or download that fails stops the run (the full documents' records, the attempts): a failed listing is not an empty one. Each example carries its `key`, `split` and an attempt's `group`.
2. **`train.py`** — fine-tunes both corner models — `lite.onnx` (the phone's live frame) and `sa24.onnx` (the server's accurate one) — starting from the **lab's** current version (`scripts/scan-lab/models-version`), or from another one with `--base <version>`:
   - the ONNX file is turned into PyTorch (`onnx2torch`) and checked to answer like the original; its batch is set free first (`onnxbatch.free_batch`: the input's first dimension named, a Reshape's constant leading 1 made 0 — the input's own batch), since a version exported with its batch baked in as 1 (v3's `edges.onnx`, 2026-10-22) cannot be trained in batches of 16;
   - each corner becomes a target spot (a Gaussian of the models' own spread, σ ≈ 2.4 heatmap pixels) where the user put it; a page the user deleted (S8) has no spots — "nothing here"; the error is taken against the corners started from whichever corner fits the model best (`corner_loss`): a document turned near 45° has two "top-left" corners of the photo, and a fixed order taught the model to put its first corner between them — on MIDV's turned scans it then found no document (owner, 2026-10-22); the cut page is turned upright afterwards anyway;
   - the loss weighs the spots over the empty background (a plain one makes every peak fade), batch norms keep their statistics, mirrored pages and light changes are added;
   - the trained model is exported back to ONNX with a free batch (`dynamic_axes`, then `free_batch` once more) and checked again, on one picture and on a batch of two, so the next version can be trained further. ~15–30 min on the 4070;
   - with `--more` (or `--resume`) the network is built from the graph the saved weights belong to — their `info.base`, not `--base`: v4's weights are of v3's graph, and every export adds a name level, so they load into no other — and an explicit `--base` that differs is refused with what to give (`graph_of`); the checkpoint's info records where the run went on from (`info.from`: that base, its epochs and the version `publish.py` stamped on it — a run never published, perhaps one the owner turned down, is pointed out). `--synth-run <folder>` names another made-up set than `~/.scan-train/synth/docs`.
3. **`exam.py`** — the exam pages are read by the old models and the new ones, set by set: the users' pages kept apart, **the owner's own documents** — made-up photos of the real pages kept apart from training (owner, 2026-10-22: `synth.held_out` — by their content in `heldout.json`, → Kept apart; of the 22 uploaded six: four ID cards and two ספחים; `synth_docs.py --templates` never lays them, `synth_docs.py --templates --exam` lays only them, 300 photos into `~/.scan-train/synth/docs-exam/`), and — when MIDV and SmartDoc are made on the PC — up to 300 photos of each one's **exam documents** (owner, 2026-10-21: real photos never trained on, so the exam means something before the site has collected pages): MIDV-2020's documents 80–99 of each kind (as `midv_mrz.py` splits them) and SmartDoc's fifth page of each kind (`datasheet005`, `letter005`…) on every background — whole documents, so no photo, scan or frame of one is learned (`midv.open_exam`; `train.py --midv / --smartdoc` never takes them); for each model and set: mean corner error (the farthest corner, whichever corner a model starts from — `docfind.quad_error`), the share within 2 %, the share not found, and from the attempts the extra pages found where the user deleted one and how often a retaken page is answered other than the rejected frame → a "before → after" report (`~/.scan-train/report.json`, with the sha256 of each new file examined, `model_sha256`), and **the picture report** `~/.scan-train/report.html`, opened in the browser: the 10 exam pages where the models differ most, the old corners red, the new blue, the right ones green (it shows workers' documents: it stays on the PC and goes with the copies). If any model is worse on any set it says **do not publish** (`"publish": false` in the report); with no exam page in any set there is nothing to measure, and it says so — it never examines a model on the pages it trained on. **Contaminated**: `heldout.json`'s `versions` marks the versions whose edges may have seen the held-out pages (`heldout_clean: false` — v3, drawn from a made-up set that recorded no template laid, possibly before the pages were kept apart; v4, v3 trained further; v5, which carried v4's edges); for a model whose base chain (the lab's version, and the base and `from` its checkpoint records) holds one, the "your documents" set is marked `"contaminated"` in the report and on the picture report, and it is never the gate alone (`exam.gate`: with no other set with pages the answer is NO; with others it still counts, so worse there is still NO).
4. **The owner decides.** **Yes** → **`publish.py`** with the models to publish named: `--edges` (the document edges models, `report.json`), `--doctypes` (the phone's document type model, `report_doctypes.json`), `--mrz` (the passport zone reader, `report_mrz.json`), `--he` (the Hebrew field reader, `report_he.json`). Only a named model's report is read; with no flag it prints the reports it found and publishes nothing. First **`publish.py <flags> --dry-run`**: the files of the version (each new or carried over from the lab's version), what goes out of the repo, the counters it would set and the attempt folders it would move — and nothing written (no Hugging Face, Firestore or Storage write, no deletion). The checks before anything is written:
   - **A report is bound to its model.** Each exam writes the sha256 of the exact files it examined (`model_sha256`: `exam.py` — `edges.onnx`, `edges-lite.onnx`; `exam_doctypes.py` — `doctype-lite.onnx`; `exam_mrz.py` — `mrz.onnx`; `train_he.py` — `he.onnx`, `he-layouts.json`); `publish.py` hashes `~/.scan-train/new/` again and refuses a report written for another file — retrained, changed, missing, or a report from before the binding: "report_X.json is for a different model; run the exam again". Each training deletes its own report when it writes a new model (`train.py` report.json and report.html, `train_doctypes.py` report_doctypes.json, `train_mrz.py` report_mrz.json, `train_he.py` report_he.json, written again by its check).
   - **A model the exam rejected** (`"publish": false` or null) is left out unless forced: `--force-edges`, `--force-doctypes`, `--force-mrz`, `--force-he` (the owner's explicit call). `--force-doctypes` is refused while the only exam is "your documents" with a document type or the turn not measured, or its sure turns right on less than 98 % (on the phone the turn head decides a page's rotation).
   - **A model with nothing new** — a new `.onnx` that is the very file of the lab's version (old edges left on the PC, a model already published) — is refused (its `--force-<model>` overrides).

   Then the new models go to Hugging Face as the next version — one commit with every file of the version, tagged `v<N>` (the models not named and the face finder carried over from the lab's version; only the phone's document type model — a `doctype.onnx` is never carried forward; the reports of the models named beside them; the owner's HF token on the PC), the counters of the models published are reset (`edgesSince` only with the edges, `doctypesSince` only with the document type model), the lab is pointed at `v<N>` (`scripts/scan-lab/models-version`). Only with the edges in the version — the attempts are the edges' examples — the attempts of the run leave `attempts/new/`: the train folders to `attempts/used/v<N>/`, the exam ones to `attempts/exam/`; `attempts/golden/` is never moved, and `attemptsSince` is lowered by the folders really moved (something listed in the bucket or in Storage). After a publish only what it used up is deleted, even with `--keep-copies` (a report kept is what would arm the next publish): the exam report of each model published (`report.json` and `report.html` with the edges, `report_doctypes.json`, `report_mrz.json`, `report_he.json`) and `attempts.json` with the edges; the reports of models not named and the training figures (`report_mrz_train.json`, read by `exam_mrz.py`) stay. The repo's files are listed first, to delete from the version those it does not hold; when that listing fails a real publish stops (the dry run says the files leaving are unknown). The other copies on the PC are deleted too (but the MIDV and SmartDoc downloads; `--keep-copies` keeps them, when another training still needs the examples, templates and made-up photos). **No** → **`clean.py`** deletes the copies (but the MIDV and SmartDoc downloads); nothing changes.

### Stopped and picked up again (checkpoint.py)

The document edges, document type and Hebrew field trainings (`train.py`, `train_doctypes.py`, `train_he.py` through `train_mrz.fit`) save each model's progress after every epoch — the weights, the optimizer's and the schedule's state, the epoch, the best weights so far — to `~/.scan-train/checkpoints/<model>.pt` (written aside, then put in place, so a crash or a power cut while writing leaves the last one whole; owner, 2026-10-21). **A checkpoint is tied to its data**: its info carries the data fingerprint (`gen.manifest.data_fingerprint`, `info["data"]`) — the class table's (`DOCTYPES`) and `heldout.json`'s sha256 (what it keeps), the ids of the examples trained on, the made-up set's run fingerprint (its `run.json`), the sizes; `train_he.py` records each set's `labels.tsv` sha1, the sizes, the batch and the steps per epoch (`data_info`).
- **`--resume`** — a run that stopped (Ctrl+C, a crash, the PC turned off) goes on where it stopped with the same command (at most the epoch it was in is lost; a run that had finished is only exported again) — only with the very same info, the data fingerprint included: other data, or a checkpoint made before the fingerprint (Training 4), is refused. A resumed one-cycle schedule must have been made for this run's steps (`checkpoint.check_steps`; the passport zone reader's `last.pt` the same): a set drawn again with another count would run it past its end.
- **`--more`** — a new run (a fresh schedule, the epochs given) from the last run's weights, its best ones where it keeps them, to train a model further on more or new examples. **Refused** when the class table or `heldout.json` changed since (the old weights learned other labels, or saw what is now the exam: a change of the split or of the labels needs a fresh run), when any example it trained on is on the exam side today (a record's split can move from train to exam with `heldout.json` unchanged — its split key changes from `s:` to `w:` once a session is linked to a worker, or `pull.py` keeps more exam keys: the fingerprint keeps each training id's short hash, `trainIds` — `sha1(id)[:12]` —, and `gen.manifest.exam_ids` lists today's exam and golden records and page copies of `examples.json` / `doctypes.json`), and when the checkpoint records no data fingerprint or no training ids (made before Training 4 or its review fixes — the owner's checkpoints of v3–v5's runs: train fresh); **`--more-anyway`** goes on even then, on the owner's explicit call, with a loud warning. When only the training examples changed (more data — what `--more` is for) it says so loudly and goes on.
- Weights that do not fit the network (another base version's graph) stop the run with what to do (`checkpoint.restore`: "train with --base X --more, or without --more"), not a traceback.
- **`publish.py` stamps** the checkpoint of each model it publishes with the version (`"published": {"version", "at"}`; its `--dry-run` shows the stamp it would write), so `train.py --more` says what it goes on from.

The folder is kept by `clean.py` and `publish.py` (`common.KEPT`). The passport zone reader keeps its own (`~/.scan-train/mrz-ckpt/`: `best.pt` between trainings, `last.pt` for `--resume`, `--fresh` from random weights — The passport zone reader below).

### Kept apart (gen/common.py, heldout.json, gen/sources.py)

What the exam measures is never trained on, by construction (the training audit, 2026-10-24):

Each pull reads them afresh from the bucket and Storage (`pull_templates.py` too).

A record or page copy kept before `gen.common.KEY_RULE_FROM` (2026-11-01; no `createdAt`: counted as before) whose key now says exam but whose id the rule before put on the training side is `"split": "none"` — in neither set (`gen.common.trains(e)` leaves it out of `train.py` and `train_doctypes.py`; the pulls count it). One the rule before kept for the exam stays there; one kept from that day on goes by its key. A version trained with the per-id rule after that day would move it forward.
- **`scripts/scan-train/heldout.json`** (committed, hashes only — no file names): the owner's real pages kept for the exam by their content sha1 and document group (seeded on 2026-10-24 with exactly the six pages the old file-name rule held; a page alone is its own group `own:<sha1 prefix>` — pages of one person's documents can be given one group), the exam background ids and fonts (none yet), the vocabulary salt (the Hebrew check vocabulary: `crc32(salt + word) % 5 == 0`), and the open sets' exam documents (MIDV-2020 from document 80, SmartDoc's page 005). `synth.held_out(path)` reads it by content, so a renamed or moved file stays where it was; a site page is held out when `templates/index.json` puts its document on the exam side. **Failing closed** (`gen.common.page_side`): a site page `index.json` gives no training side (pulled before it, its document's record unreadable — counted by `pull_templates.py` —, or `index.json` missing) is "unknown": never laid on a training photo (`synth.held_out`), nor on the exam photos (`synth.exam_page`: `synth_docs.py --exam`, `synth_fields.py --check`), and `assert_clean` refuses a photo made from it. `pull_templates.py` never copies an exam-side document's pages (and deletes such a page copied before).

Training (`field_value` / `he_line` / `lines` with `held=False`, `synth_lines.py`) draws the rest and, for names, half made-up ones (`he_name`: 2–4 syllables, a final letter's own form at the end); only `synth_fields.py --check` draws the check vocabulary.
- **The registry** — `gen/sources.py`: every source as `Source{id, kind, split_key, split, sha1, path, attrs}` — the owner's and the site's templates, the drawn kinds, the PDFs (Form 101's template, contracts), the background photos, the fonts, the vocabulary, MIDV and SmartDoc (by document: `midv.doc_no` — a clip frame by its clip's folder), the real records, attempts and page copies; `pool(split)` is the only accessor. **`python -m gen sources`** (run in `scripts/scan-train`) prints them by kind and side; **`--check`** also fails when an exam or golden key is on the training side, the same file is on both sides, a site page has no side (copied before `index.json`: run `pull_templates.py` again), or `heldout.json` changed after an exam set was made, or an exam set lies on disk with no record (`synth/docs-exam`, `synth/he-fields/check` drawn before `exam_sets.json` was kept; `exam_sets.json` in the work folder: `synth_docs.py --templates --exam` and `synth_fields.py --check` record theirs — only when drawn into the work folder's own `synth/docs-exam` / `synth/he-fields/check` (`gen.common.record_own_exam_set`): a set drawn with `--out` elsewhere, a smoke run or a test, leaves the record alone). It prints "held-out pages: 6 (same as the crc32 rule)" while `heldout.json` holds the pages the old rule held — and sha1 prefixes only, never a file name.
- **What a version saw** — `heldout.json`'s `versions` names the published versions whose models may have seen what the exam keeps (`heldout_clean: false`, by model: v3, v4 and the edges carried in v5); `exam.py` marks the templates set "contaminated" for them (step 3 above). Contamination is inherited: `publish.py` adds the new version to `versions` (`gen.common.mark_version`: `heldout_clean: false`, the models, why) when a model of it is carried over from a version marked for it, or is new and its base chain (the lab's version it was trained from, its checkpoint's `info.base` / `info.from.base`) holds one, or its exam report says `"contaminated"` — so a v6 that carries or fine-tunes v5's edges stays marked even when trained fresh or on another PC; the skill commits `heldout.json` with `models-version`. `gen.common.heldout_sha256` is the sha256 of what the file keeps (`templates`, `examBackgrounds`, `examFonts`, `vocabulary`, `open` — not its notes or `versions`), so marking a version moves nothing.

### Made-up sets: build, verify, QA (gen build, gen verify, gen qa)

Every made-up set is drawn through **`python -m gen build`** (run in `scripts/scan-train`; `gen/build.py`): `--model edges` (the scenes — below; `synth_docs.py` keeps today's photos), `--model doctype` (`synth_pages.py`), `--model he` (`synth_fields.py`), each with its own options (`--count N --seed S --jobs J --out DIR` and the rest). The old commands are thin wrappers over it with their own defaults (20000 / 6000 / 3000) and write what they always wrote, so nothing downstream changes; a run's parameters name its generator (`generator`), so `gen verify` draws it again with the same one.
- **The same bytes**: each example draws from one stream of its own, `random.Random(seed * 1_000_003 + index)` as always (`gen.rng.legacy`), so an example depends only on the seed and its index — never on the batch, the number of processes or the examples before it — and the results of the processes are put in index order. Today's pictures are drawn again byte for byte (checked on the owner's PC on 50 photos and pages: before and after the change, `--jobs 1` and `--jobs 3`). `gen/rng.py` also gives separate streams per stage (scene, page, camera, phone: `SeedSequence([run_seed, index, stage])`) for the recipes that come next; the manifest names each example's scheme (`rng`).
- **`manifest.jsonl`** (in the set's folder, one row per example, sorted by index; `gen/manifest.py`): `id`, `model`, `split` (train; the exam photos and the Hebrew check set: exam), `seed`, `index`, `rng`; **`templateId`** — `tpl:<sha1 prefix>` of the real page laid, or `drawn` — with `templateSha1` and every page laid (`templates`: a card on a sheet, a document painted over); **`backgroundId`** — `bg:<sha1 prefix>` of the background photo with its category (`catalog.json` in the backgrounds folder when there, else its sub-folder), or `procedural` (with the surface drawn, `bgKind`); the fonts picked; the vocabulary half (train / check); the scene (the photo's size, nothing here, painted, a pair) and the camera (its seed); the class and the source; the labels (the corners in the model's order and in the document's own, `doc`; the page kind and turn; a field's text only as a sha1 prefix), `labelSource` (`drawn`: exact, from the drawing), `weight`, and each output file with its sha256. Hashes only: no file name of a real page, no name or number off a document.
- **`run.json`**: the git commit of `scripts/scan-train` (and whether its files had changes not committed), the libraries' versions the pixels depend on (`requirements-synth.txt` pins them: Pillow, OpenCV, NumPy, Albumentations, albucore, python-bidi — another version draws other bytes), the sha256 of `heldout.json` (what it keeps) and of the class table, the counts (by class, source, background category, drawn / real), the manifest's sha256 and the data **fingerprint** (the same seed, count and inputs give the same fingerprint whatever `--jobs`), and the parameters to draw any example again — those name the local pages, backgrounds and fonts, so `run.json` stays on the PC like the set.
- **`python -m gen verify --run DIR --sample 50`** (`gen/verify.py`; `--run` a folder, or its name under `~/.scan-train/synth/`): every row is checked against what the exam keeps — a training row laying a held-out template, on an exam background, with an exam split key or cut from MIDV's or SmartDoc's exam documents, or an exam row laying a page that is not held out, fails the run (`gen.manifest.held_refs`); every output file must have the manifest's sha256; and a sample (the same examples every time) is drawn again into a folder inside the run (deleted after) and compared byte for byte (sha256) with the labels. A warning when the libraries' versions differ from `run.json`'s. Writes `verify.json`; exit 1 on a failure. `--jobs` draws the sample in processes (the same bytes).
- **`python -m gen qa --run DIR`** (`gen/qa.py`) writes **`DIR/qa/index.html`** — local only, never uploaded (the pictures come from the owner's real pages): contact sheets per stratum (the source × the class) with the corners drawn (the first corner red, the document's own top-left blue) and the class and turn written on them, a field's text only as a sha1 prefix; the table source × class, every cell its count or n=0; histograms by class, source and background category; the line "intersection with held-out = N" and the verify result (`gen verify` on a sample is run first when the set has none of its fingerprint). No file name of a real page and no name or number appears on the sheet. **`qa/purity.json`**: passed when the intersection is 0 and verify passed, with the set's fingerprint and today's `heldout.json` hash.
- **No training without it**: `train.py --synth`, `train_doctypes.py --synth` and `train_he.py` (its training fields) refuse a set drawn through `gen build` (it has `run.json`) with no `qa/purity.json`, one not passed, one of another drawing (drawn again since), or one made with another `heldout.json` (`gen.qa.require_qa`: "run python -m gen qa --run DIR and look at the sheet"), and they run `held_refs` over its manifest again at training time — a site page's side comes from `templates/index.json`, which can move a page to the exam after the sheet was drawn: such a set is refused ("now references what the exam keeps … draw it again"); a set drawn before `gen build` only warns (draw it again). `--synth-run <folder>` gives `train.py` and `train_doctypes.py` another set than the default folder.

### Scenes: one camera for the table and the documents (gen build --model edges)

The made-up photos of `synth_docs.py` lay a tilted document on a flat crop of a background — the table is never seen at the document's slant, so the edges model can tell them apart by that. **`python -m gen build --model edges`** draws **scenes** instead (`gen/pages.py`, `gen/camera.py`, `gen/scene.py`, written by `gen/outputs/edges.py`; `synth_docs.py` keeps today's photos, byte for byte, and its `run.json` names its generator — but on a background folder with the bank's `catalog.json` it lays its documents only on the bank's usable photos of its side, training-side ones for a training run and exam-side ones for `--exam` (none yet: procedural surfaces only), and a folder with no catalog trains on every photo but `heldout.json`'s exam backgrounds (`background_photos`; its `run.json` records `photosSplit`)):
- **Flat pages** (`gen/pages.py`: `Page{rgba, size_mm, doctype, kind, material, fields, mrz_text, face_box, source, rect, ppm}`): the drawn kinds (`synth_docs.DRAW` now returns, beside the picture and its rect, each value's box — measured with `textbbox`, not one draw of the stream changed —, a passport's two zone lines and the holder's photo's box; a fold's bow moves the boxes with it, `synth_docs.unbow`), a drawn contract (`synth_pages.contract`) and **Hebrew A4 pages that are not a contract** (`synth_pages.he_sheet`: a payslip, a bank letter, a medical form, a notice — "other"), the real pages whose fields are marked (`template_vary.vary` with values from the training vocabulary, or the check one in an exam run: `seen` false), the unmarked ones washed out (no field boxes), and **PDFs rendered by PyMuPDF** at 100–150 dpi — the Form 101 template (`functions/assets/form101_fillable.pdf`, "other") and the firm's contract templates put into `~/.scan-train/contracts/` ("contract"), their fields empty. Without PyMuPDF the PDF source is skipped and counted (`run.json` `pdfSkipped`) and another page drawn; `requirements-synth.txt` pins it. A drawn passport's zone is sized to stay on the page here (`passport(fit=True)`; `synth_docs.py`'s own photos keep today's size).
- **One plane in millimetres** (`gen/scene.py`): 1–4 pages, each put by a similarity (mostly a quarter turn and a little, 15 % any angle), in one of the recipes, in the phone's search order: `single`; `pair` (2–4 pages apart, mostly turned alike); `card_on_sheet` (an ID card lying on its ספח, a loose sheet or an A4 page, at least 3 mm in, a little turned); `painted` (another page found first, painted over as the lab's `findNext` paints, on the final frame — after the light and the phone's effects, as the phone paints the photo it captured); `none` (no page; half of them on a background with text but no document, when the bank has one); `partial` (a page partly out of the frame — **weight 0** until the owner confirms its label: no corners, conf 0; `--partial-weight`). Weights `WEIGHTS` (single 0.37, pair 0.30, card on sheet 0.15, painted 0.10, none 0.08; `--recipes single=…`). Paper may be **bent** (lifted off the plane by a sine) or **folded** (a crease), each side catching its own light, or have worn rounded corners; a **finger** holds a page by an edge (never within 5 mm of any corner); **occluders** — the bank's cut-outs (`gen occluders add`), else a drawn pen, phone, keys or coin — lie over an edge or beside, never over a corner.
- **One camera** (`gen/camera.py`): a pinhole camera looking at the plane — the frame of a phone (1920 × 1080, 1280 × 720 or a ~4000 × 3000 photo, upright or wide; drawn at most 1600 px long), field of view 65–80° along its long side, 12–55 cm from the point it looks at, tilted 0–45° from straight down, from any side, turned a little; the distance the nearest that keeps every page in sight and up to 1.7 times it, nearer shots more often. **ONE homography takes the table and every page to the frame**: the background photo lies on the same plane at its physical size (its long side 450–1200 mm, or the catalog's `widthMm`) but never wider than its pixels over the frame's px/mm at the point the camera looks at (`Camera.ppm_at`) — the table as sharp as the documents on it, never a photo enlarged 3–6 times beside a sharp page ("smooth = table", a cue the phone never gives); a procedural surface (`synth_docs.surface`, ~15 % of the scenes: a category of its own) is drawn at the frame's px/mm × 1.2 over the frame's footprint on the plane (at most 3200 px; beyond, mirrored), its patterns at their size in mm (`surface(…, scale)`); the scene records both (`bgPpm`, `framePpm`); a bent page's points go through the same camera with their height. Every picture is sampled through a mip pyramid (`warp_mip`: the level from each pixel's own scale, two levels blended), so a page far away is not aliased. Then a shadow under each page and a card's glare (as `synth_docs.lay` did), uneven light and the phone's colours, blur, noise and JPEG (`synth_docs.light`, `synth_docs.camera`) — heavier physics only after an ablation shows it helps (owner).
- **Labels** — projections of each page's own corners and field boxes through that camera: `quad_doc` (its own top-left first), `quad_model` (`synth.order_corners`), `upright`, `inside_of`, `page_id` (`tpl:<sha1 prefix>`, `pdf:<sha1 prefix>` or the drawn kind), the fields' quads, the face's quad, the zone's text (a sha1 prefix in the manifest). The tests measure the rendered edges against them (each side's 0.5 crossings near a corner, two lines intersected): on 200 random scenes per recipe — card on its ספח, a bent and a folded page among them — every corner and field box within 0.5 px.
- **What is written** (`gen/outputs/edges.py`): each picture as the phone keeps one (`phone.store_attempt`: at most 1600 px, JPEG 0.85) in `img/`, and `examples.json` in `pull.py`'s form, one entry per picture with its manifest row (`manifest`) and its **role**: `answer` — the frame, its answer the largest page in sight not lying on another; `next` — the frame with the pages found before painted over as the lab's `findNext` paints them (`phone.lab_paint`, the one copy — also `docfind.find_next_lab`'s and `pull.painted`'s: each quad grown 4 % from its centre, so the page's rim and its shadow's edge go too, in the colour of the border of the frame drawn at 32 × 32, an antialiased fill), its answer the next one (`img/<n>-n<k>.jpg`; a `painted` scene's frame is one too); `inside` — a card on its sheet written as the **flat cut of the outer page** (`phone.warp_rgba` of the sheet's corners, not turned, as the lab's `findInside` cuts it), its answer the card's corners on the cut (`img/<n>-in<k>.jpg`; the lab's own way back, `phone.unwarp`, gives the card's corners on the frame) — so no picture carries two answers (the training audit's "card on its ספח yields two contradictory labels", the made-up side); `none` and `partial`: `fixed` null. Every entry names the real pages laid (`templates`, `templateSha1`), the background photo's sha1 (`bg`) and the occluders' sha1 prefixes (`occ`) for `assert_clean`.
- **Streams**: scene (the recipe, the layout, the camera, the background, occluders), page (each page's drawing) and camera (light and the phone's effects) — `gen.rng.streams`, the manifest's `rng` `seedsequence`; `gen verify` draws a sample again byte for byte as for every set. **`run.json`** counts the scenes by recipe (`byRecipe`), the answer's source (`bySource`: drawn, template, washed, pdf, none), the background category (`byBackground`), every page laid by its source (`pagesBySource`), the background surfaces used (`backgroundSeries`) and `pdfSkipped`. **The QA sheet** adds the per-recipe strata: the tables recipe × class and recipe × background category (every cell a count or n=0), a histogram by recipe, and a contact sheet per recipe with every picture of a scene — the frame, each `next` picture and each `inside` cut — with its own answer.
- `--exam` draws the exam's scenes: only the real pages `heldout.json` keeps, the bank's exam backgrounds, the exam's occluders and the check vocabulary, and no PDF (every PDF is on the training side: the exam's contract and other pages are drawn); `held_refs` fails an exam row on a training background, laying a PDF or with a training occluder (seed 7, 300 scenes; recorded in `exam_sets.json` when drawn under `~/.scan-train/gen/runs/`). Defaults: 8000 scenes, seed 1, out `~/.scan-train/gen/runs/edges-s<seed>-n<count>`; train on it with `train.py --synth N --synth-run <that folder>` after `gen qa`.

### The background bank (gen bg)

The backgrounds are a catalogued bank (`gen/backgrounds.py`), not a folder of photos:
- **`<home>/backgrounds/catalog.json`** (and `backgrounds-own/` for the owner's own shots): for each photo its category, series, licence, URL, size, sha1, split, `ownerShot`, `text_present`, and the check's `status`, `phash` and `docConf`; and `examLocked`, every sha1 ever on the exam side. **A photo is used only when its check passed and its licence is confirmed** (CC0, public domain, the owner's own); one with no confirmed licence is never sampled. `side()` is the one reading of a photo's side — the scenes' `Bank`, `synth_docs.py`'s photos and the registry all use it: exam when locked (the catalog's `examLocked`, `heldout.json`'s `examBackgrounds` — even once it is no longer used), else none when it is not usable, else its split; a photo not split yet is on neither side.
- **`python -m gen bg add DIR --category auto|<name> [--series S] [--licence L] [--owner]`** catalogs a folder (copied into the bank unless it is there): a download's `sources.json` gives its licence, URL, title and — `auto` — its category by its words (car, desk, bed-sofa, tablecloth, rug, glass, light, dark, stone, tile, wood, fabric, hand); `--owner` puts the owner's shots into `backgrounds-own/` with the licence `owner`.
- **`python -m gen bg check [--min-side 1600]`**: a photo under 1600 px on its long side is `small`; of near-duplicates by pHash (OpenCV's DCT, at most 6 of 64 bits apart) the larger is kept, the others `duplicate`; a photo in which the lab's edges models (`scripts/scan-lab/models-version`, from `<home>/models/<version>/`, the light one on the live input and the accurate one on the capture, on the whole photo and its four quarters) see a document with conf ≥ 0.5 is `document` — a background with paper teaches the model to pass documents by; a photo with text but no document's shape (dark letter-sized marks chained on baselines, covering under a fifth of it — a woven texture's marks cover all of it) is marked `text_present`: a hard negative the `none` scenes prefer. Series: one surface shot again — an explicit `--series`, else the same download title's first four words or pHashes at most 12 bits apart, whatever the categories (two shots of one table may get two categories from their words). Of near-duplicates the photo on the exam side is kept first, then the one that trained, then the larger; a new photo of a series on the exam side goes to the exam at once (while the series has fewer than 3 of its category there, else none). It prints the photos used by category, the surfaces, the rejected by reason, the ones with no confirmed licence and the hard negatives.
- **`python -m gen bg split [--share 0.2]`**: about a fifth of the new surfaces go to the exam, by the crc32 of the series' id — a series (whatever its categories) stays on one side —, at most 3 photos of one series per category in the exam, the rest of it in neither set. **The exam side is sticky**: what was on the exam side is in `examLocked` and stays there whatever is added later (the next downloads after the split) — a series holding a locked photo is the exam's, a photo of it that trained before goes to none (`twinOfExam`, counted in the report: its near twin is in the exam), a new photo of a training series trains, and only a series of new photos alone is split by the crc. The registry (`gen sources`) and every training's check (`assert_clean`, `gen verify`) take the locked and exam photos as exam backgrounds; a photo the catalog never uses, or does not list, is in neither set. Until `bg split` has run, the scenes lay no photo (`gen build` says so).
- **Sampling** (`Bank`): balanced by category, then by series (a series counts once), then a photo; `--procedural-share` (0.15) of the scenes get a procedural surface. When the bank has 150 photos or more the photos' share can go up (the generator spec: about 0.85).
- **`python -m gen bg pull` / `push`**: `datasets/backgrounds` and `datasets/backgrounds-own` in the private bucket through `datasets_hf.py` (its sets now include `backgrounds-own` and `occluders`); `push` is the owner's step after looking at the bank — no generator writes to the bucket. **`python -m gen occluders add DIR --category cup --size-mm 80`**: cut-outs (PNG with an alpha channel; a picture with none is skipped) into `<home>/occluders/` with their long side in mm. A cut-out's side is the crc32 of its sha1 (`occluder_side`, about a fifth to the exam): the scenes of each side lay only their own (the drawn pen, phone, keys and coin on both), and the registry's `occluder` sources make `assert_clean` and `held_refs` check them.
- **The bucket's photos today** (checked 2026-10-24, the lab's v5): the 74 photos of `datasets/backgrounds` are 960–1024 px on their long side, so `bg check` rejects every one as `small` — the scenes then lay their pages on procedural surfaces only. With `--min-side 960` (the smoke's second run): 8 photos in which v5 sees a document (conf 0.51–0.91), 3 near-duplicates, 1 with text and no document; 63 used in 10 categories (fabric 20, stone 10, rug 9, wood 7, dark 5, desk 4, bed-sofa 3, tablecloth 3, light 1, tile 1), 56 surfaces, 10 photos in the exam. The 1600 rule wants the photos at their full size again (each one's URL is in the catalog) or the owner's own shots.

### The phone mirror (gen/phone.py; E4: gen exam-phone)

The scanner lab shrinks and cuts a picture its own way before a model sees it, and training and the exams used to do it another way (cv2 `INTER_AREA`; the Chromium measurement below puts the two 24 dB apart on a camera frame): **`scripts/scan-train/gen/phone.py`** is the phone's input path in Python, ported from `scan-lab/scan-core.js` and `scan-lab/index.html` (copied to `scan/`) — a change on either side is mirrored on the other (CLAUDE.md → Duplicated on purpose). Pure numpy (OpenCV only for the `area` kernel and the JPEG), no torch, no Google package.
- **Exact ports**: `corners(hm)` (scan-core.js `corners`; `docfind.py` re-exports it — one copy in Python), `homography` / `warp_rgba` (`warpRGBA`: bilinear, no antialiasing, the sides by `Math.round`, no exact proportion, what falls outside the photo 0, alpha too), `mrz_find` (`mrzFind`, to the pixel) with `line_input` (`mrzRead`'s 32 × 512 grey input), `he_line(page, box)` (`heLine`: margins 1.5 % / 25 % of the box), `face_input` (`faceScore`: the 320 letterbox at the top-left, BGR, each of the 4 turns), `doctype_input` (`doctypeAnswer`: 256 × 256, the aspect not kept), `store_attempt` (`newAttempt`: at most 1600 px, JPEG 0.85), and the rules by which the lab takes more documents on one photo: `doc_shape` (`docShape`: every side at least 15 % of the longest, every corner 35°–145°), `lab_good_quad` (`goodQuad`: sure, convex, over 3 %, no aspect rule), `in_quad` / `lab_quad_iou` (`inQuad` / `quadIoU`: counted at the centres of a 64 × 64 grid), `lab_border_colour` / `lab_ring_colour` (`findNext`'s paint colour: a 32 × 32 drawing of the photo, its border's upper middle value per channel), `lab_paint` / `lab_paint_polys` (`findNext`'s painting: each found quad grown 4 % from its centre, an antialiased canvas fill), `unwarp` (`findInside`'s homography back onto the photo) and `INSIDE_MIN` / `INSIDE_MAX` / `LAB_MAX_DOCS` (`findInside`'s 3–60 %, `MAX_DOCS`).
- **The resampling** — the one thing a browser decides for itself: `frame_to_S(img, op)` with op `live` (the camera frame by `createImageBitmap`, `resizeQuality: 'low'`), `capture` (`smallRGBA`: `drawImage` onto the 256 canvas at the default smoothing; the document type square, the face finder's letterbox and the stored photo are drawn the same way) or `high` (`imageSmoothingQuality = 'high'`: the zone and field lines). Each op's **kernel** comes from **`gen/phone_profile.json`**: `bilinear` (one sample per pixel, no mipmaps — Chromium's 'low'), `mipmap` (Skia's linear mipmaps), `high` (the mipmaps when shrinking, the Mitchell cubic when enlarging — Chromium's 'high'), `cubic`, `area` (INTER_AREA), `nearest`. No phone has been measured yet, so each op draws from a **kernel mix** (live / capture: bilinear 0.6, mipmap 0.25, area 0.15; high: high 0.6, mipmap 0.2, area 0.2), and the profile's name with its file's short sha256 (`phone.profile_id()`, e.g. `default-mix:885681620955`) is written beside what it made — the checkpoints' data fingerprint (`resize`) and the E4 report. The exams take each mix's heaviest kernel (the same every run).
- **Measured in Chromium on every PR** (`tests/e2e/phone-parity.test.js`, 20 fixed frames through the lab's own functions): `createImageBitmap` 'low' and `drawImage` at the default smoothing are `bilinear` (worst frame 77 and 44 dB), 'high' is `high` (worst 50 dB); the profile records it under `browsers.chromium`. **Safari is not measured** (`browsers.safari` null; the test's `run.json` says so).
- **`python -m gen profile --frames DIR`** writes the probe's 20 fixed frames (PNG, with `frames.json`); **`python -m gen profile --from probe.json --frames DIR [--out FILE]`** fits a profile to a browser's outputs of every path on them (`phone.fit_profile`: for each op the kernel nearest it, by the worst frame's PSNR; the zone's boxes checked against `mrz_find`). The lab's probe page (Settings → the same frames through each path, saved as `probe.json`) is not built yet: it needs the owner's phones. Until then the default mix stays.
- **Training resamples like the phone**: `train.py` makes each photo's 256 input once, at load, by `frame_to_S` — half as the camera frame's live input, half as the capture's, the kernel drawn from the mix, by a stream of its own (`random.Random("train.py:resize")`, the same every run) —, and `train_doctypes.py` draws each page onto its square as `doctype_input` does (a site copy is 256 already and stays as it is); `--resize area` gives INTER_AREA as before. The fingerprint's `resize` changes with the profile, so `--more` warns on it like any data change. The photos are resampled from the size they are kept at (a made-up photo's long side is 640, a camera frame's 1920): the stored photo, not the camera's.
- **The exams on the phone's path**: `exam_doctypes.py` cuts "your documents" with `warp_rgba` and reads every page through `doctype_input`; `docfind.detect` takes `resize` ("area" — the default, as `exam.py` reads — or "live", "capture", "high", optionally `:<kernel>`), and so do `detect_padded`, `find_next` and `find_inside` (the lab's `findInside`: a document lying on a found one, on its flat cut, 3–60 % of it, taken back onto the photo). `find_next(..., lab=True)` (`find_next_lab`) is the lab's `findNext` step by step — its acceptance (`goodQuad` on the model's answer, then `docShape` in the photo's pixels and `quadIoU` ≤ 0.3 against every found one), its paint colour, the margin and the strips by `Math.round` with no smallest size, the painting antialiased like a canvas fill; without it `find_next` keeps `docfind.py`'s own rules (`good_quad` with the photo's shape: no longer than 3 : 1; `border_colour`), which its `pages()` uses.
- **E4 — `python -m gen exam-phone --model edges --count 40 [--version V] [--out DIR]`** (`gen/exam_phone.py`): the lab's edges models (`scripts/scan-lab/models-version`; `model_path` fetches them) on up to `--count` photos of each exam set (`synth/docs-exam`, MIDV's and SmartDoc's exam documents — the same ones every run), with no retraining: for each model and set the mean corner error, the share within 2 % and the share not found by INTER_AREA, by `live` and by `capture` (`phone` names the light model's live input and the accurate one's capture), the templates set marked `contaminated` as in `exam.py`; then the lab's whole shot on each path (`area`, `phone`): the light model's live corners (none: no shot), the accurate model's confirming them, up to three more documents by the lab's `findNext` (`find_next(lab=True)`) and one lying on each by `find_inside` (5 at most), the lab's rules on both paths — counted: shots, confirmed, moved, the documents found, photos with more by `find_next` (MIDV and SmartDoc photos hold one document: there these are extra ones), photos with one inside, the made-up photos with two documents where both were found, the photos with none where a shot was taken, and the first document's error. Writes `exam_phone.json` (with the model files' sha256 and the profile) and prints the table. The run of v5 (40 photos a set, 2026-10-24, with the lab's `findNext` rules): the first document's corners the same on both paths (mean error 0.002–0.004, all within 2 %); the lab's `findNext` found more documents on the phone's path — on MIDV's one-document photos an extra one on 29 of 40 against 22 by INTER_AREA (SmartDoc 40 and 40, your documents 5 and 6).

### The passport zone reader (H8b — made-up lines only)

The passport's machine-readable zone (two lines of 44, ICAO 9303 — the same in every country's passport) is read by the firm's own small model, `mrz.onnx` (docs/hf-plan.md → H8b), learned **only from made-up lines** — no real passport is needed to train it; the real ones the site collected (H8a) are its exam. Run when the owner asks for it (no bell: nothing has to be collected first):
1. **`synth_lines.py mrz`** — draws ~100 000 made-up zone lines with TRDG (TextRecognitionDataGenerator, MIT) in the OCR-B font (`scripts/scan-train/fonts/OCRB.otf`, public domain) into `~/.scan-train/synth/mrz/` (`labels.tsv` beside them), on every core but the first; the lines come from `synth.py`: every check digit right, mostly the passports the firm's workers hold (owner, 2026-10-21: Thai, Indian, Ukrainian, Russian, Belarusian, Moldovan, Sri Lankan — each country's number and personal number as printed), names put together at random. Its own packages: `pip install --no-deps trdg==1.8.0` and `requirements-synth.txt` (TRDG's pinned old ones do not install on a new Python; `synth_lines.py` mends its one call that new Pillow dropped).
2. **`train_mrz.py`** — a CRNN of 0.6 M weights (convolutions, a two-way LSTM, CTC; `mrzmodel.py` holds its contract) learns to read one line; each line is first made like a phone's crop of a passport — blurred, small, noisy, squeezed into JPEG, tilted, unevenly lit, with a guilloche-like pattern or a strip of the other line. Exported to ONNX (input `img` [1,1,32,512], output `logits` [1,128,38]) and checked to answer like the trained model. ~10–20 min on the 4070. **The weights are kept between trainings** (owner, 2026-10-21) in `~/.scan-train/mrz-ckpt/` — made-up and public lines only, no worker's data, so `clean.py` and `publish.py` leave it: `best.pt`, the best weights so far, which the next training starts from (learning rate 5e-4 instead of 2e-3; `--lr` sets it) and replaces only when it beats them on that day's check lines; `last.pt`, the running training saved after every epoch, which `--resume` continues (same settings) after a stop, and which is deleted when the training ends. `--fresh` starts from random weights (`best.pt` still replaced only when beaten). The check lines are one line in 50 picked by its text, so a check line is never trained on in any training, whatever `--count` drew.
3. **`exam_mrz.py`** — the made-up check lines' figures, and on the real passports collected (the primary page of each `documents/…` record): the two lowest lines found the way the phone will (`mrzmodel.find_lines`), read, line 2's values kept where their check digit is right, compared with what the user saved — and with what the AI had filled in. "Publish" when ≥ 93 % of the made-up lines are read right, ≥ 95 % of MIDV's exam passports (below) have every check-digit field right, and, on the real passports, it is right at least as often as the AI (with none collected yet: the shadow on the site examines it). The real photos weigh more than the made-up lines (owner, 2026-10-22): many made-up check lines are made so small and blurred that a person cannot read them either. `find_lines` leaves out a last band less than half as tall as the one above it — the page's dark edge under a zone printed low (MIDV's Serbian and Latvian passports), which it took for line 2 before.
4. **The owner decides** — `publish.py --mrz` puts `mrz.onnx` (and `report_mrz.json`, bound to it by `model_sha256`) into the next version (`--force-mrz` for a model the exam rejected), or `clean.py`. The lab runs it from its version (each shot shows the zone's line 2 and its check digits); the site, once its version holds it, reads every passport in shadow beside the AI — Admin → Scanner → Passport zone reader shows how often each got the fields the user kept (docs/scan.md → The scan window).

**Background photos** (owner, 2026-10-24): CC0 / public-domain photos of tables, cloths, carpets, floors and countertops from Openverse (their sources in `sources.json`; 74 in the bucket today) are kept in the private bucket's `datasets/backgrounds/` (`python -m gen bg pull`, or `datasets_hf.py push|pull backgrounds`), not on the PC between trainings; the scenes take them from the catalogued bank (→ The background bank), `synth_docs.py` lays its documents on them when the folder is there (`--backgrounds` names another).

**Real zones from MIDV-2020** (owner, 2026-10-21): MIDV's passports (Azerbaijan, Greece, Latvia, Serbia, Russia's internal passport) are real photos and scans of printed mock passports, and each one's zone text is in its template's annotation (`templates.tar`, fetched by `midv.py --download midv2020`). **`midv_mrz.py`** cuts each picture flat by its corners the way the scanner cuts a page (the document's own top-left first, at the template's size, 1000 px wide), skips one whose zone is out of the picture, and splits by the document's number: documents 00–79 give **training lines** — the two zone lines cut where the template has them (a field whose value is a 44-character zone line, or one field holding both), with a margin, in grey (`~/.scan-train/midv-mrz/train/`, `labels.tsv`); documents 80–99 give **exam pages** — the flat page as it is with its two true lines (`exam/`, `exam.json`); video frames only with `--clip-step N`. **`train_mrz.py --midv`** adds the training lines to the made-up ones, each shown `--midv-repeat` (8) times an epoch, made a little worse only half the time (they are a phone's already). **`exam_mrz.py`** reads the exam pages the phone's way (`find_lines`, then the model) and reports beside the rest: the zone found, line 2 read right, every check-digit field right (`midvPages`, `midvZoneFound`, `midvLine2Right`, `midvFieldsAllRight` in `report_mrz.json`) — every check-digit field right on ≥ 95 % of them is part of the decision. MIDV's terms: MIDV above.

The same made-up lines serve the field reader model later (H8c): `synth_lines.py he` draws Hebrew ID card fields (names, ID numbers with a right check digit, dates, streets, cities) in the PC's Hebrew fonts (Windows: Arial, David, Miriam, Narkisim), in logical order in `labels.tsv`.

### The Hebrew field reader (H8c — trained on the PC, read on the phone in shadow)

The fields of an Israeli ID card, its back and a ספח (names, ID numbers, dates, the Hebrew-calendar dates, sex, address, city, a spouse's and children's) are read by the AI today; the firm's own reader starts on made-up fields (docs/hf-plan.md → H8c):
1. **`synth_fields.py --count 3000`** — the owner's marked real pages made other people's (`template_vary.py`), made like a phone's cut page (smaller, blurred, noisy, unevenly lit, JPEG), and every field cut out a little off with its text, kind and page (a sha1 prefix) (`~/.scan-train/synth/he-fields/train/`, `labels.tsv`, `sources.json`) — from the marked pages **not** held out, with the training vocabulary; **`--count 300 --check`** draws only the held-out marked pages (`heldout.json`: today three ID cards and a ספח; the card's back and the licence have no check field) with the check vocabulary (another seed; `--out` another folder), so the check measures cards and names the reader never saw; with no held-out or no other marked page it stops. Optionally `synth_lines.py he` (more names, streets, cities and dates in the PC's fonts — the training vocabulary only).
2. **`train_he.py`** — the passport zone reader's small CRNN (`train_mrz.MrzNet`, CTC; `hemodel.py`: Hebrew letters, digits and the marks printed, `CHARS`) learns the fields in the visual order (`hemodel.visual`; `logical` turns an answer back), the cut fields made worse only half the time (they are a phone's already), the made-up lines like the zone's. Before training it refuses a training set whose `sources.json` is missing, names a held-out page or the check vocabulary (`gen.sources.assert_clean`). Exported to ONNX (`he.onnx`: input `img` [1,1,32,512], output `logits` [1,128,len(CHARS)+1]) and checked on the check fields: every field read right, by kind, the ID numbers whose check digit agrees (`report_he.json`; "YES" at ≥ 90 %).
   It also writes `he-layouts.json` — where the phone reads (`hemodel.layouts`: of the new and the old ID card's marked page in `template_fields.json`, the boxes of the surname, the given name, the ID number and the dates marked `same: dob` / `expiry`).
3. **The owner decides** — `publish.py --he` puts `he.onnx` and `he-layouts.json` together (and `report_he.json`, bound to both by `model_sha256`) into the next version (`--force-he` for a model the check rejected), or `clean.py`. The lab runs it from its version (each shot of an ID card shows the fields read); the site, once its version holds it, reads every ID card in shadow beside the AI — Admin → Scanner → Hebrew field reader shows how often each got the fields the user kept (docs/scan.md → The scan window).

## 5. Lab first, then the site

- **Lab:** `publish.py` (with the models named, after its `--dry-run`) points `scripts/scan-lab/models-version` at the new version; the change is deployed (PR, merge); `/scan-lab/` then runs `v<N>` and the owner tries it on the phone. A model not named is carried over unchanged, so a version holds exactly the models the owner said yes to, each with the report of its own file.
- **Site:** only when the owner says the lab is better, the same version is set in **both** `scripts/scan/models-version` (the phone's light model, `/scan/`) and `functions/scan_models_version.txt` (the server's accurate model; a test keeps the two equal), then deployed.
- **Rollback:** the previous version in the same files; every version stays on Hugging Face.

At deploy each copy's `fetch-models.sh` takes its version from Hugging Face (`resolve/<tag>/<file>`, no key — the repo is public), else from Storage while the version is not moved yet; only `base-v1` may fall back to the models' authors — a trained version is the firm's own. **The server runs no scanner model** (2026-10-19: `preprocess_scan` and its Storage mirror were removed — the site's scanner is the lab's page, which runs its models on the phone); `functions/scan_models_version.txt` only names the site's version in each training example.

## 6. The owner's side

1. The bell says **Time to retrain the document edges model** (or **Enough pages to train the document type model**).
2. On the PC: Claude Code in this project → `/scan-train` (the first time it sets up Python and asks the owner to sign in to Google in the browser once; Hugging Face: `hf auth login` once, the token kept on the PC).
3. About an hour later: the "before → after" report → **yes** or **no**.
4. Try the new version in the lab (Admin → Scanner lab); if it is better, say so — it is then given to the site.
