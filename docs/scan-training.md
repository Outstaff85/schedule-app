# Scanner training (how the scanner learns)

The whole training of the scanner in one place: where the examples come from, where they are kept, how a model is trained, checked and handed over, and what the owner does. Approved by the owner on 2026-10-18 (docs/scan-plan.md → S6). The scanner itself is docs/scan.md → The scan window.

## The idea in one line

**The site collects → the owner's PC trains → the lab tries → the site gets the new model.**

```
 site (src/scan/)            Storage / Firestore              owner's PC                 Hugging Face                 lab (/scan-lab/)   site
 users correct corners  ──►  training/scan/, scanTraining ──► /scan-train: pull, train,  ──► OutStaff/scanner-models ──► tried on the ──► set for the site
 and document types          (or the private HF bucket)       exam, publish (on "yes")       tag v<N>, set for the lab   phone           when better
```

- **The site's scanner** is the only source of examples: real scans by the firms' users. The lab collects nothing (no login, no data).
- **The models' home is Hugging Face** (docs/hf-plan.md): the public repo `OutStaff/scanner-models`, one tag per version (`base-v1`, `v2`…), every file of the version in its commit, named by what it does (`edges.onnx`, `edges-lite.onnx`, `face.onnx`, `doctype.onnx`, `doctype-lite.onnx`, the exam reports). The examples are in Firebase (Storage `training/scan/`, Firestore `scanTraining`). A version not moved yet (`move_to_hf.py`) is still read from Storage `models/scan/<version>/` under its old names (`sa24.onnx`, `lite.onnx`, `yunet640.onnx`).
- **The lab and the site never share code or a model file** (CLAUDE.md → Scanner: the lab and the site are apart); each names the model version it uses.

## 1. What is collected (on the site)

In the scan window (docs/scan.md → The scan window):

- **Corners** — a tap on a page opens its photo with the frame the model found; the user drags a corner and taps Apply. The model's corners and the user's are an example.
- **Page kind** — each page shows the kind Haiku gave it (ID card, its back, ספח, passport, contract, other); the user can pick another. Haiku's kind and the user's are an example.

On **Done**, every page the server found is sent in the background to the function `scan_feedback` (`src/scan/server.ts`, `sendFeedback`); with no network the examples wait in a queue on the phone (`localStorage` `scanFeedbackQueue`) and go the next time the scan window opens. A page:

| | sends | kept? |
|---|---|---|
| corners moved (≥ 0.5 % of the photo) | both corners + a 256×256 copy of the part of the photo the model looked at | yes |
| kind changed | both kinds + a 256×256 copy of the page | yes |
| neither — one page in five (`rightSeen`) | its corners and kinds + the same 256×256 copy, marked `keep`, and a 256×256 copy of the page | yes, as "the model was right" (`right: true`) — so the training also learns what the model already does well and does not forget it, and the document type model gets pages of every kind, not only Haiku's mistakes |
| neither — the other four | the corners and kinds only | no — only counted |

**What the document edges model learns from** is the photo as the model saw it — before it was cut, straightened or enhanced — scaled to 256×256, which is exactly the model's input: the copy, where the model put the corners on it, and where they really are. The cut page is not needed for the corners; it is used only for the page kind, which a future kind model reads on cut pages. Never the full photo; only small copies.

## 2. Where it is kept

`scan_feedback` (`functions/main.py`, checks in `functions/feedback.py`, the files through `functions/datastore.py`; a manager login's ID token; its actions: `add` — the examples above, `document` — a full document (below), `attempt` / `attemptOutcome` — every scan attempt (S8, below), `stats`, `mode`, `settings` / `setSettings`). **Where the files go** (docs/hf-plan.md → H7): the **private** Hugging Face bucket `OutStaff/scanner-data` (the secret `HF_DATA_TOKEN`, declared on `scan_feedback` — a token that may only write there; never public); a write the bucket refuses (out of reach, no token) goes to Firebase instead, as before H7, so nothing is lost:

| | the private bucket | Firebase (until the token is there, and what is not moved yet) |
|---|---|---|
| the edges copy | `edges/<YYYY-MM>/<id>.jpg` | Storage `training/scan/<YYYY-MM>/<id>.jpg` |
| the page copy | `doctype/<YYYY-MM>/<id>.jpg` | Storage `training/scan/<YYYY-MM>/<id>-page.jpg` |
| the record | `records/<YYYY-MM>/<id>.json` | Firestore `scanTraining/<id>` |
| a full document (H8a) | `documents/<tenant>/<YYYY-MM>/<id>/page-<n>.jpg`, `record.json` | Storage `training/documents/…` |
| every scan attempt (S8) | `attempts/new/<site\|lab>/<YYYY-MM-DD>/<id>/picture.jpg`, `answer.json`, `outcome-<time>.json`; after a training `attempts/used/v<N>/…` | Storage `training/attempts/…` |

What is in Firebase moves to the bucket with `scripts/scan-train/move_data_to_hf.py --apply` (it creates the bucket private and refuses a public one; run on 2026-10-19 — nothing was there yet); it is kept for an example that lands in Firebase when the bucket refuses, and the pulls read both.

- the copies → (above);
- the record → `edgesModel`, `edgesFixed`, `moved`, `doctypeModel`, `doctypeFixed`, `doctypeBy` (who gave `doctypeModel`: `haiku` or `model`), `right` (a page the model got right, kept as a sample), `source`, `model` (the model version that answered), `tenantId`, `image`, `pageImage`, `createdAt`, `deleteAt`;
- the counts → Firestore `scanTrainingStats/current`: `edgesSince` (corner corrections since the last training — the kept right pages and the scan window's `page` examples do not count), `kept`, `right`, `movedSum`, `doctypesSince` (the page copies of each kind, by the kind the user left — for the document type model), and after a training `lastTrainedAt`, `lastVersion`, `lastReport`.

**Names (docs/hf-plan.md → H0, 2026-10-19):** the fields say which model they teach — `edges*` the document edges model, `doctype*` the document type model. Before H0 they were `cornersModel` / `cornersFixed`, `kindModel` / `kindFixed` / `kindBy`, `newSince`, `kindsSince`, `lastKindsTrainedAt` / `lastKindsReport`. `scripts/scan-train/rename_fields.py --apply` has run (2026-10-19; nothing was stored under the old names); the old names are still read, for a phone with the old app: `scan_feedback` takes an example under either name (a phone with the old app, a queued example), the counters add the old one to the new (`feedback.edges_since`, `feedback.doctype_counts`), the pulls map an old record (`common.named`), and a publish clears the old counters.

**Full documents for the field reader model (H8a, owner 2026-10-19):** on the save of the worker window after a scan (a new worker, or a rescanned one — `saveWorker` → `ManagerBridge.sendScanDocument`, `scanDocument` in `src/scan-process/session.ts`, `sendScanDocument` in `src/scan/server.ts`), the scan goes to `scan_feedback` (`action: "document"`): the document's own pages as the AI read them (not a contract, not an "Other" page; the primary marked), each page's document type, the AI's read with its `fieldBoxes` (where each field is) and the other pages' reads, the fields the scan filled (`scanned`, `workerFields`) and the fields saved (`saved`) — `corrected` lists where they differ, the AI's mistakes. Never the worker's other fields (rates, phone). **On for every firm by default**; the super-admin turns it off for a firm (`tenants/<id>/settings/scan.collectDocuments: false`, `collects_documents`). The counts: `documentsSince`, `documents`, `fieldsCorrected`. Kept without a time limit; the legal check and the notice to the workers are the owner's.

**Every scan attempt (S8, owner 2026-10-20; docs/scan-plan.md → S8):** `scan_feedback` `{"action": "attempt", "attempts": [...]}` (any manager login, up to 10 per request) takes the scanner's attempts from the site and the lab — none from a firm whose full-document collection is off (`collects_documents`, `feedback.attempts_wanted`; the super-admin, with no firm, always): the picture (a JPEG up to 1.5 MB), the models' corners (none when the picture was taken whole), the corners the user moved (kept only when moved ≥ 0.5 %), the outcome (`kept`, `retaken`, `deleted`), the retake group, the source (`site` / `lab`), how it came in (`camera`, `photo`, `pdf`), the model version, the way it ran and how many pages it was cut into (checks: `feedback.check_attempt`). Each goes to its own folder with `answer.json` (`attempt_record`), and the answer names the folders; a later outcome — a kept page deleted from its batch — is `{"action": "attemptOutcome", "dir", "outcome", "page"}`, written beside it as `outcome-<time>.json` (`page`: which of its pages); pages deleted before the attempt was sent come in it as `deletedPages`; the corners the user moved in the corner editor come as `edgesFixed` (the first document) and `edgesMoreFixed` (the others, `null` where not moved). The phone's side (what is an attempt, when it is decided, the queue): docs/scan.md → The scan window. The count: `attemptsSince` and `attempts`.

**Privacy:** no client can read or write any of it (no Firestore or Storage rule opens them, the bucket is private); only `scan_feedback` writes, only `/scan-train` on the owner's PC (the owner's own Google account and HF token) reads. Every firm's corrections are used, with no switch (owner, 2026-10-18). **Deleting on request:** `scripts/scan-train/delete_data.py --firm <tenantId>` or `--worker <workerId>` (`--apply`) deletes every example of a firm or a worker's full documents, from the bucket (for real: no history) and from Firebase.

**Time limit:** none in the bucket (owner, 2026-10-19 — the delete-on-request script instead). In Firebase, until moved: each record has `deleteAt` = +365 days and Firestore deletes it (the TTL policy in `firestore.indexes.json`); the copies under `training/` are deleted after 365 days by a Storage lifecycle rule (`scripts/scan/storage_lifecycle.py`, set by the rules deploy; it needs Storage Admin on the deploy's service account — the deploy warns if it could not set it).

## 3. When to train

When **20** new corrections are kept (owner, 2026-10-20: 20 for every model), the super-admin's bell shows **Time to retrain the scanner** (the server counts; the app asks `scan_feedback` `{"action":"stats"}` at most every 6 hours). When every page kind but "Other" has **20** page copies (`doctypesSince`, `feedback.DOCTYPE_AT`), it shows **Enough pages for the document type model** (`doctypesDue`). When **15** new scan attempts are in (`attemptsSince`, `feedback.ATTEMPTS_AT`; S8), it shows **New scan attempts — time to train** (`attemptsDue`). Nothing trains by itself.

## 4. How a model is trained (`/scan-train` on the owner's PC)

The skill `.claude/skills/scan-train/SKILL.md`, run in Claude Code on the owner's PC (RTX 4070), runs `scripts/scan-train/` step by step:

1. **`pull.py`** — downloads every kept corner example to `~/.scan-train/`, and every new scan attempt (S8, `attempts/new/` — in the bucket, or in Firebase where the bucket refused it): its examples by `attempts.py` (a kept page — its moved corners, else the model's — on the photo with the documents found before it painted over in the border's colour (not the one it lies on: an ID card found on its ספח's cut); a deleted page — "nothing here", empty maps; a retaken page with no corners moved — the exam only, as a hard page), and the folders pulled (`attempts.json`); about one in seven (chosen by its id, always the same ones) is kept apart as the **exam** and never trained on.
2. **`train.py`** — fine-tunes both corner models — `lite.onnx` (the phone's live frame) and `sa24.onnx` (the server's accurate one) — starting from the **lab's** current version (`scripts/scan-lab/models-version`), or from another one with `--base <version>`:
   - the ONNX file is turned into PyTorch (`onnx2torch`) and checked to answer like the original; its batch is set free first (`onnxbatch.free_batch`: the input's first dimension named, a Reshape's constant leading 1 made 0 — the input's own batch), since a version exported with its batch baked in as 1 (v3's `edges.onnx`, 2026-10-22) cannot be trained in batches of 16;
   - each corner becomes a target spot (a Gaussian of the models' own spread, σ ≈ 2.4 heatmap pixels) where the user put it; a page the user deleted (S8) has no spots — "nothing here"; the error is taken against the corners started from whichever corner fits the model best (`corner_loss`): a document turned near 45° has two "top-left" corners of the photo, and a fixed order taught the model to put its first corner between them — on MIDV's turned scans it then found no document (owner, 2026-10-22); the cut page is turned upright afterwards anyway;
   - the loss weighs the spots over the empty background (a plain one makes every peak fade), batch norms keep their statistics, mirrored pages and light changes are added;
   - the trained model is exported back to ONNX with a free batch (`dynamic_axes`, then `free_batch` once more) and checked again, on one picture and on a batch of two, so the next version can be trained further. ~15–30 min on the 4070.
3. **`exam.py`** — the exam pages are read by the old models and the new ones, set by set: the users' pages kept apart, **the owner's own documents** — made-up photos of the real pages kept apart from training (owner, 2026-10-22: `synth.held_out`, about one page in six by its kind folder and file name — of the 22 uploaded six: ID cards new and old, a passport, two ספחים; `synth_docs.py --templates` never lays them, `synth_docs.py --templates --exam` lays only them, 300 photos into `~/.scan-train/synth/docs-exam/`), and — when MIDV and SmartDoc are made on the PC — up to 300 photos of each one's **exam documents** (owner, 2026-10-21: real photos never trained on, so the exam means something before the site has collected pages): MIDV-2020's documents 80–99 of each kind (as `midv_mrz.py` splits them) and SmartDoc's fifth page of each kind (`datasheet005`, `letter005`…) on every background — whole documents, so no photo, scan or frame of one is learned (`midv.open_exam`; `train.py --midv / --smartdoc` never takes them); for each model and set: mean corner error (the farthest corner, whichever corner a model starts from — `docfind.quad_error`), the share within 2 %, the share not found, and from the attempts the extra pages found where the user deleted one and how often a retaken page is answered other than the rejected frame → a "before → after" report (`~/.scan-train/report.json`), and **the picture report** `~/.scan-train/report.html`, opened in the browser: the 10 exam pages where the models differ most, the old corners red, the new blue, the right ones green (it shows workers' documents: it stays on the PC and goes with the copies). If any model is worse on any set it says **do not publish** (`"publish": false` in the report); with no exam page in any set there is nothing to measure, and it says so — it never examines a model on the pages it trained on.
4. **The owner decides.** **Yes** → **`publish.py`**: the new models go to Hugging Face as the next version — one commit with every file of the version, tagged `v<N>` (the models not retrained and the face finder carried over, the reports beside them; the owner's HF token on the PC), the bell's counter is reset, the lab is pointed at `v<N>` (`scripts/scan-lab/models-version`), the attempts move to `attempts/used/v<N>/` (`attemptsSince` lowered by them) — only with the edges models in the version, since they are the edges' examples —, and the copies on the PC are deleted (but the MIDV and SmartDoc downloads; `--keep-copies` keeps them all, when another training still needs the examples, templates and made-up photos). **No** → **`clean.py`** deletes the copies (but the MIDV and SmartDoc downloads); nothing changes.

### Stopped and picked up again (checkpoint.py)

The document edges, document type and Hebrew field trainings (`train.py`, `train_doctypes.py`, `train_he.py` through `train_mrz.fit`) save each model's progress after every epoch — the weights, the optimizer's and the schedule's state, the epoch, the best weights so far — to `~/.scan-train/checkpoints/<model>.pt` (written aside, then put in place, so a crash or a power cut while writing leaves the last one whole; owner, 2026-10-21). A run that stopped (Ctrl+C, a crash, the PC turned off) goes on where it stopped with the same command and **`--resume`** (the same data and epochs; at most the epoch it was in is lost; a run that had finished is only exported again). **`--more`** starts a new run (a fresh schedule, the epochs given) from the last run's weights — its best ones where it keeps them — to train a model further on more or new examples. The folder is kept by `clean.py` and `publish.py` (`common.KEPT`). The passport zone reader keeps its own (`~/.scan-train/mrz-ckpt/`: `best.pt` between trainings, `last.pt` for `--resume`, `--fresh` from random weights — The passport zone reader below).

### Made-up document photos (synth_docs.py)

**The PC stays usable** (owner, 2026-10-22: with every core drawing it slowed down and could hang): every drawing script (`synth_docs.py`, `synth_lines.py`, `synth_pages.py`, `synth_fields.py`) runs at below-normal priority, off the first physical core (logical cores 0 and 1) and with two processes fewer than the logical cores (`gentle()` in `home.py`; the processes it starts inherit both; `--jobs` still sets the number). The training scripts (`train.py`, `train_mrz.py`, `train_doctypes.py`, `train_he.py`) only lower their priority; the GPU is used as before.

The site's examples are few at first; the document edges models can also learn from **made-up photos** whose corners are known exactly (owner, 2026-10-21). `synth_docs.py --count 20000` draws them into `~/.scan-train/synth/docs/` (`img/<n>.jpg`, the long side 640, and `examples.json` in `pull.py`'s form), on every core but the first (see below); the same seed draws the same photos, so nothing of it is kept or uploaded:
- **the documents**, drawn flat with made-up data (`synth.py`: names, ID numbers, the passport's zone with right check digits; each marked SPECIMEN, a shape for the holder's photo, no state's emblem): an ID card's front and back (ID-1, rounded corners), a passport's data page (ID-3; mostly with the booklet's other page above it, a fold between — the corners are the data page's), a ספח (a printed form on a folded sheet, of varying shape, its folds and a gentle bow) and a loose sheet put into a passport;
- **the photo**: a table, a cloth, a check, a dark or white ground with things lying about — or the owner's own background photos (`--backgrounds <folder>`, photos with no document in them); the document laid on it by a perspective of its own (`synth.scene_quad`: mostly a quarter turn and a little, one in seven (`TURNED_ANY`) by any angle as on a scanner's glass, seen at a slant, 18–80 % of the photo, every corner inside), a shadow under it, uneven light, a glare on a card, sometimes a finger on one side; then Albumentations (2.0.8, MIT) for colours and quality only — brightness, gamma, a shadow, blur, noise, a smaller copy, JPEG — never the geometry, so the corners stay true;
- **the corners** in the model's order (`synth.order_corners`: the photo's top-left first, clockwise — the page is turned upright later, by its face); 5 % "nothing here" (no document: empty maps), 10 % with another document painted over in the border's colour (as the next document search sees it, `pull.painted`).

**Real pages as templates** (`--templates`, owner 2026-10-21): the firm's own documents laid the same way, so a few real pages teach the models how an Israeli ID card, its back, a passport or a ספח looks at its edges (the card's colour, the laminate, the paper) on every made-up ground and slant. They are cut pages in `~/.scan-train/templates/<kind>/` (`id_front`, `id_back`, `passport`, `sefach`, `insert`): **`pull_templates.py --per 100`** copies them from the full documents the site collected (H8a, `documents/…/record.json`: each page with the kind the user left; the newest months first), and every page the owner uploaded to the same private bucket under `templates/<kind>/` (photos of Israeli documents cut straight: `hf buckets sync <folder> hf://buckets/OutStaff/scanner-data/templates`; copied as `own-<name>`) — or the owner puts them into the folder by hand (or into a folder of their own outside `~/.scan-train`, given as `--templates <folder>`: `clean.py` does not touch it). The pages under `templates/` carry no worker's id: `delete_data.py` does not find them — one is deleted by hand (`hf buckets remove`). A real page is a worker's document: its face and text are **washed out** (blurred past reading, the layout's colours kept, made-up text laid on it — `--sharp` keeps them), it stays on the PC, and `clean.py` / `publish.py` delete the folder with the other copies. `--template-share` (0.4) is the share of photos with a real page; a card's is set to an ID card's size with its corners rounded, a passport page to ID-3, a sheet keeps its shape and gets folds.

`--show` also writes `show/<n>.jpg` with the corners drawn, to look at first. **Two documents in sight** (owner, 2026-10-22: an ID card below or on its ספח got one corner on one and three on the other): `PAIR_SHARE` of the photos lay a sheet (ספח, insert) with a card on it (`synth.card_on_sheet`, `PAIR_ON` of them) or beside it, and the answer is the larger document, whole — the scanner finds the other next (`findNext` / `findInside`); the exam photos (`--exam`) have such pairs too, from the pages kept apart. `train.py --synth N` adds N of them, at random, to the users' examples (never to the exam: the exam stays the users' real pages, so a model that learned only made-up habits shows up there). Its packages: `requirements-synth.txt` (Albumentations among them).

### MIDV — real photos of mock documents (midv.py)

Beside the made-up photos, the edges models learn from **MIDV** (owner, 2026-10-21: the made-up photos and MIDV together): real phone photos, scans and video frames of mock identity documents printed and laminated by the datasets' authors (Smart Engines, L3i), each with the document's corners —
- **MIDV-2020**: 1000 mock documents of 10 kinds (ID cards of Albania, Spain, Estonia, Finland, Slovakia; passports of Azerbaijan, Greece, Latvia, Serbia; Russia's internal passport), each with its own made-up data and a generated face; per document one photo (on a table, a keyboard, a cloth, a text page, outdoors, in low light, at a strong slant, with glare), two scans (upright, turned) and a video clip (frames every 1/10 s; `--clips`, a very large download). Its annotations are VGG Image Annotator projects: the region `doc_quad`, the document's own top-left first;
- **MIDV-500 / MIDV-2019**: 50 documents, 15 000 video frames (table, keyboard, in hand, partly out of the picture, clutter; 2019: low light, strong slants); `{"quad": …}` per frame.

`midv.py --download midv2020` (or `midv500`, `midv2019`) fetches them from the authors' FTP (`ftp://smartengines.com`, anonymous) into `~/.scan-train/midv/raw/`; `midv.py` (or `--src <folder>` for a copy already downloaded) turns every picture into an example in `pull.py`'s form in `~/.scan-train/midv/` (`img/`, the long side 640; `examples.json`): the corners 0..1 in the model's order (`synth.order_corners` — MIDV gives the document's own top-left first), a picture where the document goes out of it left out (the model's corners are inside), every third annotated frame of a clip (`--clip-step`). The download stays on the PC between trainings (`common.clear_work` keeps `midv/`: no worker's data in it); nothing is uploaded.

**Space on the PC:** `midv.py --drop-raw` (and `smartdoc.py --drop-raw`) deletes the download once the sets are made — `midv.py` makes MIDV-2020's zone lines too (`midv_mrz.py`) while the templates are there — so only `midv/` (the pictures at 640 px, `examples.json`), `midv-mrz/` and `smartdoc/` stay, hundreds of MB instead of GB. **In the private bucket:** `datasets_hf.py push` uploads those sets to `OutStaff/scanner-data` under `datasets/<set>/` (never a `raw/` folder; MIDV's terms allow no public copy — the private bucket only), `datasets_hf.py pull` brings them back on any PC before a training (the owner's HF token); `train.py` finds each picture by its name in its set's `img/`, wherever the set was made. **Another disk:** every script keeps its copies in `~/.scan-train`, or in the folder the `SCAN_TRAIN_HOME` environment variable names (`scripts/scan-train/home.py`).

**The terms:** MIDV is published for research; the papers name no licence. Its document images are Wikimedia Commons samples (each one's licence in `ftp://smartengines.com/midv-500/documents.pdf`), MIDV-2020's faces are Generated Photos'. The weights trained on it are the firm's model on the site — the owner reads the terms before a version trained with `--midv` goes to the site.

**Training with them** (`train.py --synth N --midv M --smartdoc K`): the made-up photos, MIDV and SmartDoc are added to the users' examples, at random, never to the exam — the exam is the users' own pages, the made-up photos of the owner's real pages kept apart (`synth_docs.py --templates --exam`) and MIDV's and SmartDoc's exam documents (`midv.open_exam`: 585 MIDV-2020 pictures and 1 694 SmartDoc frames kept out of training, 2 367 and 6 652 left to train on), so `exam.py` shows whether they helped. With thousands of added examples fewer epochs are needed (`--epochs 3`–`5`); the first such training is best checked on the exam against one with the users' examples only.

### SmartDoc — real phone frames of paper pages (smartdoc.py)

MIDV has cards and passports; paper — the ספח, a sheet put into a passport, a contract — comes from **SmartDoc 2015, Challenge 1** (ICDAR 2015, L3i; **CC BY 4.0**: fine for the firm's model, the attribution in `smartdoc.py`): 30 A4 pages (data sheets, letters, magazines, papers, patents, tax forms) printed and filmed by hand on 5 backgrounds (tables, a cluttered desk), ~25 000 frames with the page's corners. **`smartdoc.py --download`** fetches the authors' release (`jchazalon/smartdoc15-ch1-dataset` on GitHub, `frames.tar.gz`, ~1 GB) into `~/.scan-train/smartdoc/raw/` and writes the examples (`img/`, `examples.json`): every third frame (`--step`; ~8 300), the corners in the model's order (the file lists tl, bl, br, tr), half of the frames turned a quarter (they are all landscape, a phone's photos mostly portrait). Kept on the PC between trainings (`common.clear_work`). `train.py --smartdoc N` adds N of them.

### Variations of the real pages (template_vary.py)

A few real pages would only teach those pages; made into other people's, each one is thousands (owner, 2026-10-21 — the way MIDV-2020 was made). The owner's real pages marked in **`scripts/scan-train/template_fields.json`** — keyed by `<kind>/<file name>` as uploaded to the private bucket's `templates/`; each field's box (shares of the page), its kind (`synth.FIELD_KINDS`: surname, given, idNo, date, hedate, sex, marital, city, street, country, digits) and `same` for the fields printing one value (the holder's ID number on every part of a ספח), the photo's box, a printed code to scramble (`scramble`), a number printed sideways to rub out (`erase`), `"align": "left"` for a value printed from the left (a driving licence's); and, to fix the upload first, `crop` (the document's box on it — a photo with the table around), `turn` (clockwise quarter turns that set it upright) and `kind` (its type when uploaded into another kind's folder: a passport among the ID cards; `licence` — a driving licence, a card to the edges models, "other" to the page kinds); boxes only, no data — are varied by **`template_vary.vary`**: every field's printed marks inpainted (the card's ground kept), a made-up value of its kind (`synth.field_value`: an ID number with a right check digit, a date and a Hebrew-calendar date as printed…) printed in its place right-aligned in a Hebrew font of the PC, the colour of the text it replaced; the photo becomes a shape. No data of the real holder stays, and each call gives the page's every field with its text and box. Marked so far (2026-10-21; the owner's 22 uploads): ID cards new (5) and old (4, two layouts), a card's back, ספחים (a whole sheet, the holder's part and the first upload's), a driving licence; the five passports uploaded among the ID cards are marked `kind: passport` (two cut by `crop`) and laid washed out, as are two whole ספחים of another layout and a turned part (`turn` only). The kinds now include a Latin name (`latin`) and a licence's one-line `address`. **A new page** is marked with **`mark_fields.py <page> --like <a marked entry of the same layout> --like-page <its page> --show marked.png [--write <kind>/<name>]`** — the two pages matched on what every card of the layout prints alike (SIFT features, a RANSAC homography) and every box carried over — and looked at: a page of another layout is marked by hand (its pixel boxes as shares). Every variation is looked at once for a value left over: a field rubbed out takes a little more than its box (`_grown`), and a page whose boxes did not carry well is left with none (washed out). A page with no entry is laid washed out, as before. The variations serve the edges models (`synth_docs.py --templates`), the page kinds (`synth_pages.py`) and the Hebrew field reader (`synth_fields.py`).

### The page kinds (S7)

When the bell says **Enough pages for the document type model** (every kind but "Other" has 20 page copies), `/scan-train` runs its page-kind steps:
1. **`pull_doctypes.py`** — every kept page copy with the kind the user left (and the one Haiku or the model gave); the same one in seven is the exam.
2. **`train_doctypes.py`** — two models from ImageNet weights (timm): the phone's (EfficientNet-Lite0, `doctype-lite.onnx`) and the server's (Lite2, `doctype.onnx` — no server code runs it since 2026-10-19; the phone's is the one at work), each with two answers: the kind (6) and the turn the page needs (4) — the turn learned by showing every upright copy at a random quarter turn. Exported to ONNX and checked.
3. **`exam_doctypes.py`** — on the exam pages: kind right, how many it is sure of (≥ 90 %) and how right those are, the turn right, and the site's way (the model where sure, Haiku elsewhere) against Haiku alone. A worse model → the next size up (Lite1, Lite2… — owner, 2026-10-19), trained and examined again.
4. **The owner decides** — `publish.py` puts the models into the next version beside the document edges models (the counter `doctypesSince` reset), or `clean.py`.

The models switch on by themselves once their version is set (the lab first, then the site): a page the model is sure of needs no Haiku.

**Made-up pages for the page kinds** (owner, 2026-10-21 — before the site has collected 20 of each): **`synth_pages.py --count 6000`** writes upright cut pages of every kind to `~/.scan-train/synth/pages/` (`img/`, `pages.json` in `pull_doctypes.py`'s form): ID cards, their backs, passports (the data page) and ספחים drawn or made from the owner's real pages (`template_vary.py`), contracts drawn (Hebrew or English: clauses, a table, the lines to sign), "other" from a sheet put into a passport and SmartDoc's printed pages, and MIDV's cards and passports — the last two cut by their own corners (`doc` in `midv.py` / `smartdoc.py`'s examples: the document's own top-left first); each a little changed (light, blur, noise, JPEG). **`train_doctypes.py --synth N`** adds N of them to the site's page copies, or trains on them alone while there are none; the exam stays the site's pages (with none, nothing can be measured: the lab shows it on the phone, the site's shadow against Haiku).

### The passport zone reader (H8b — made-up lines only)

The passport's machine-readable zone (two lines of 44, ICAO 9303 — the same in every country's passport) is read by the firm's own small model, `mrz.onnx` (docs/hf-plan.md → H8b), learned **only from made-up lines** — no real passport is needed to train it; the real ones the site collected (H8a) are its exam. Run when the owner asks for it (no bell: nothing has to be collected first):
1. **`synth_lines.py mrz`** — draws ~100 000 made-up zone lines with TRDG (TextRecognitionDataGenerator, MIT) in the OCR-B font (`scripts/scan-train/fonts/OCRB.otf`, public domain) into `~/.scan-train/synth/mrz/` (`labels.tsv` beside them), on every core but the first; the lines come from `synth.py`: every check digit right, mostly the passports the firm's workers hold (owner, 2026-10-21: Thai, Indian, Ukrainian, Russian, Belarusian, Moldovan, Sri Lankan — each country's number and personal number as printed), names put together at random. The same seed draws the same lines, so nothing of it is kept or uploaded. Its own packages: `pip install --no-deps trdg==1.8.0` and `requirements-synth.txt` (TRDG's pinned old ones do not install on a new Python; `synth_lines.py` mends its one call that new Pillow dropped).
2. **`train_mrz.py`** — a CRNN of 0.6 M weights (convolutions, a two-way LSTM, CTC; `mrzmodel.py` holds its contract) learns to read one line; each line is first made like a phone's crop of a passport — blurred, small, noisy, squeezed into JPEG, tilted, unevenly lit, with a guilloche-like pattern or a strip of the other line. Exported to ONNX (input `img` [1,1,32,512], output `logits` [1,128,38]) and checked to answer like the trained model. ~10–20 min on the 4070. **The weights are kept between trainings** (owner, 2026-10-21) in `~/.scan-train/mrz-ckpt/` — made-up and public lines only, no worker's data, so `clean.py` and `publish.py` leave it: `best.pt`, the best weights so far, which the next training starts from (learning rate 5e-4 instead of 2e-3; `--lr` sets it) and replaces only when it beats them on that day's check lines; `last.pt`, the running training saved after every epoch, which `--resume` continues (same settings) after a stop, and which is deleted when the training ends. `--fresh` starts from random weights (`best.pt` still replaced only when beaten). The check lines are one line in 50 picked by its text, so a check line is never trained on in any training, whatever `--count` drew.
3. **`exam_mrz.py`** — the made-up check lines' figures, and on the real passports collected (the primary page of each `documents/…` record): the two lowest lines found the way the phone will (`mrzmodel.find_lines`), read, line 2's values kept where their check digit is right, compared with what the user saved — and with what the AI had filled in. "Publish" when ≥ 93 % of the made-up lines are read right, ≥ 95 % of MIDV's exam passports (below) have every check-digit field right, and, on the real passports, it is right at least as often as the AI (with none collected yet: the shadow on the site examines it). The real photos weigh more than the made-up lines (owner, 2026-10-22): many made-up check lines are made so small and blurred that a person cannot read them either. `find_lines` leaves out a last band less than half as tall as the one above it — the page's dark edge under a zone printed low (MIDV's Serbian and Latvian passports), which it took for line 2 before.
4. **The owner decides** — `publish.py` puts `mrz.onnx` (and `report_mrz.json`) into the next version (`--force-mrz` for a model the exam rejected), or `clean.py`. The lab runs it from its version (each shot shows the zone's line 2 and its check digits); the site, once its version holds it, reads every passport in shadow beside the AI — Admin → Scanner → Passport zone reader shows how often each got the fields the user kept (docs/scan.md → The scan window).

**Background photos** (owner, 2026-10-24): 25 CC0 / public-domain photos of tables, cloths, carpets, floors and countertops from Openverse (no document, no rectangle that looks like one; their sources in `sources.json`) are kept in the private bucket's `datasets/backgrounds/` (`datasets_hf.py push|pull backgrounds`), not on the PC between trainings; `synth_docs.py` lays its documents on them when the folder is there (`--backgrounds` names another).

**Real zones from MIDV-2020** (owner, 2026-10-21): MIDV's passports (Azerbaijan, Greece, Latvia, Serbia, Russia's internal passport) are real photos and scans of printed mock passports, and each one's zone text is in its template's annotation (`templates.tar`, fetched by `midv.py --download midv2020`). **`midv_mrz.py`** cuts each picture flat by its corners the way the scanner cuts a page (the document's own top-left first, at the template's size, 1000 px wide), skips one whose zone is out of the picture, and splits by the document's number: documents 00–79 give **training lines** — the two zone lines cut where the template has them (a field whose value is a 44-character zone line, or one field holding both), with a margin, in grey (`~/.scan-train/midv-mrz/train/`, `labels.tsv`); documents 80–99 give **exam pages** — the flat page as it is with its two true lines (`exam/`, `exam.json`); video frames only with `--clip-step N`. **`train_mrz.py --midv`** adds the training lines to the made-up ones, each shown `--midv-repeat` (8) times an epoch, made a little worse only half the time (they are a phone's already). **`exam_mrz.py`** reads the exam pages the phone's way (`find_lines`, then the model) and reports beside the rest: the zone found, line 2 read right, every check-digit field right (`midvPages`, `midvZoneFound`, `midvLine2Right`, `midvFieldsAllRight` in `report_mrz.json`) — every check-digit field right on ≥ 95 % of them is part of the decision. MIDV's terms: MIDV above.

The same made-up lines serve the field reader model later (H8c): `synth_lines.py he` draws Hebrew ID card fields (names, ID numbers with a right check digit, dates, streets, cities) in the PC's Hebrew fonts (Windows: Arial, David, Miriam, Narkisim), in logical order in `labels.tsv`.

### The Hebrew field reader (H8c — trained on the PC, read on the phone in shadow)

The fields of an Israeli ID card, its back and a ספח (names, ID numbers, dates, the Hebrew-calendar dates, sex, address, city, a spouse's and children's) are read by the AI today; the firm's own reader starts on made-up fields (docs/hf-plan.md → H8c):
1. **`synth_fields.py --count 3000`** — the owner's marked real pages made other people's (`template_vary.py`), made like a phone's cut page (smaller, blurred, noisy, unevenly lit, JPEG), and every field cut out a little off with its text and kind (`~/.scan-train/synth/he-fields/train/`, `labels.tsv`); **`--count 300 --check`** draws other pages (another seed) to measure on. Optionally `synth_lines.py he` (more names, streets, cities and dates in the PC's fonts).
2. **`train_he.py`** — the passport zone reader's small CRNN (`train_mrz.MrzNet`, CTC; `hemodel.py`: Hebrew letters, digits and the marks printed, `CHARS`) learns the fields in the visual order (`hemodel.visual`; `logical` turns an answer back), the cut fields made worse only half the time (they are a phone's already), the made-up lines like the zone's. Exported to ONNX (`he.onnx`: input `img` [1,1,32,512], output `logits` [1,128,len(CHARS)+1]) and checked on the check fields: every field read right, by kind, the ID numbers whose check digit agrees (`report_he.json`; "YES" at ≥ 90 %).
   It also writes `he-layouts.json` — where the phone reads (`hemodel.layouts`: of the new and the old ID card's marked page in `template_fields.json`, the boxes of the surname, the given name, the ID number and the dates marked `same: dob` / `expiry`).
3. **The owner decides** — `publish.py` puts `he.onnx` and `he-layouts.json` together (and `report_he.json`) into the next version (`--force-he` for a model the check rejected), or `clean.py`. The lab runs it from its version (each shot of an ID card shows the fields read); the site, once its version holds it, reads every ID card in shadow beside the AI — Admin → Scanner → Hebrew field reader shows how often each got the fields the user kept (docs/scan.md → The scan window).

Not yet: its exam on the site's real ID cards (H8a keeps each read's `fieldBoxes` and the values the user kept — the exam once there are enough).

## 5. Lab first, then the site

- **Lab:** the changed `scripts/scan-lab/models-version` is deployed (PR, merge); `/scan-lab/` then runs `v<N>` and the owner tries it on the phone.
- **Site:** only when the owner says the lab is better, the same version is set in **both** `scripts/scan/models-version` (the phone's light model, `/scan/`) and `functions/scan_models_version.txt` (the server's accurate model; a test keeps the two equal), then deployed.
- **Rollback:** the previous version in the same files; every version stays on Hugging Face.

At deploy each copy's `fetch-models.sh` takes its version from Hugging Face (`resolve/<tag>/<file>`, no key — the repo is public), else from Storage while the version is not moved yet; only `base-v1` may fall back to the models' authors — a trained version is the firm's own. **The server runs no scanner model** (2026-10-19: `preprocess_scan` and its Storage mirror were removed — the site's scanner is the lab's page, which runs its models on the phone); `functions/scan_models_version.txt` only names the site's version in each training example.

## 6. The owner's side

1. The bell says **Time to retrain the document edges model** (or **Enough pages to train the document type model**).
2. On the PC: Claude Code in this project → `/scan-train` (the first time it sets up Python and asks the owner to sign in to Google in the browser once; Hugging Face: `hf auth login` once, the token kept on the PC).
3. About an hour later: the "before → after" report → **yes** or **no**.
4. Try the new version in the lab (Admin → Scanner lab); if it is better, say so — it is then given to the site.
