# Clients

Clients (sites/objects where workers work): the Clients tab, the client window, the map picker, billing rates and the manual punch. Since stage 6d the tab and its windows are React inside the manager page (`src/manager/Clients.tsx`, `ClientEditor.tsx`, `ManualPunch.tsx`, the rules in `clients.ts`; [build.md](build.md) → The manager's React pieces); the records, the map picker, the figures and the saves stay in `schedule-manager.html` and reach them through `ManagerBridge`.

## Data: the client record

Global `clients` array. It is saved with the schedule; each client is one document `tenants/{t}/clients/{id}`.

The client's documents are in Storage under `tenants/{t}/clients/{id}/documents/`: its signed months (`hours-<YYYY-MM>-signed.pdf`, signed in the client portal — [hours-review.md](hours-review.md) → Signing the month), opened from Accounting → Hours approvals, and its signed contracts (`<ms>-contract-<name>.pdf`, [contracts.md](contracts.md) → Client contracts), listed in the client window's Contract section. A send's frozen template and the firm's signature and stamp sit in `…/clients/{id}/sign/<request>/`, the client's signature in `…/clients/{id}/signature/`; only the `sign_documents` function writes any of them.

| Field | Meaning |
|---|---|
| `id`, `name`, `color` (from `CLIENT_COLORS`) | |
| `companyNumber` | ח.פ, plain text (leading zeros kept) |
| `object` | object / branch name, shown next to the name |
| `address` | |
| `lat`, `lng`, `radius` (m, default 100, never under 10 — `clientRadius`), `mapsUrl` | geofence for the worker punch page |
| `defaultHourlyRate`, `defaultOtRate`, `defaultShabbatRate` | **worker pay** default at this client, for workers without a rate of their own (tier 3 of `effectiveRates()`, see [accounting.md](accounting.md)); the client card sets only `defaultHourlyRate` and saves the other two empty (OT / Shabbat by the law) |
| `rateMode` | `tiered` (default), `fixed` or `daily` — how the **client is billed** |
| `billRate`, `billOtRate`, `billShabbatRate` | billing rates for `tiered` (empty OT/Shabbat = law tiers) |
| `fixedBillRate` | billing rate for `fixed` |
| `dailyBillRate` | ₪ per worked shift for `daily` |
| `contactPhone`, `email` | the client's contact phone (a client's contract goes to it on WhatsApp) and email — the marks `{{client_phone}}`, `{{client_email}}` |
| `signerName`, `signerRole` | who signs for the client and their role — `{{client_signer}}`, `{{client_signer_role}}`; a signing fills them (and the other contact fields) only while they are empty |
| `contractTemplateId` | the client's contract template; empty = the firm's default client template ([contracts.md](contracts.md) → Client contracts) |
| `notes` | old field, no longer shown or edited; kept on the record |

Worker pay and client billing are separate sets of fields. Billing never changes what a worker is paid.

## Clients tab (`#clientsRoot`, React)

`renderClientsPage()` asks `ManagerIsland.renderClients()` to draw `Clients` (`src/manager/Clients.tsx`) from `ManagerBridge.clients()`: each client's id, name, colour, address / site, its active workers, this month's hours at it (`salaryEntriesFor('month').byClient`), **No rate** (`hasBillRate` of `src/manager/accounting.ts` false: no billing rate for the client's billing mode — fixed ₪/h, ₪ per day, or the tiered `billRate` / older `defaultHourlyRate` — the same rule as Accounting's "No billing rate — billed 0") and **Hours waiting** (a pending hours batch has entries for it), and `canEdit` (the `clients` section). There is no page title, no breadcrumb and no side panel on this tab. A glass **New** (`openClient(null)` → `openAddClient`) and, for a login with `clients`, **Select** above the plates. A plate per client (`Plate`, `PagedList columns`, 10 at a time): the colour as the bar, the name with its notices, "N workers · address" (or the site), the month's hours at the right, a ⋮ (Edit, Manual punch, Delete) and a swipe left (Edit, Delete). A tap opens the client window (no card to read first; with a mouse a single click waits 250 ms for a double click, as the old `tapEdit` did), so does a double click or a long press. **Delete never asks**: the plate goes behind the Undo snack (`undoDelete`, left out meanwhile); when its 5 s are up `ManagerBridge.deleteClients(ids)` → `deleteClientsNow` removes the client, takes it off every worker (`clientIds`, `clientRates`) and off the site filter, and saves. A login that may not write those workers (`mayWriteWorkers` in `src/manager/logic/access.ts`: Workers or Schedule and Edit workers, and Edit pay when a worker has a rate at that client) is refused with a toast and the client stays — the refused worker writes would otherwise block every later save of that device; a supplier's delete (`deleteSuppliersNow`) is checked the same way. Select's bulk Delete does the same for the ticked ones. No clients yet → `Empty` with "Add the first client"; before the data is drawn once, Skeleton plates.

## Client window (`#clientModal`, React `ClientEditor`)

`openAddClient()` / `openEditClient(cid)` set `editingClientId` (a new client gets the next `CLIENT_COLORS` colour; an edited one keeps its colour — no colour picker) and `showClientModal(c)` draws `ClientEditor` into the page's `#clientModal` (`ManagerIsland.openClient(record, editId)`) with `ManagerBridge.clientInfo(editId)` (active workers, this month's hours and billed sum there, pending hours batches, the client logins, `canDelete`, `PAY_RULES.otMult` / `shabbatMult`), then opens `#clientOverlay`. Every label goes through `tr()` (the Hebrew in `i18n/he.json` is the window's former Hebrew wording); the layout stays left to right like every other window.

- **Head:** the client's colour as an initials disc, the name ("New client" / "Edit client" while empty), "N workers · Xh this month" (a new one: site · address) and, for a saved client, a ⋮ with **Manual punch** (`punchFromClient` → `punchFromClientModal`: the window is saved first, then the manual punch opens; closing it brings the window back, drawn again from the saved record — `#clientOverlay.__reopen`) and **Delete** (with `clients`; `deleteFromEditor` → `closeEditorUnsaved`: closed without saving and not coming back, then the plate goes behind the Undo snack, `deleteLater`).
- **Section plates** (Accordion, the owner's fixed order; a new client opens Client, an edit opens none; a closed section keeps its fields): **Client** (Client name — amber while empty — and Company no.; Contact phone and Email; Signer's name and Signer's role — each pair a `FieldRow`), **Place** (Address; Site / branch and Radius (m) in a pair; the small map — the radius as a dashed circle, "150 m", "Tap to pick the place on the map" until a point is set; the map itself is the button: a tap opens the map picker, `ManagerBridge.pickPlace` — then "Or paste a Google Maps link" (`parseMapsUrl` reads `@lat,lng`, `?q=`, `?ll=`, `/lat,lng` and a plain `lat, lng`; a link not recognised says so) and the status line "Location set: lat, lng"; there are no Latitude / Longitude fields), **Rates**, **Contract** (below). Its logins are made only in Admin → Users ([admin.md](admin.md) → Users pane; owner, 2026-10-19); the head shows an "N waiting" badge for the hours batches of this client waiting for review.
- **Rates block** (mockup 04; the section's summary "₪45 worker · ₪58 client · hourly"):
  - **Pay mode** By the hour / By the day (`#cPayUnit`, `setPayUnit`): by the day (`daily`) hides the hourly fields and shows "Client pays per day" (`#cBillDaily` → `dailyBillRate`): `clientBillPay` bills that sum once for each shift with hours, whatever their length; by the hour goes back to the hourly mode last picked (`hourMode`).
  - **Two rates side by side:** **Worker pay** (`#cDefRate` → `defaultHourlyRate`) — the regular ₪/h every worker at this client gets unless the worker has an own rate; OT and Shabbat always follow the law from it (saving clears an older client's `defaultOtRate` / `defaultShabbatRate`); read-only for a login without Edit pay (`ClientInfo.canPay`, `hasEditPay()` in `src/manager/logic/access.ts`), whose save keeps the three as they were — `saveSchedule` writes them as the server holds them (read just before), so a stale copy on the device never makes the save fail; the rules refuse any change to them without Edit pay ([backend.md](backend.md)) — and **Client pays** (`#cBillMain`): the main billing rate (`billMain`: `fixedBillRate` in fixed mode, else `billRate`); never changes a worker's pay.
  - **Billing mode** (by the hour; `#cRateMode`): **By law (overtime + Shabbat)** (`tiered`) — Overtime / Shabbat (`#cBillOt`, `#cBillShab` → `billOtRate`, `billShabbatRate`) in a pair under the buttons, empty = by law (the placeholder shows the law's figure from the regular rate); **Fixed** — one flat ₪/h, the OT / Shabbat pair hidden. The values live in the window's `Bill` state (`billOf`; `billRate` falls back to `defaultHourlyRate` for clients saved before `billRate` existed).
  - **Margin** (`#cBillMargin`, `margin`): what the client pays minus the worker pay per regular hour in ₪ ("Profit per hour", red "Loss per hour" when the client pays less), the same in % of the client's rate ("Margin") and, for a saved client, what it is billed this month ("This month"); hidden while either rate is empty.
- **Contract** (`src/manager/ClientContract.tsx`, `ClientContractSection`; [contracts.md](contracts.md) → Client contracts), read when the section is first opened: a new client says "Save the client first". The **Contract template** select — the default option "The default: <name>" (`defaultFor(list, '', 'client')`), then the client's own templates ("this client only"), then the firm's client templates — saved as `contractTemplateId`. The status of the latest send (`clientList`): **Sent to sign <date>**, **Signed <date>** or **Needs sending again** (withdrawn: its template was deleted). For a login that may send client contracts (`canFirmSign`): **Send to sign** (`clientSend`, way `remote`, the values from the window's live form — `clientContractValues`, what the client pays only with `canSeeBilling`; otherwise "Billing is not filled in: this login does not see client billing.") shows the link with **Send on WhatsApp** (`wa.me/<contact phone, a leading 0 → 972>` with `clientSignMessage`: the client's name, "You have a contract to sign. Open the link, check your details, read the contract and sign at the bottom.", the link — in the sender's language; no contact phone: a line says to add it) and **Copy**; **Sign here** (`clientSend` way `person`, then `ClientSignFlow` in a window: the client signs on this phone); **A contract for this client only** (the owner and the super-admin: the upload window with `clientId`, kind client; picked for the client); **Firm's signature and stamp** (`FirmSealWindow`). The **Signed contracts** are plates (`PagedList`): the name and the signing date; a tap opens the PDF (`storageUrl`). A signed request not taken on yet fills the client's **empty** contact fields from the details the client signed with (`takeOnPatch`, `src/manager/logic/client-contract.ts`: company no., address, contact phone, email, signer's name and role — never what the firm typed; saved with the window) and is marked taken on (`clientApplied`). A login without the right sees the status and the signed contracts only.
- **Saving:** a tap outside the window saves it (`clientOverlay.__onUserClose` → `saveClient({auto:true})` → the window's `save`); the Save button at the bottom too; a note under it says so. `clientRecordOf` builds the record from the fields and the billing state (a contact or contract field still empty on a client saved before them is left out, so opening and closing it changes nothing); `ManagerBridge.commitClient(editId, fields)` → `commitClient` stores it in place (an unchanged client closes without a save) or pushes a new one (`uid()`), toasts "{name} updated!" / "{name} added!", redraws the tab and saves. A new client without a name is not created; an existing one with its name emptied closes with "The client's name is empty — changes were not saved"; Save with an empty name opens Client and focuses the name.

## Map picker (`src/manager/MapPicker.tsx`, `#mapPickOverlay`)

React since stage 8e-3, drawn into the page's `#mapPickModal`; the page opens the overlay over the client window (`openMapPicker(start, onPick)` → `ManagerIsland.openMapPicker`), so it goes back to the window when it closes.
- **Loading:** `GOOGLE_MAPS_API_KEY` (`src/manager/maps.ts`) is a browser key restricted to the app's domains. The Maps script loads on first use (`loadGoogleMaps()`); `window.gm_authFailure` toasts when the key is rejected; a script that fails to load toasts "Google Maps failed to load" (through `tr()`) and closes the picker.
- **Map:**
  - it starts at the saved coordinates, or geocodes the address/name (`region:'il'`), or falls back to Tel Aviv (`MAP_DEFAULT_CENTER`);
  - the classic `Marker` is draggable and a tap on the map moves it;
  - a `Circle` shows the radius, redrawn as the Radius (m) field changes.
- **Search box:** `PlaceAutocompleteElement` limited to Israel. It handles both `gmp-select` and the older `gmp-placeselect` event; without Places, "Address search unavailable — tap the map instead".
- **Use my location:** the device GPS, then a toast with its accuracy.
- **Opening:** from the client window's small map (`ManagerBridge.pickPlace`): `start` is the window's point, its address (or name, for the geocoding) and radius.
- **Saving:** Use this location (enabled once a point is set) hands lat/lng (6 decimals), the radius and a `https://www.google.com/maps?q=lat,lng` link to `onPick`, which fills the client window. `ManagerIsland.mapPickAt(lat, lng)` sets the pin from outside (the browser checks — no Google Maps on the emulators).

## Manual punch (client window ⋮ / a client plate's ⋮ → Manual punch)

- `openManualPunch(cid)` draws `ManualPunch` (`src/manager/ManualPunch.tsx`) into `#manualPunchModal` (`ManagerIsland.openManualPunch`) and opens `#manualPunchOverlay`: the worker (`ManagerBridge.punchInfo`: the active workers assigned to this client, or every active one if none), Clock IN / Clock OUT, the date (Date Picker), the time and a note; "Manual entry — GPS not verified".
- Save Punch (a worker and a time are required) builds the punch `{id: Date.now(), workerId, workerName, type, time, date (DD/MM/YYYY from the date field's own parts, so the same day as `ts` in any time zone), ts, site, clientId, dist:null, gpsVerified:false, manual:true, notes, gpsWarnings:['Manual entry by manager']}` and hands it to `ManagerBridge.addPunch` → `addManualPunch`: added to the local punch log and sent to Firestore with `gsSavePunch()` (see [app-core.md](app-core.md)), the window closes with a toast, Today / Admin redraw.
## Where clients are used elsewhere

- **Schedule site filter:** the Schedule tab's site select filters the roster by client (`selectedClientId`, `ManagerBridge.setClient` → `filterByClient`).
- **Workers:** assigned with the chip picker in the worker modal ([workers.md](workers.md)).
- **Pay and billing:** `effectiveRates()` and `clientBillPay()`, and the Accounting rate matrix and "Billable by client" table ([accounting.md](accounting.md)).
- **Punch page:** the geofence ([punch.md](punch.md)).
- **Supplier portal:** sees a client only as `{id, name, object}` ([portals.md](portals.md)).
- **Isolation:** no client-facing surface ever shows supplier data.
