# Hours review (`src/hours-review/`, the `hours` function)

The screen is drawn in the Odinson Glass look (redesign stage 10): glass tabs and month arrows, the status line as a plate with a coloured bar, each day a plate with its state as the bar (`--c`) and as a pill (`.hrv-pill`, `HRV_STATES[st].pill`: Waiting, Approved, Fixed, Changed, Disputed, Fix proposed, Rejected — stage 13) and the hours in the figure green. Its styles fall back to plain values where a page lacks the design tokens.

One screen, one Cloud Function and one store for every login that reviews its workers' hours: a **client** (in the client portal), a **supplier** (the supplier portal's Hours approval tab) and an **HR** (the manager app, Accounting). The same ticks, the same per-day actions, the same code (per user request 2026-10-11: "one template and one set of functions for hours").

## Ticks (`users.hourPerms` → claim `hp`)

`HOUR_PERMS` in `functions-auth/core.py` (and `HOUR_PERM_LABELS` in the manager app):

- **hours** — see the month's shifts (in / out / hours per day);
- **approve** — approve a day, several ticked days at once (Select for a login with this tick — owner 2026-10-13: a Select button above the days; after it "N selected · Select all · Done" and a tick box on every day still waiting / changed / whose fix was rejected; a tap on the day or its box ticks it, the day's own buttons stay; with a tick the glass bar shows — its Approve sends their lines in one `approve` (`approveSelected` in `HoursReview.tsx`), ✕ clears the ticks), or the whole month at once;
- **dispute** — dispute a day with a comment;
- **fix** — propose the right in / out of a day (with a comment); applied only when a manager accepts it;
- **schedule** — the workers' planned shifts;
- **export** — the month to Excel.

Set in the login's permission template (Admin → Users → Templates, a super-admin; [admin.md](admin.md) → Users pane) and shown read-only in the user window's **Hours** block (`src/manager/Users.tsx`), for HR, supplier and client (`HOUR_ROLES`). The default HR, Supplier and Client templates have `HOUR_DEFAULT` (hours, approve, dispute, fix); a login made without a template gets the same; a login with no ticks stored (made before `hourPerms`) gets the same (`claims_for`, `_stored_hour_perms` in `list_users`), except a client made before then, whose old `permissions` list are its ticks. Ticks set to none stay none. The login reply and the Users list carry `hourPerms`; a change ends the user's sessions like any rights change. The pages read the ticks from the ID token (`firestore-backend.js` `hourPerms()`).

Whose workers: a client — the workers at its site (`punches.clientId`); a supplier — its own (`workers.supplierId`); an HR — the workers assigned to it (`workers.hrId`), or every worker of the firm when its "Only own workers" is off (claim `own`). "Only own workers" closes the user form: an HR may untick it, a supplier and a client always have it on (locked).

## The `hours` function (`functions-auth/hours.py` → `hours_action(db, caller, body)`)

`caller` = the ID token's `uid, role, tenantId, clientId, supplierId, own, hp, perms` (`main.py`). A superadmin passes `tenantId` in the body. `scope_of(caller)` gives `(kind, ownerId)`: `client`/clientId, `supplier`/supplierId, `hr`/uid; any other role → "Not available for this login". A missing tick → "Not allowed for this login". Never returns a wage, a rate, a supplier, GPS, notes, documents or a token.

- `load {month}` → `{owner: {kind, id, name, object}, perms, month, workers, punches?, days?}` — `workers` `{id, name}` (+ `schedule` / `dates` with the schedule tick, `portal._week` / `_dates`; a worker who worked here this month and has since moved is listed too); with the hours tick, the scope's `punches` of the month with a day of margin (`{id, workerId, type, time, date, ts}`) and `days` (the stored day entries).
- `approve {month, lines}` → each line `"<worker>|<day>|<ins>|<outs>"` (a day's shifts comma-joined; ≤ 3000, the scope's workers only — for a client, the workers with punches at its site that month) stored as `approved`. Dispute and fix take only the same workers (else "Bad day").
- `dispute {month, workerId, day, line, comment}` → `disputed` with the comment; an empty comment takes a dispute back.
- `fix {month, workerId, day, line, shift?, inT, outT, comment}` → `fix` (HH:MM checked); `shift` picks one of the day's shifts (0 = the first; out of range → "Bad shift"), stored with its old times `oldIn` / `oldOut`, which the accept looks for; the day's line then gets that shift's new times.
- `sign {month, pages}` (a **client** login with the hours and approve ticks; any other scope → "Not available for this login") → the month signed: `pages` are 1–12 base64 JPEGs (≤ 2 MB each, checked by their header) drawn by the portal; at least one day of the month must be approved ("Approve the month first"); `jpeg_pdf` wraps them into one A4 PDF (no PDF library), stored through the Admin SDK at `tenants/{t}/clients/{clientId}/documents/hours-<month>-signed.pdf` (a new signature replaces it), and `signed {path, at, byName, pages}` is merged into the month's document. The reply, like `load` (a client's, with the hours tick), carries only `signed {at, byName}` — never the path. `main.py` passes `storage.bucket` as `hours_action(..., bucket)`.
- Managers only (`_is_manager`: owner, super-admin, staff with Accounting): `list {month}` → every login's document of the month (an HR's with `ownOnly`); `resolve {docId, key, accept}` → a proposed fix accepted (the shift's in / out punches matching the old line get the new times as Israel time — an out before the in moves to the next day, and the out's `day` / `date` follow it; `editedBy: 'approval'`; status `fixed`, the line updated) or rejected (`rejected`); `resolvedBy` / `resolvedAt` stored. A shift whose punches can't be matched (several shifts, edited since) → "edit them in the punch log".

Store: `tenants/{t}/hourApprovals/{kind}_{ownerId}_{YYYY-MM}` = `{kind, ownerId, ownerName, month, days: {"<workerId>|<YYYY-MM-DD>": {status, line, comment?, inT?, outT?, byName, at, resolvedBy?, resolvedAt?}}, signed?: {path, at, byName, pages}}` — written only by the function (a day write replaces `days` whole and keeps `signed`); managers read it (`firestore.rules`).

## The screen in the new stack (`src/hours-review/`)

The screen of the client portal (stage 3 of [react-migration-plan.md](react-migration-plan.md)), of the supplier portal's Approvals tab (stage 4) and of an HR in the manager app (Accounting, stage 6e). The old pages' copy, `hours-review.js`, was removed with stage 6e.

- `hours.ts` — the data: `HOURS_FN_URL`; the reply types (`HoursData`: `month, perms, owner, workers, punches, days`); `monthKey(offset)` / `monthStart(key)` (date-fns); `can(data, tick)`; `monthDays(data)` (the shift pairing of `src/lib/payroll.ts`, a row per worker and day with its `line` — the same lines as the owner's `hourDayLines`); `dayState(data, row)`; `PICKABLE`; `STATES` (colour, label, pill); `planned(worker, date)`.
- `HoursReview.tsx` — `HoursReview({call, hideOwner, sign?})`; `call(body)` posts to the `hours` function (the page's own, with its ID token). The state (month, tab, data) lives outside React (`useSyncExternalStore`), so a language change redraws without a new load; `hoursReviewReload()` reloads, `useHoursOwner()` gives the header its client. Tabs **Hours** / **Schedule** (ui Tabs) by their ticks; month arrows (no future months). **Hours**: the Figures (approved, waiting, disputed or changed, fixes proposed); the status plate ("N of M days approved" …, **Export**, **Approve the month** — asks first in an Alert Dialog); the total; **Select** (`useSelection` over the pickable days: a tap ticks a day, the bulk bar's **Approve** sends their lines in one `approve`); a Section per worker (name, days, hours), paged by 10 (`PagedList`), a Plate per day — the date, the state pill, the shifts, the hours, the bar in the state's colour, the state's note under it; its ⋮ holds Approve this day / Dispute this day / Propose a fix by the ticks, and a tap opens the fix (else the dispute). The dispute and fix windows (`Window`) have no buttons: closing one sends (dispute: empty = take it back; fix: only when a time differs from the punches; a day with several shifts first picks the shift). **Schedule**: a Section per worker with a Table of its planned days (today in accent). With `sign` (the client portal) see Signing the month below. Plates and controls carry `data-day-key` / `data-state` / `data-testid` for the browser tests.

### Signing the month (a client, stage 5c)

- With `sign={signer}` (the client portal passes its login's name) and the approve tick: once every day of the month is approved or its fix accepted, the status plate shows **Sign the month** (primary; **Sign again** once signed, and "Signed <date> — <name>" under it); "Approve the month" that leaves no day open opens the same window at once.
- The window (`SignWindow`, a `Window` with one primary): the days and hours of the month, a note that the signed PDF is kept with the client's documents at the firm, the shared `SignaturePad`; **Sign and save** (off until something is drawn) → `signedMonthPages(data, days, png, signer)` (`signed-pdf.ts`) draws A4 pages at 150 dpi on white — the title, the month, the client and object, a row per day (date, worker, shifts, hours, state pill), the total, "I approve the hours of this month.", the signature, the signer and the time — as JPEGs, sent as `sign`. Only what the screen shows a client goes in: no pay, rates, suppliers, GPS, files or tokens. Closing the window signs nothing.
- The owner: Accounting → Hours approvals shows a client's signed month on its plate ("Signed <date> — <name>", **Signed PDF** → `openSignedHours(path)`: `firestore-backend.js` `storageUrl(path)` in a new tab; the managers' Storage read in `storage.rules`).

Where it runs:

- **Client portal** — the whole page, the React screen ([client-portal.md](client-portal.md)).
- **Supplier portal** — the **Approvals** tab, the React screen (`HoursReview`, [supplier-portal.md](supplier-portal.md)), shown with an hours or schedule tick.
- **Manager app, an HR login** — Accounting → `#accSecReview` (the React `HoursReview` over the page's `hoursCall`, `ManagerBridge.hoursCall`), shown with an hours or schedule tick (`hrHourReview()`); such an HR gets the Accounting tab for it even without the Accounting section, and then sees only this part.

## Accounting → Hours approvals (the owner)

The Approvals tab's **Hours approvals** (`ApprovalsTab`, Accounting.tsx; a month period only, never for an HR): every login's document of the month (`ManagerBridge.hourApprovals(month)` → the page's `hourApprovalsOf(month)` → `list`; kept for a minute per month so a redraw on each new punch doesn't ask the server — opening the tab, an accept / reject and the accountant report read afresh); it first waits for the first load of the punches (`__punchSynced`, set by `syncPunchesFromGS`), so a day is never compared with a punch log still loading, and every redraw (each punch change while Accounting is open) compares again with the punches in memory. One plate per login (kind: Client / Supplier / HR, `approvalDocsShown`) with "N of M days approved", a client's signed month ("Signed <date> — <name>", **Signed PDF**) and each day that needs a look — disputed (comment), fix proposed (old → new times, comment, **Accept** (asks first) / **Reject** → `ManagerBridge.resolveFix`), fix rejected, changed after approval. "Changed" and the day count come from `hourApprovalSummary(d, doc, month)` over `hourDayLines(d, doc, month)` (`src/manager/accounting.ts`): the scope's punches in the owner's punch log paired into the same lines as the review (supplier: its workers; HR: its workers, or all when its own-only is off — `ownOnly`, which `list` adds to an HR's document; client: punches at the client). After an accept the punch listener brings the moved punches.

The accountant report (a month) has a sheet **Hours approvals**: login, role, worker, date, status, proposed fix, comment, by, when.
