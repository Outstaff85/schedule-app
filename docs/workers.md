# Workers

The Workers tab, the worker window (add / edit / review after a scan), the worker card, worker documents, and the hours import/export entry points. The tab and the windows are React (`src/manager/`, stage 6c); the data and the server calls are the manager page's modules (`src/manager/page/`, `src/manager/data/`).

## Data: the worker record

One object per worker in the global `workers` array. It is saved as part of the schedule (see [app-core.md](app-core.md) → saving); it is one document `tenants/{t}/workers/{id}`.

| Field | Meaning |
|---|---|
| `id` | `uid()` — `'id'` + 7 random chars |
| `name` | always `docGiven + ' ' + docSurname`, rebuilt on every save |
| `docGiven`, `docSurname` | given name, surname (Latin for a foreign passport) |
| `colorIdx` | index into `WORKER_COLORS` (8 colors) |
| `phone`, `notes` | |
| `status` | `active` / `vacation` / `fired` (shown as פעיל / בחופשה / לא פעיל, Active / On vacation / Inactive) |
| `hourlyRate` | the worker's own rate (₪/h, or ₪/day when `payMode` is `daily`); `otRate`, `shabbatRate`; the older `regRate`. All set in the pay window (Accounting → Salary row, or the worker card's Pay) ([accounting.md](accounting.md)) |
| `clientRates` | `{clientId: {rate, otRate, shabbatRate}}` — per-client override, see [accounting.md](accounting.md) |
| `travelAllowance`, `travelMonthly` | travel: ₪ per day worked and ₪ per month with work, added on top of pay (the pay window (Accounting → Salary row, or the worker card's Pay)) |
| `clientIds` | array — a worker can work at several clients |
| `supplierId`, `supplierRates` | one supplier (agency); `supplierRates[sid].rate` = commission override |
| `hrId` | uid of the HR login the worker belongs to, or absent; set only by the owner / super-admin (worker modal HR field, the HR card in Users) or automatically for a worker an HR adds ([hr.md](hr.md)) |
| `bank`, `bankBranch`, `bankAccountNumber` | the worker's own bank details (the pay window (Accounting → Salary row, or the worker card's Pay)) |
| `schedule` | 7 items, Sunday first: `{type:'work'|'off', start:'HH:MM'|null, end}` |
| `startDate` / `workStartDate` | same value, one input; `startDate` starts the contract term when the worker has no contract document, `workStartDate` goes to Form 101 |
| `expiryEnabled`, `expiryMonths`, `expiryWarnMonths` | opt-in contract term: its length in months and how many months before its end to warn, counted from the latest contract document's date, else from `startDate` (`workerExpiryStatus`) |
| `token` | punch-link token: `genToken()` (`src/manager/data/ids.ts`) — 16 random bytes from `crypto.getRandomValues` as base64url, 22 characters; a worker a supplier adds gets the same kind from the server (`supplierAddWorker`, `secrets.token_urlsafe(16)`); older 8-character tokens keep working |
| `createdAt` | ISO; Form 101 signature date |
| `docType` | `israeli_id` (default) / `passport` |
| `docId` | ID or passport number. Old records may hold it inside `address` as `ת.ז. 123…`/`Passport X` — always read it through `workerDocId(w)` / `workerAddress(w)` |
| `docSex` (`M`/`F`), `docDob`, `docExpiry`, `address`, `houseNumber`, `city` | Form 101 personal fields |
| `maritalStatus` | `marital_single` / `_married` / `_divorced` / `_widowed` |
| `healthFund` | `Clalit` / `Maccabi` / `Meuhedet` / `Leumit` |
| `incomeType`, `otherIncomeType` | Form 101 income section (`INCOME_LABELS`, `OTHER_INCOME_LABELS` in `src/manager/worker.ts`) |
| `docChildren` | `[{name, idNo, dob}]` |
| `spouseSurname`, `spouseGiven`, `spouseId`, `spouseDob`, `spouseIncome` (`''`/`none`/`work`/`other`) | Form 101 section ו |
| `avatarB64` | no longer kept (owner 2026-10-13): `saveWorker` drops it, and `dropWorkerPhotos()` removes an old one from every worker this login may write right after a server load (then `autoSave`) |
| `docUrl`, `docFileId`, `docSavedAt` | the Form 101 PDF (download URL, Storage path `tenants/…`) |
| `scanPages` | the scanned pages, each its own JPEG in Storage: `[{fileId, kind, primary?, savedAt}]` — `kind` one of `id_front`, `id_back`, `sefach`, `passport`, `other`; the ID card or passport first (`primary`) ([contracts.md](contracts.md) → Scanned pages) |
| `sigFileId`, `sigSavedAt` | the signature, a PNG in Storage, and when it was stored |
| `assetsFileId` | the old scan sidecar (scan + signature + extra pages in one JSON), read until it is split into `scanPages` (`scripts/migrate/scan_pages.py`); gone once the worker's pages are saved again |
| `contractCategory`, `contractTemplateId`, `contractTerms` | the contract's category, a template picked for this worker alone (empty: the category's default), the worker's own terms for `{{terms_1}}`…`{{terms_5}}` (empty ones at the end dropped) — [contracts.md](contracts.md) → The worker's contract |
| `movedToOtherFirm`, `movedAt` / `movedFromOtherFirm` | the worker moved to another firm (set Inactive here, the card's chip Moved to another firm) / the record was copied from another firm with the worker's signed consent ([contracts.md](contracts.md) → Moving to another firm) |
| `signedPrint`, `signedPrintPay`, `signedPrintMarks` | what the signed documents printed about the worker (a hash), for the notice Documents changed — needs a new signature ([contracts.md](contracts.md) → A new signature after a change) |
| `signedAt`, `signDate`, `signedRequestId` | the last signing of Form 101 and the contract: when (server time), the date printed, its request; the signed contract is a `docs` entry with `signed: true` ([contracts.md](contracts.md) → Signing) |
| `assetsMigratedFrom` | the sidecar a worker's pages were split from, until the migration's cleanup deletes it |
| `docHasSignature`, `docExtraPages` | written by `aiFillForm101()` on each successful save |
| `docUploadFailed` | last PDF upload failed |
| `docs` | other documents: `[{id, type, name, fileId, url, mediaType, uploadedAt, expiry}]` — `expiry` (`YYYY-MM-DD` or empty) for a visa, work permit or other; a contract has no expiry: `contractDate` (`YYYY-MM-DD`, the day its term counts from — Add document's Contract date), a signed contract also `signed: true` (its date: the worker's `signDate`); an `expiry` on a contract entry from before 2026-10-25 is ignored |

## Badges and status helpers

- **Inactive workers** (`isActiveWorker(w)`: status not `fired`) leave the everyday lists — the Workers tab by default, the Schedule (`getVisible`), Today (missing, expiries), the manual-punch picker and the contract warnings — and return when set Active on their card (user request 2026-10-11). Accounting still counts their hours; their data and documents stay.
- `workerExpiryStatus(w)` → `null` or `{level:'warning'|'overdue', deadline, from}` (an active worker with `expiryEnabled` and `expiryMonths`). **A contract has no end date** (owner, 2026-10-25): the term is the worker's own option — `expiryMonths` long, warning `expiryWarnMonths` before its end — and **a new contract restarts it**. It counts from `termStart(w)`: the latest contract document (`currentContractDoc(w)`: of the latest contract upload — `currentDocs`, uploaded in Add document, scanned or signed — its date, `contractDocDate`: the entry's `contractDate`, for a signed one the worker's `signDate`, else the day it was uploaded; `from` is that document), or `startDate` when the worker has no contract document (`from` null). The deadline is that day + `expiryMonths`; overdue from the deadline, warning from `expiryWarnMonths` before it. With the option off nothing warns, whatever the contract. A contract's date is never a document reminder (`workerDocExpiries` leaves contracts out; their files keep the green of a document with nothing due — `docExpiryMap` holds only the expiring documents). The worker window's contract-expiry section says where the term counts from: "Counted from the latest contract (dd/mm/yyyy)", else "Counted from the start date (dd/mm/yyyy)". Shown on the worker's plate and card, on Today, and in the bell ("Contract ending" / "Contract ended", `notifList`); there is no banner under the title bar (removed, owner 2026-10-26). The worker form says in red when the warning is on but there is neither a contract document nor a start date (`WorkerEditor.tsx`).
- `workerDocStatus(w)` → `{level:'ok'|'warn'|'error', missing, expiry, docExpiries, docExpired, failed, lines}`:
  - **missing:** no ID/passport number, no `docUrl` (Form 101), no stored scan (`workerHasScan`: `scanPages`, or the old `assetsFileId`), `docHasSignature === false`, or (Israeli ID) `docExtraPages === 0` (no ספח);
  - **expiry:** `docExpiry` already past is an error; within `DOC_EXPIRY_WARN_MONTHS` (3) is a warning;
  - **docExpiries:** `workerDocExpiries(w)` for `w.docs` — of a visa or work permit only the latest upload counts (`currentDocs`: the files uploaded together share their time; a new one replaces the old one, so the old one's date no longer warns), every "other" document counts; a contract has no expiry (its date starts the contract term, `workerExpiryStatus` above); one reminder per type + expiry date; warns `WORKER_DOC_WARN_DAYS` ahead (visa / work permit 60, other 30);
  - **failed:** `docUploadFailed`.
  
  Handed to the React Workers list through the bridge (`docLevel`, `docLines` and the list badge `docBadge`: DOCS / ID EXPIRED / `<TYPE> EXPIRED` / UPLOAD FAILED; nothing when complete).
- **NEW badge** — the React `NewBadge` (`src/components/shared/new-badge.tsx`): a green "NEW" next to the name for 3 days after `w.createdAt` (set when the worker is added in the app or by a supplier in its portal; the tooltip gives the date). On the Workers list and the worker card; the supplier portal's worker list has the same badge.
- `parseDocDate(s)` reads `DD/MM/YYYY` (or `.`, `-`) and ISO dates.

## Worker card (`openWorkerCard(wi)`, `#workerCardOverlay`)

A read-only sheet (`WorkerCard`), **one page** — no Info / Docs / Hours switch — laid out after the owner's mock (2026-10-26), with the app's tokens and shared pieces; 540 px wide on a computer, on a phone the bottom sheet every window is. Top to bottom:
- **the head** (`WorkerHeadLine`: avatar, name, site · today's punch) with the **status switch** at its top right in the place of the month's hours (the card shows no month's hours); under it every notice chip (a tap closes the card and opens the notices sheet; closing it comes back to the card), NEW, the sign chip (Sent to sign / Signed <date> / Needs sending again) and "Moved to another firm";
- **Rescan** / "Scan document" and **Documents to sign** ("To sign" on a phone, where the two share a line) — for a login that edits workers;
- **the facts in pairs** (`Kv`, a grid of two equal columns, every box its column's width — never one stretched): ID / Passport | Clients; HR | Supplier; Start date | Shift today; Address | Income; Documents | Hours sent. HR and Supplier are always shown, "—" when there is none (the HR's name comes from the HR logins, which only the owner / super-admin loads; an HR login sees its own name on its own workers; any other login whose worker has an HR reads "Assigned"). Address: the city (`city`) on the first line, the street and house number (`address`, `houseNumber` — the Form 101 fields) under it, Hebrew; without a city the street takes the first line. The card shows neither the month's hours nor the scheduled hours per week (the Workers list and the Schedule tab show them). Income: the income type in Hebrew, as on Form 101. Documents: "Complete" (green) or what is missing / expiring (`workerDocStatus` lines, amber or red). Hours sent: the latest hours batch's status (Sent for review / Approved / Rejected, coloured; `latestHoursBatch`, live — [accounting.md](accounting.md) → Pending hours), its date on the next line, "—" with none. Then, only when the worker has them and in the same pairs: Phone, Contract (Expired / Expiring soon — the deadline), Other income; the notes across both columns;
- the missing scan-field rows (with `hasPermission('workers')`; across both columns): one amber row per scan field still missing (`MissingScanRows`, `#cardMiss_<key>`; the first 3, the rest behind "Show N more missing fields"). When the worker has a saved scan (`workerHasScan`: `scanPages`, or the older `assetsFileId`), tapping a row searches it for that field (`ManagerBridge.findScanFields` → the page's `findScanFields`). A value found is saved on the worker (`setScanField`: `autoSave`, `name` rebuilt for a name field), and the Form 101 is rebuilt (`regenerateWorkerDoc`). Not found → the row says so, with a link to photograph the page again; a search that fails or does not answer in time ends too: the row can be tapped again, with a note;
- **the documents box** (`DocsBox`, `data-testid="card-docs"`, across both columns): "Uploaded documents", **+ Add** (`card-docs-add` → `openWorkerDocUpload`, for a login that edits workers), Select, and the documents as plates — or "No documents yet — contract, visa, work permit…" (Worker documents below);
- **the bottom bar** (`card-actions`), which stays at the bottom of the sheet while the middle (`card-body`) scrolls — `#workerCardModal` is a flex column and the card's middle the one part that scrolls: **"Saved: <date>"** at the bottom left, always (the date the Form 101 was last saved, `docSavedAt`; "—" before one), and at the right one primary **Edit** (`#workerCardEdit`) and a ⋮ (`data-testid="card-more"`, a Dropdown Menu) with the rest: Pay, Download document, Download data (below), Upload hours, Export hours, Punch link — by rights.

**Status** — one **Active ↔ Inactive** switch (`Switch`, `card-status-switch`) with its word (`card-status-word`): on = Active, off = Inactive (`status: 'fired'`). A flip calls `setWorkerStatus(wi, statusFromSwitch(on))` (`src/manager/logic/workers.ts`), which saves at once and draws the card again. ### Download data (`src/manager/DownloadData.tsx`, the `worker_docs` function)

**Download data** in the worker card's ⋮ (any login that sees the worker card; the server then asks for the Workers right) opens a window over the card (`Window`, `DownloadData`): the parts of the worker's data to put into **one PDF**, as tiles (`CheckGrid` / `CheckTile`) — **Form 101**, **Contract**, **ID and scans**, **Other documents**; the summary page is always first and has no tick. A tile with nothing behind it is greyed out (`downloadAvailable`: no contract in `docs`; no `scanPages` and no sidecar; no other document). Each tile's hint says what it brings: Form 101 is the signed copy as stored (a signed worker) or a preview marked as not signed; the scans are "already inside the signed Form 101" when that is picked too; a login that does not see pay (`canSeePay`) is told the contract is left out when it may hold pay. **The default ticks** (owner, 2026-10-25): Form 101 and the ID sheet ticked, the contract and the other documents not; the last choice is kept on the device (`localStorage` `downloadDataPicks`, `storedInclude` / `storeInclude` in `src/manager/logic/workerdocs.ts`, wrapped in try/catch — an empty or blocked storage gives the default). **Download** calls the bridge's `downloadData(workerId, include)`: when Form 101 is picked, the app sends its values (`form101Payload`, the firm's profile refreshed first — the server builds no Form 101 values of its own), `workerDocsCall` posts to `WORKER_DOCS_FN_URL` (`src/manager/logic/functions.ts`) with the login's ID token, the PDF comes back raw as a blob and is opened in a new tab (`openPdfBlob`, `src/manager/contracts.ts`); a toast says how many pages, and whether the contract was left out or files could not be added. The worker card warms the function with `{ping}` when it opens.

The PDF (`functions/workerdocs.py`, put together now and never stored):

1. **the summary page**, always first — the names, the ID or passport number and its expiry, the date of birth, the phone, the address, the start date, the clients, the supplier, the signing date, and the list of what follows; Hebrew labels, right to left; never pay or rates;
2. **Form 101** — a signed Form 101 when there is one: a signed worker's `docFileId` (`signedAt`), else the Form 101 part of the latest signed request not yet taken onto the worker, **whole** (a legal copy is never trimmed; a signed worker whose copy is not found gets none, never a preview); otherwise **a preview** built from the values sent, the stored pages and the firm's block in those values, with the visible mark **טיוטה — לא נחתם** on its pages and no signing date. A preview never carries a signing's signature: only a signature captured from a scan (`sigFileId`) of a worker with no signed set that no sign request kept. When the scans are picked too, the preview leaves its pages out, so the photos appear once;
3. **the contract** — the signed one first. A contract may hold pay unless shown otherwise: the sign request whose contract part is that file gives `printPay`; none found (an older entry, an uploaded or scanned contract) counts as holding pay. Either way a login that does not see pay (`may_see_pay`) gets it left out (`X-Withheld: contract`);
4. **ID and scans** — **one A4 sheet** with the worker's document and the ספח (`functions/idsheet.py`; owner, 2026-10-25): the ID card's front and its back (when scanned), or the passport, with the ספח on the same sheet. The placement follows the pictures' shapes — every way of cutting the sheet's pictures into rows or columns, in order, is tried, and the one whose smallest picture comes out largest is kept (two cards one above the other with a tall ספח beside them, three landscape pictures down the page…). An ID card worker without a ספח gets its box left empty with the Hebrew caption **ספח — חסר, לא נסרק**; a passport worker has no ספח box. Each other page then gets an A4 of its own. A stored JPEG goes in with its own bytes. When the stored signed Form 101 is in the PDF, the scans are left out (it holds them already);
5. **the other documents** (`docs[]`: visa, work permit, other, an older contract — with the same pay rule); a PDF goes in as it is, a picture gets a page of its own.

Only files under the worker's own folder (`tenants/<t>/workers/<w>/`) are read; a bundle over 25 MiB is refused with a clear error. The function's settings and answer: [backend.md](backend.md) → Cloud Functions → `worker_docs`. The old call, `sign_documents` `bundle`, stays for a device that has not reloaded and is put together by the same code (Form 101 the stored `docFileId`).

Tests: `tests/auth/test_worker_docs.py` (the rights matrix; every subset of the picker with its order and pages; one ID sheet and the photos once; the layout by shape; a missing ספח, a passport; a legacy signed Form 101 whole; no pay without the right; the preview's mark and never a signing's signature; a path outside the worker; the size cap; the headers; the old `bundle`; the function's settings) and the browser check "download data" (`tests/e2e/main.test.js`: the picker's default ticks over the card, Download → one raw PDF with its page count in `X-Pages`, Form 101's values sent, the choice kept).

## Worker window (`showWorkerModal(w)`, `#workerModal`)

One form for add, edit and post-scan review (`WorkerEditor`, React Hook Form; 680px wide on a computer, a sheet on a phone). Labels of every Form 101 field are Hebrew (a foreign passport's names stay Latin, as typed or scanned); the rest goes through `tr()`. Laid out as section plates (`Accordion`, several open at once) in the owner's fixed order ([redesign.md](redesign.md) → Editors): a head (the initials disc with a ring in the worker's worst-status colour, the name, "site · today's punch · month hours", every notice chip, the scan button when editing), then **Person** (Hebrew pairs: given name / surname, ID / ID expiry, sex as a segmented switch, marital status / health fund as selects, birth date / phone), **Address**, **Work** (clients, supplier, HR, start date — a Date Picker, the weekly roster toggle, the contract-expiry toggle, notes), **Documents** (editing only: a plate per document — ID / passport and Form 101 first, then `w.docs` — with Upload / Renew where something is missing or expiring, and Add document; its colour and badge from `workerDocStatus`), **Form 101** (income types, spouse, children, signature — the shared `SignaturePad`), **Access** (the punch link and New token — editing only). Each closed plate shows a summary of its first three values and its colour (amber with a field the scan left empty, green when filled, grey when empty). A closed section keeps its fields in the page (hidden), so every save and search reads them all. A new worker or a scan review opens Person; a section with a scan field left empty opens by itself.

- **Opening:** it warms the Form 101 function (`warmCloudFunctions`); a worker with only `name` shows `docGiven` / `docSurname` split from it (otherwise the "name required" check would silently block the save); clients not in the firm any more and a supplier that is gone are dropped from the form; the roster, the contract warning, the spouse and the children panels start closed.
- **Sections:**
  - **No photo** (owner 2026-10-13): the head shows the initials disc only; a scan takes no portrait.
  - **Scan fields** (`SCAN_FIELDS` in `src/manager/worker.ts`; the page's `SCAN_FIND_FIELDS` keeps the zoomed re-read kinds): given name, surname, ID or passport number, date of birth and sex, plus street, house number and city for an Israeli ID, each with its page (front or ספח) and Hebrew label. A field's state is its mark (`data-scan` on the input: `missing`, `busy`, `none`, `check`, `found`), its note under it (`data-testid="scan-hint"`).
    - **Field search:** when the worker has a scan to search (`workerHasScanPages`), every empty scan field is framed amber, placeholder "🔍 Tap to search the scan". Tapping it (a select: on pointer down) searches the scan for that field (`ManagerBridge.findScanFields(editId, keys, docType)` → `findScanFields(w, keys, docType)`). Found → filled, green for a moment (or "check" when unsure). Not found → a note with a link to `rescanFromWorkerModal()`, and further taps no longer search. Failed or no answer in time → the field is framed to be searched again (a tap), with a note giving the reason. Typing clears the mark.
    - **Second pass after a scan** (`autoFindMissingScanFields` → the window's `findMissing`, called by `openWorkerModalFromScan`): all framed fields are searched together, in one request. Street, house number and city are left out when the live scan has no page besides the front.
    - `findScanFields(w, keys, docType)` (the page; one request for all keys) takes the photos from `workerScanPages(w)`: the scan in memory when it belongs to this window, else the stored pages (`loadStoredAssets`, `src/manager/data/pages.ts` — `loadWorkerPages`, or the old sidecar; cached per set of files). It sends up to 4 photos, ספח pages first when every field is an address field, to `aiFindField` with `fields`. Values found with a box are re-read zoomed in one `aiVerifyFields` per page (`digits9`/`passportNo`, `date`, `hebrewText`/`latinName`, `houseNumber`), and the zoomed read wins. The value is then normalized: ID digits, `DD/MM/YYYY`, sex `M`/`F`, house number without spaces. When the two reads differ, the result is `unsure`. A search always ends (`SCAN_FIND_MS`: the stored pages 45 s, the search 60 s, each zoomed re-read 30 s — a re-read given up keeps the first read): the stored pages not read, the search failed (an `error` reply) or not answered in time → it rejects, and the window or the card gives the field back to be searched again with a note; no scan → `null`.
    - **"Check" fields:** the fields whose two scan reads disagreed (`w.__scanCheck`, from the scan) are framed amber with "Check — …" until edited. The first tap on such a field reads it again (`recheck`); the note's "🔍 Read it again from the scan" link reads it again any time. The same value → the frame goes (green for a moment). Another value → put in, still framed, with "Check — before: … · after: …" and **Restore**. Not found → the value stays, framed.
    - `rescanFromWorkerModal()` (the page) keeps the form as a draft (`window.__wDraft` = `ManagerIsland.editorDraft()`: the form's values, children, clients, the signature drawn) and opens the scan window over it: with this session's pages already in it when the scan in memory belongs to this window (a new worker, or this worker just rescanned) — add, remove or re-cut pages; only the changed ones are read again — otherwise a new scan of this worker (`__aiRescanWorkerId`; [scan.md](scan.md) → Scan again). When the scan finishes, `openWorkerModalFromScan()` opens the window again and calls `applyWorkerDraft()`: a field that had a value keeps it, an empty one takes the scan's value; the signature comes back on the pad. `openAddWorker`, `openEditWorker` and `startNewScan` clear the draft.
  - The form's title has no status or saved date: both are on the worker card.
  - **Personal data**, two short fields per line (`FieldRow`): first + last name; ID/passport + ID expiry; sex; marital status + health fund; date of birth + phone; street + house no. + city (one line of three). No money field: rate, pay mode, OT / Shabbat, travel and bank are set in the pay window ([accounting.md](accounting.md)); the save keeps them on an edit. One rule stays: when a client that has a rate is added to an hourly worker with a rate of their own, the own rate is cleared (`hourlyRate = 0`), so the new client's rate applies.
  - **Clients.** Chips (✕ removes) plus a Combobox "Tap to add a client" listing the clients not yet added (search by name and object).
  - **Supplier.** A select (`#wSupplierId`). **HR** (`#wHrId`, owner and super-admin only, below).
  - **Weekly schedule.** Behind a toggle. It is only written on save if it was opened: a new worker gets all days off, an existing one keeps their shifts.
  - **Contract-expiry warning.** Behind a toggle; opening it turns the warning on (`expiryEnabled`): the term's months and how many months ahead to warn, and where the term counts from (the latest contract's date, else the start date); it says in red when there is neither.
  - **Spouse and children.** Two buttons side by side, each opening a framed panel: the spouse fields and the children rows (the name across, then ID / passport, date of birth and delete). The buttons show "✓" for a filled-in spouse and the number of children. Picking "married" opens the spouse panel.
  - **Contract** (its own section, between Documents and Form 101; `ContractSection`, `src/manager/WorkerContract.tsx`): the contract's category (`#wContractCategory`, the firm's categories offered), the template (`#wContractTemplate`: the category's default, or another for this worker alone), the worker's own terms (`#wTerms1`…`#wTerms5`) and, for a saved worker, **A contract for this worker only** (the upload window of Contract templates, the template kept as the worker's own and picked). The firm's templates load when the section is first opened ([contracts.md](contracts.md) → The worker's contract).
  - **Signature, notes.** No colour picker — a new worker gets the next `WORKER_COLORS` colour (`blankWorkerDefaults`), an edited one keeps its colour; the signature pad ([form101.md](form101.md)); notes; a new punch-link token (`regenerateWorkerToken(wid)`: asks, saves, the window shows the new link).

### Saving (`saveWorker()`, `src/manager/worker-save.ts`)

The window has no Save button: it saves when closed by a tap outside (`workerOverlay.__onUserClose` → the page's `saveWorker({auto:true})`, one save at a time, `saveWorker.busy` → `ManagerIsland.saveWorker`). A note under the form says so. On such a close: an edit with nothing changed (form fields, signature, HR pick, a rescan) just closes — the form is compared with the record and with the record's own form put through the same save, so the form's defaults (a start date of today, the income types…) on a record that lacked them are not a change; nothing is saved and Form 101 is not rebuilt; an empty name closes without saving (an edit says so in a toast, a new worker is not created); otherwise the steps below run. `saveWorker()` with no options (tests, the scan flow) behaves the same except that an empty name focuses the field.

1. **Read the form** (`commonFields` in `src/manager/worker.ts`). The document number is normalized (`normDocId`): a passport's without spaces, in capitals; an Israeli ID's digits joined, an 8-digit one zero-padded to 9. A spouse entered with no marital status saves as `marital_married`. Empty children rows are dropped. Status (set on the card) and colour stay the record's.
2. **Duplicate guard.** Numbers are matched without spaces, dashes or leading zeros (`docIdKey`); an edit whose number differs from the stored one only in form (an older 8-digit ID the save would pad, dashes, capitals) writes it as stored (`keepStoredDocId`), so the signed print's hash and the Form 101 stay as they are. For a new worker: if another worker has the same number (`ManagerBridge.findByDocId`), `confirm()` offers to update that worker instead (`mergeIntoDuplicate`): only what the user entered overwrites — not empty values, nor the form's defaults (start date, contract warning, income types, marital status), nor the document type unless a scan of this session found it; an empty HR field keeps the worker's HR; schedule, status and colour are kept; `clientIds` are merged; a live scan in this session marks it as rescanned. Cancel returns to the form. For an edit, by any login: a number changed to one another worker of the firm has (`findByDocId(docId, editId)`) is refused with "A worker with this document number already exists in the firm" and nothing is saved. A second record with the same number is never created.

   An HR login with "only own workers" has only its own workers in `workers`, so when there is no local match it also asks the server (`docExistsInFirm` → `checkWorkerDoc`, answers only yes/no across the whole firm) and refuses with "A worker with this document number already exists in the firm". The same server check also runs when an HR changes an existing worker's number.
3. **Editing an existing worker.**
   - It compares `FORM101_WATCHED` (`docId, address, houseNumber, city, incomeType, otherIncomeType, docSurname, docGiven, maritalStatus, healthFund, workStartDate, phone, docSex, docDob, docChildren` and the five spouse fields), then `commitEdit` puts the form over the record on the page (the own-rate rule above, `avatarB64` dropped, an HR change through `assignWorkersToHr`), `render()`, `autoSave()`.
   - **Rescanned in this session** (`__aiRescannedWorkerId === id`): the window shows the upload progress while `autoUploadWithRetry()` rebuilds the PDF from the fresh scan, for the document type being saved (a rescan that found a passport for a worker added as an Israeli ID builds a passport form and keeps `docType: 'passport'`).
   - **Otherwise**, if a watched field changed or a signature was drawn on the pad: `regenerateWorkerDoc(id, newSigPng)` runs in the background from the stored pages (a new signature replaces the stored one; a rebuild whose pages could not be read is not done), followed by a toast.
4. **New worker.** It gets a `token` and `createdAt` and is added (`addRecord`: `hrId` — an HR login's own uid; for an owner / super-admin the HR field's choice), saved with `autoSave()`. The signature PNG goes to `window.__wCapturedSigPng`, and the window shows the upload progress (`renderWorkerUploadProgress`, advanced by `aiFillForm101`) while `autoUploadWithRetry()` builds and uploads Form 101 from the live scan globals. See [form101.md](form101.md).
5. **HR field** (`#wHrId`, owner and super-admin only, options from `hrUsers()`): `hrUsers()` returns the cached HR list, which is loaded once per app open on first need (the worker window, a worker tile or card with an HR), not at startup; when the list arrives (`prefetchAdminUsers()`), an open window redraws its HR field. The worker card shows the HR ("none" when unassigned) to the owner / super-admin.

`openAddWorker()` clears the scan globals (`__aiScanImage`, `__aiPacketOtherPages`, `__aiAvatarB64`, `__wCapturedSigPng`) so a previous scan never attaches to a manually added worker.

### Deleting (`ManagerBridge.deleteWorkers(ids)` → `deleteWorkerNow(id)`)

Started from a plate's ⋮ or swipe, Select's bulk Delete, or the Delete in the list view's row (only with `hasPermission('workers')`; the worker card has no Delete) — the React list, through the React Undo snack (`undoDelete`): the worker leaves the list at once, Undo brings it back, and when the 5 s are up `ManagerBridge.deleteWorkers(ids)` removes them (`deleteWorkerNow`), `render()`, saves and says so in a toast. **It never asks.** `deleteWorkerNow(id)` removes the worker and their files are deleted best-effort through `gsDeleteWorkerDoc()`: the PDF (`docFileId`), the scanned pages, the signature and the old sidecar (`scanFileIds`), and every `docs[].fileId` (punches and hours stay) — the signed ones too: Delete worker is a person's own delete (`manual`; owner, 2026-10-25 — docs/contracts.md → Signed files are kept).

## Worker documents (contract, visa, work permit, other)

These are separate from the Form 101 scan, and their labels are English.

- `openWorkerDocUpload(workerId)` opens `#workerDocOverlay` (`DocUpload`, a fresh window each time — `key` = the open's number): type (`WORKER_DOC_TYPES`, Contract first), a date (Date Picker, its month and year as two fields in the calendar's caption) — for a contract "Contract date (the contract term counts from it)", today unless changed, saved on each file as `contractDate` (a contract has no end date: a new one restarts the contract term — `workerExpiryStatus`), shown on the card's documents box as "Contract date dd/mm/yyyy"; for the other types "Expiry date (optional — reminder before it expires)", saved as `expiry` (`YYYY-MM-DD`) and shown as "Expires dd/mm/yyyy" — and several files. It opens from the documents box's + Add on the card (and from the notices sheet). The card's ⋮ menu does not give the focus back to ⋮ when it closes (`onCloseAutoFocus` prevented): the focus coming back to the card behind, a moment later, closed a date picker opened meanwhile in a window opened from it.
- **Upload:** every file is prepared with `fileForStorage()` (images shrunk) and all are uploaded in parallel to Storage with `uploadWorkerFile({action:'saveWorkerFile', workerId, …}, onProgress)` (through `ManagerBridge`, real byte progress) — see [app-core.md](app-core.md) → Data calls; the entries `{id, type, name, fileId, url, mediaType, uploadedAt, contractDate | expiry}` are appended to `w.docs` and saved (`addDocs`); a failed file is reported (`reportError`) and the window stays with only the failed files chosen, so Upload again sends only those (the uploaded ones are already added); otherwise it closes and the card shows again.
- The card's documents box lists them as plates (`Plate`, newest first, `PagedList` by 10): the type, the file name, the expiry (amber expiring, red expired) or a contract's date; a tap opens the file, the ⋮ has Open and — with `hasPermission('workers')` — Delete, a swipe left Delete. **Select** (the Select button at the right end of the box's head line, after + Add; `SelectHead`): the boxes, the same button then reads Select all, the glass bar's Delete; another pane clears the ticks, closing the card ends it.
- Delete never asks: the plates go behind the React Undo snack; when its time is up the entries are removed, saved, and their files deleted (`removeDocs` → `gsDeleteWorkerDoc`); Undo brings them back. A signed document (`signed: true`) is removed the same way: Remove is a person's own delete (`manual`; docs/contracts.md → Signed files are kept).

## Hours import (from the worker card)

`openHoursImportModal(workerId)` opens `#hoursImportOverlay` (`HoursImport`):
- a client select (the worker's clients, or all clients if they have none) and a file input (`.xlsx`, `.xls`, `.csv`, images, PDF; several files);
- **reading the files** — every file in parallel: spreadsheets → the page's `parseHoursExcelFile()` (SheetJS; a header row with `Date` and `In`, `Out` optional, or the same words in Russian, any order, case-insensitive; a spreadsheet's date cells come as dates, a CSV is read as text — `raw` — so a day-first date is not taken as month first); images and PDFs → `fileToUploadPages()`, then every page in parallel → `parseHoursImagePage()` (`aiReadHoursTable`). Every date goes through `normHoursDate` (`src/manager/logic/dates.ts`: `d/m/yyyy`, `d.m.yyyy`, `d-m-yyyy`, `yyyy-mm-dd`, a Date) to `dd/MM/yyyy`, and every in / out time through `normHoursTime` (`H:MM`, `HH:MM[:SS]`, `H.MM`, `HHMM`, an hour alone, a spreadsheet's time cell) to `HH:MM`; one that is not a real date or time is kept as it was read; a row with neither time (a day off) is dropped;
- **preview** — the first 10 entries are shown, those that can't be sent (`isHoursEntry`: a date that is not `dd/MM/yyyy`, an in that is not `HH:MM`, an out that is neither empty nor `HH:MM`) first and in red with a count; while there is one, the send is refused with a toast (fix the file and choose it again);
- **enter by hand** — "Add shift" rows of date (Date Picker) / in / out (`nextManualDate`, `manualEntries`); each new row takes the day after the last one; a daily-paid worker's row may leave the times empty and counts as one day, 08:00–16:00. The send button is on whenever there is a file or a row; a row that can't be sent (no date; an hourly worker without in and out; only one of the two times) is outlined red and explained in a toast (`manualRowsProblem`), and nothing is sent;
- **submit** — sends `savePendingHoursBatch` (it refuses a date that is not `dd/MM/yyyy`, a time that is not `HH:MM`, and an out with no in) with the file's and the typed `{workerId, clientId, date, inTime, outTime}` rows in one batch (file name, plus "entered by hand" when rows were typed); the window stays open and clears;
- **sent for approval** — this worker's batches (`loadPendingHours`; an own-workers HR gets only its own) with a status chip (`HoursStatusChip`): amber "Sent for review", green "Approved", red "Rejected", with the date; paged by 10.

Nothing reaches payroll until an owner approves it in Accounting ([accounting.md](accounting.md)).
