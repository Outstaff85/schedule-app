# Build: the new stack and dist/

The move to React ([react-migration-plan.md](react-migration-plan.md)) is done (stages 0–7). Two kinds of page build into `dist/`:

- **New pages** — React + TypeScript + Tailwind + shadcn/ui in `src/`, built by Vite: the test page `/next` (`next/index.html` → `src/next/`), the client portal (`client-portal.html` at the repo root → `src/client/`), the supplier portal (`supplier-portal.html` → `src/supplier/`) and the worker punch page (`worker-punch.html` → `src/punch/`); they keep their old file names, so `/client`, `/supplier`, `/punch`, the manager app's hand-over, the workers' links and the service worker's list stay the same.
- **The manager app** — `schedule-manager.html` at the repo root, copied into the build unchanged with the files it loads (`firestore-backend.js`, `scan-pipeline.js`, `payroll.js`, `og.css`, the fonts and the icon subset). Every tab and window is React, from one built module, `assets/manager.js` (below); the page itself keeps the frame, the login, the map picker, the scan window and the data layer the React pieces call through `ManagerBridge`.

Firebase Hosting serves `dist/`, which `npm run build` makes from both.

## The tokens in the new stack

`og.css` stays the one copy of `docs/design/system/tokens.json` in the code. A new page links `/og.css` (and `/fonts/fonts.css`) in its HTML entry; Vite bundles both into the page's CSS. `globals.css` defines no token: its `@theme inline` block points Tailwind's color names at the tokens — the shadcn/ui names (`background` → `--ground`, `foreground` → `--ink`, `card` → `--plate`, `popover` → `--glass-menu`, `primary` → `--glass-strong`, `secondary` → `--glass`, `muted` → `--surface-2`, `muted-foreground` → `--ink-2`, `accent` → `--glass-active`, `destructive` → `--red`, `border` → `--hairline`, `input` → `--glass-edge`, `ring` → `--accent`) and the Odinson Glass names (`plate`, `plate-on`, `glass`, `glass-edge`, `sheet`, `faint`, `info`, `ok`, `warn`, `bad`, `fig`). `og.css` is unlayered, so where a name is both a token and a Tailwind theme variable (`--font-sans`, `--font-mono`, `--radius-sm` … `--radius-xl`) the token wins: `rounded-lg` is 16px and `font-sans` is DM Sans. A class like `bg-plate` or `text-muted-foreground` is the way to color a new component; `tests/design/check.js` fails when a file in `src/` or `next/index.html` defines a token.

## `npm run build`

1. `tsc --noEmit` — the TypeScript check; an error stops the build.
2. `vite build` — builds every page in `input` into `dist/` (`dist/next/index.html`, hashed files in `dist/assets/`) and the manager app's module `src/manager/main.tsx` as `dist/assets/manager.js` (a fixed name, `output.entryFileNames`; the chunks it imports keep their hashed names); `dist/` is emptied first.
3. `node scripts/copy-static.mjs` — copies the manager page and its files into `dist/` byte for byte. The list (`staticFiles`) is every file tracked by git (every file on disk when there is no git) except: the top-level `firebase.json`, the rules and index files, the new pages' HTML entries at the top level (`client-portal.html`, `supplier-portal.html`, `worker-punch.html`) and `manifest-punch.json` (built by Vite with the punch page), `docs/`, `archive/`, `functions/`, `functions-auth/`, `tests/`, `node_modules/`, `dist/`, `src/`, `next/`, `scripts/`, `package.json`, `package-lock.json`, `tsconfig.json`, `vite.config.mts`, `components.json`; anything under a dot folder or named with a dot first; and any `*.md`, `Screenshot_*.jpg|png`, `*-local.html`, `*.log`, `*.pyc` or `__pycache__`. A file Vite also built stops the copy with an error.

`payroll.js` (the manager page's copy of `src/lib/payroll.ts`, docs/accounting.md → Payroll module) is not built here: it is committed, so the page also works from the repo root. Step 1 is followed by `node scripts/build-payroll.mjs --check`, which builds `payroll.ts` in memory (Vite library mode, one IIFE, not minified, global `Payroll`) and stops the build when the committed `payroll.js` differs; `npm run build:payroll` rewrites it. Step 3 copies it like every other old file.

`tests/build/check.js` then checks `dist/`: every listed file is there and identical to the repo's, `schedule-manager.html` loads `assets/manager.js`, which is built with every chunk it imports, `schedule-manager.html`, `service-worker.js`, `og.css`, `manifest.json`, `payroll.js` and the icons are on the list and `client-portal.html` / `supplier-portal.html` / `worker-punch.html` / `manifest-punch.json` are not, the punch page's built manifest has absolute paths and its icons and start page are in `dist/`, nothing that must never be public is in it (functions, tests, docs, `src/`, sources and config, dot files), `dist/next/index.html`, `dist/client-portal.html`, `dist/supplier-portal.html` and `dist/worker-punch.html` point at their built scripts, and `firebase.json` serves `dist`.

## Other commands

- `npm run dev` — the Vite dev server. It serves the repo root, so the manager page opens at the same paths as on Hosting (`/schedule-manager.html`, `/og.css` …) and the new ones at theirs (`/next/`), with instant reload for `src/`.
- `npm run typecheck` — only the TypeScript check.
- `npm run preview` — serves `dist/` after a build.
- `npm run check:build` — `tests/build/check.js`.

## Hosting

`firebase.json` → `hosting.public` is `dist`. The rewrites (`/` → `schedule-manager.html`, `/punch`, `/supplier`, `/client`, `/next` → `/next/index.html`), the `no-cache` headers and the `ignore` list are unchanged; the ignore list still guards against a file that must never be public reaching `dist/`. The service worker (`service-worker.js`) is an old-page file and is copied as is; it is network-first for every same-origin GET and keeps a copy of each file it fetched, so a new page opened once online also opens offline with its hashed files (the punch page relies on it — keep its code free of lazy chunks).

## CI

- `deploy.yml` (every push to `main`): `npm ci`, `npm run build`, `node tests/build/check.js`, then the Hosting deploy of `dist/`. A failing build or check stops the deploy; the live site stays as it was.
- `tests.yml` (every pull request into `main`): the same build and check after the dictionary / icon / token checks; the browser tests then run against `dist/` (`tests/e2e/run.sh` serves `dist/` when it is built, the repo root otherwise) and start with `tests/e2e/next.test.js` ([tests.md](tests.md)).

## The manager's React pieces

Stage 6 moved the manager app (`schedule-manager.html`) to React one tab at a time; the page is copied byte for byte and every tab and window is a React root inside it:

- **Loading.** The page ends with `<script type="module" src="assets/manager.js">`. Vite builds it from `src/manager/main.tsx` under that fixed name (Hosting serves `*.js` with `no-cache`, so a new build is picked up at once); `npm run dev` answers `/assets/manager.js` from the source (a small plugin in `vite.config.mts`). Opened as a file, without the build, the moved tabs stay empty.
- **Styles.** `src/styles/manager.css`, imported as a string and put in a `<style>` right before the page's `og.css` link: Tailwind's theme and utilities with the shadcn names (`theme.css`) and no preflight (the page has its own reset), not in a cascade layer (the page's unlayered `* {margin:0; padding:0}` would beat layered utilities), and a small reset scoped to the React roots (`[data-island]`). og.css comes after it, so og.css still wins where they meet, as on the new pages.
- **Data and actions.** The page sets `window.ManagerBridge` (`src/manager/bridge.ts` is the contract): the language and its loaded dictionary (`lang()`, `dict()` — the pieces call `adoptLanguage`, no `I18nProvider`), a tab's snapshot (`today()`, `schedule()`, `workers()`, `clients()`, `suppliers()`, `accounting()` with `accData()`), and the page's actions (Today: `openWorker`, `openNotices`, `openSuppliers`, `addWorker`, `refresh`; Schedule: `setWeek`, `setClient`, `setShift`, `applyDated`, `decideRequest`, `moveWorker`, `editWorker`, `exportAs`, `toast` — [app-core.md](app-core.md) → Schedule tab; Workers: `scanNew`, `openPay`, `copyLink`, `setStatus`, `deleteWorkers` with `openWorker`, `openNotices`, `editWorker`, `addWorker` — [workers.md](workers.md) → Workers tab; the worker windows: `card`, `notices`, `editorInfo`, `record` and the actions `WorkerBridge` lists — the card's status, scan field and documents, the window's scan search, its save (`findByDocId`, `docExistsInFirm`, `commitEdit`, `addRecord`, `uploadForm101`, `regenerateDoc`), the uploads (`fileForStorage`, `uploadWorkerFile`), the hours (`parseHoursSheet`, `filePages`, `readHoursPage`, `sendHours`, `loadPendingHours`, `exportHours`) — [workers.md](workers.md) → The worker windows in React; Clients and Suppliers: `openClient`, `openSupplier`, `manualPunch`, `deleteClients`, `deleteSuppliers`, and for their windows `clientInfo`, `supplierInfo`, `commitClient`, `commitSupplier`, `punchFromClient`, `deleteFromEditor`, `pickPlace` (the page's map picker), `saveLogin`, `newLogin`, `punchInfo`, `addPunch` — [clients.md](clients.md), [suppliers.md](suppliers.md); Accounting: `setPeriod`, `ensurePeriod`, `openClientWindow`, `hourApprovals`, `resolveFix`, `openSigned`, `approveBatch`, `rejectBatches`, `hoursCall`, `xlsx`, `payInfo`, `savePay` — [accounting.md](accounting.md) → Accounting tab; Admin: `admin()`, `setAdminPane`, `punchLog`, `loadEarlierPunches`, `loadAllPunches`, `exportPunches`, `clearPunchMonths`, `savePunch`, `deletePunches`, and for Firms, Users, Errors and Timings `adminCall` (a data call through the page's dispatcher), `loadFirms`, `openFirm`, `setFirmsActive`, `deleteFirms`, `openFirmWindow`, `firmsPayable`, `loadUsers`, `openUserWindow`, `deleteUsers`, `setLogPeriod`, `reloadLog`, `resetLogs`, `copyText`, with their windows' `firmInfo`, `loadProfile`, `firmMessage`, `saveFirmMessage`, `firmSaved`, `userInfo`, `hrMonthCommission`, `assignWorkers`, `openAssign`, `userSaved` — [admin.md](admin.md)). The module also sets `window.ManagerAcc` (the Accounting figures of `accounting.ts` the page's own wrappers call: `salaryEntriesFor`, `commissionFor`, `supplierCommission`, `hourApprovalSummary`, …). The page's state that the frame shares (the shown week, the Schedule tab's site filter) stays on the page; an action changes it and redraws through `render()`. Data that still belongs to a tab not yet moved (a worker's notices, today's shift) is worked out on the page by its own functions and handed over, never computed a second time in React.
- **Drawing.** The module sets `window.ManagerIsland` (`renderToday()`, `renderSchedule()`, `renderWorkers()`, `renderClients()`, `renderSuppliers()`, `renderAccounting()` with `setAccTab(k)`, `renderAdmin()`, `renderFirmsScreen()` — one React root per moved tab, `#todayRoot`, `#scheduleRoot`, `#workersRoot`, `#clientsRoot`, `#suppliersRoot`, `#accountingRoot` and `#adminRoot` (the whole Admin tab: the section tabs, tiles, Punch Log, Firms, Users, Errors and Timings), and `#firmsScreenRoot` (the firms of the super-admin's landing screen `#firmsScreen`, whose header stays the page's) — and fires `manager-island-ready`; the page's draw function for a moved tab (`renderDashboard`, `renderSchedulePage`, `renderWorkersPage`, `renderClientsPage`, `renderSuppliersPage`, `renderAccounting`, `renderAdmin`) calls it, so `render()`, `switchTab()` and a language change redraw the React tab as they did the old one; the tab reads a fresh snapshot on each call. The draw is synchronous (`flushSync`), so the page's code right after it (the breadcrumb reads the lit site tab) sees the new DOM. The React Undo snack (`UndoHost`) is one more root of its own, at the end of `<body>` (`[data-island="undo"]`), shared by every moved tab — inside a tab's section a hidden tab would hide it.
- **Windows.** A moved window is drawn into the page's own overlay (`.overlay > .modal#…`, `windowRoot` in `main.tsx`; `data-island="window"` on the `.modal`), so it opens, closes and chains with the old windows (backdrop, swipe, `__returnTo` / `__reopen`): now the worker card, the notices sheet, the worker window, Add document and Upload / Export hours (`ManagerIsland.openCard`, `openNotices`, `openEditor`, `openDocUpload`, `openHoursImport`, `openHoursExport`; the window's `saveWorker`, `editorDraft`, `applyDraft`, `findMissing`, `uploadProgress`) the client window, the supplier window and the manual punch (`openClient` with its `saveClient`, `openSupplier`, `openManualPunch`; the pay window, `openPay`; and the firm window, the user window and Add workers, `openFirm`, `openUser`, `openAssign`; a window that comes back draws itself again from the saved record, `overlay.__reopen`). The map picker stays the page's Google Maps window; the client window opens it and gets the place back (`pickPlace`). The page's entry point draws the window, then opens its overlay; a closed overlay lets go of its React content; `render()` calls `refreshWindows()` so an open window reads its data again. Their Radix menus, selects and date pickers get `z-index: 3600` in `manager.css` (the overlays are 100–960). When the frame moves to the React `Shell`, they move to `Window`.
- **What stays on the page** (stage 7, the cleanup): no tab or window is drawn by the page's own code. It keeps the frame (the title bar with the breadcrumb, the greeting and the bell; the side menu and the phone bottom bar with its More sheet; the account menu; the Language sheet; the side panel's worker list and site filter), the login and the Firms screen's header, the map picker, the scan window (`scan-pipeline.js`), the data layer (load, save, cache, punches, the dispatcher) and every action the bridge hands over — stage 7 removed the rest (the page's functions, CSS and `og.css` rules nothing drew any more; [history.md](history.md) → React migration stage 7). The React `Shell` with `app` draws the same V7 frame ([components.md](components.md)); moving the frame and the login into it and making the page a Vite entry like the portals would take the page's remaining script into `src/` — not done: it is the data layer the bridge serves, not dead code.

## Adding a new page

Add its HTML entry (like `next/index.html`: links `/fonts/fonts.css` and `/og.css`, one `<script type="module">` to its code in `src/`) to `input` (and `optimizeDeps.entries`) in `vite.config.mts`, its folder name — or, for an entry at the top level that replaces an old page (`client-portal.html`, `supplier-portal.html`, `worker-punch.html`), its file name — to `EXCLUDED_TOP` in `scripts/static-files.mjs`, the entry to the built pages `tests/build/check.js` checks, its route to the Hosting rewrites, and a browser check.
