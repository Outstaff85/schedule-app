# Tests

Everything runs on the Firebase emulators — never against the live project, no secrets. On every pull request into `main` the workflow `.github/workflows/tests.yml` runs all of it (about 5–10 minutes; a new push to the same PR cancels the run still in progress, so only the latest commit is tested); a red check on the PR means something below failed — fix it before merging.

Each test file runs in its own `firebase emulators:exec --only firestore,auth,storage`, so each starts from clean data.
- **`run.sh <file>`** — serves `dist/` on `127.0.0.1:8765` (what Hosting serves; the repo root when `dist/` is not built), starts `server.py`, waits for "ready", runs the file with node, stops both.

- **Fire-and-forget work:** a check on something the code starts without awaiting it (the replaced scan pages and the old sidecar deleted by `saveScanPages`) polls for it (up to ~5 s) instead of reading it at once.
- **Writing a check:** `ok(condition, 'area: what is expected ' + JSON.stringify(details))` — prints `PASS`/`FAIL` (on GitHub Actions a `FAIL` is also printed as an `::error::` annotation, so the check run shows it without opening the log); the file ends with "ALL PASSED" or "N FAILED" and exits non-zero on a failure. Most checks run code in the page (`p.evaluate`) and read the page's own globals. Add the check next to the area it covers; a new feature gets a check in the same PR.
- **Screenshots** go to `tests/e2e/out/` (git-ignored; `E2E_OUT` overrides). In CI they are uploaded as the artifact `e2e-screenshots` when the job fails.
- **A fixed "today"** (`E2E_NOW`, set by `run.sh`): the latest Wednesday or Thursday from the 3rd of a month on, 12:00 UTC. `server.py` seeds from it and every page's clock starts at it (`ctx.clock.install`), so "yesterday" is always a weekday of the same week and month and the checks give the same result on any day (a run on a Sunday used to see yesterday's shift as last week's Shabbat).
- **Options:** `CHROMIUM_PATH` — a Chromium binary to use instead of Playwright's own; `E2E_NOW` — another "today" (ISO, e.g. `2026-09-03T12:00:00Z`).
- **When a check fails:** read the `FAIL` line (it carries the details), reproduce with `npm run test:main` (or `test:hr`), fix the code — or the check, only when the behaviour change was intended. A check is never deleted or skipped to make the run green.
