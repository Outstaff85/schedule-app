# Tests

Everything runs on the Firebase emulators — never against the live project, no secrets. On every pull request into `main` the workflow `.github/workflows/tests.yml` runs all of it (about 5–10 minutes); a red check on the PR means something below failed — fix it before merging.

| Suite | Where | What it checks | Run locally |
|---|---|---|---|
| Dictionaries | `tests/i18n/check.js` | every `tr()` / `data-i18n` text has a Hebrew translation, none is empty or unused | `node tests/i18n/check.js` |
| Design tokens | `tests/design/check.js` | `og.css` carries every token of `docs/design/system/tokens.json` with the same value, every page links `og.css`, no page redefines a token — nor does any file of the new stack (`src/`, `next/index.html`, which must link `/og.css`) | `node tests/design/check.js`; after editing `tokens.json`, `python tests/design/build.py` rewrites the token block of `og.css` |
| Design audit (not a test) | `tests/e2e/audit.js` | screenshots of every screen and window of every page at 390 and 1280 px, for comparing with `docs/design/system/` (stage 13) | `cd tests/e2e && PYTHON=… E2E_OUT=<dir> npm run audit` |
| Build | `tests/build/check.js` | after `npm run build`: `dist/` holds every file of the old pages unchanged, the built new pages, and nothing that must never be public; `firebase.json` serves `dist` ([build.md](build.md)) | `npm ci && npm run build && node tests/build/check.js` (repo root) |
| Payroll | `tests/payroll/compare.test.mjs` | the old pages' payroll code (`legacy.mjs`, a verbatim snapshot of the four pages' copies before stage 2 — never edited) and `payroll.js` (built from `src/lib/payroll.ts`) on the same inputs, each page's way (the manager with `tr`, the portals without), inside one vm with a fixed clock and `TZ=Asia/Jerusalem`: 22 generated months × 14 workers (rates as numbers, strings, empty, overrides per client, daily pay, travel, days set by hand; day, night, split and Saturday shifts, double IN, OUT without IN, missing times, 0 min, >12 h, open shifts) — buckets, hours and warnings, rates and sources, every shift's pay, daily pay's seen days, period keys and overrides must be identical; plus figures checked by hand. `--data <export.json>` (`{workers, clients, punches}`) also compares a real export | `node tests/payroll/compare.test.mjs` (`npm run test:payroll`) |
| Icons | `tests/icons/check.js` | every `ti-<name>` used by a page is in the self-hosted subset | `node tests/icons/check.js` |
| Rules | `tests/rules/rules.test.mjs` | `firestore.rules` / `storage.rules`: who may read and write what (firms, roles, HR, suppliers) | `cd tests/rules && npm install && npm test` |
| Functions | `tests/auth/*.py` | `functions-auth/`: login, users, punch link, supplier portal, hours review (`test_hours.py`), AI reads (`ai_golden.json`), files | `cd tests/rules && PYTHON=<python> npm run test:auth` |
| Browser | `tests/e2e/` | the `/next` component gallery of the new stack (`next.test.js`, from `dist/`), then the real pages in Chromium with the real function code: login per role, workers, schedule, accounting and exports, punch link, supplier portal, client portal and hours review, HR | `npm ci && npm run build` at the repo root, then `cd tests/e2e && npm install && PYTHON=<python> npm test` |

`<python>` = a Python 3.12 with `pip install -r functions-auth/requirements.txt pytest`. The emulators need Java 21. In a Claude cloud session Chromium is preinstalled (`PLAYWRIGHT_BROWSERS_PATH`); elsewhere run `npx playwright install chromium` once.

## Browser tests (`tests/e2e/`)

- **`package.json`** — `npm test` = `build` (bundles the Firebase web SDK 12.19.0 from `firebase-entry.js` into `build/firebase-all.js` with esbuild) + `test:next` + `test:main` + `test:hr`. `test:next` (`next.test.js`) needs no emulators: it serves `dist/` itself on `127.0.0.1:8766` (with the `/next` rewrite) and checks the component gallery (docs/components.md) on a computer (1280px, mouse) and a phone (390px, touch): every component block is drawn; plates and fonts carry the `og.css` tokens; tabs on a computer, the bottom bar with More on a phone; a list shows 10 rows and "Show more (4 left)"; a scroll that no user input started and a wheel up load nothing, a wheel down with the row in view loads the next page; tap opens a plate's details, double click (computer) and long press (phone) open the edit window — a Dialog on a computer, a Drawer on a phone, no ✕ or Cancel, closed by the backdrop; a swipe left shows Edit / Delete; ⋮ holds Delete last in red-soft; Delete shows the Undo snack and Undo restores; Select mode (tick boxes, "2 selected", the bulk delete); a figure filters; a second window goes back to the first; Select, Combobox search and the Date Picker; the form's field errors; the Language window, Hebrew from `i18n/he.json`, the layout left to right and the choice kept in `uiLang`; no script errors; the old manager page comes out of `dist/` unchanged. Screenshots of every section on both sizes go to `out/` (`next-computer-*.png`, `next-phone-*.png`). It stops with a message when `dist/` is not built. Each test file runs in its own `firebase emulators:exec --only firestore,auth,storage`, so each starts from clean data.
- **`run.sh <file>`** — serves `dist/` on `127.0.0.1:8765` (what Hosting serves; the repo root when `dist/` is not built), starts `server.py`, waits for "ready", runs the file with node, stops both.
- **`server.py`** — the real `functions-auth/main.py` functions (`login`, `users_admin`, `punch`, `supplier`, `hours`, `ai_read`, `weather`) behind one local HTTP server on `:5055`, on the emulators. It seeds two firms (`seed()`: owner `owner1`, supplier `sup1`, super-admin `boss`, supplier `sup1` with hours ticks hours / approve / export, client login `client1` (client c2, every hours tick), workers Avi `tok-avi` and Dana `tok-dana`, clients, punches yesterday and 9 days ago) and replaces the Anthropic call and OpenWeatherMap (light rain, 14°) with stand-ins. Test hooks: `POST /seed` (reseed), `/aicalls`, `/revoke` (gives Avi a new link token), `/lang/<code>`, `/punches` (count and ids).
- **The pages see the emulators** through `localStorage.fsEmulator`, a fake `FIREBASE_WEB_CONFIG`, the SDK served from the bundle in place of gstatic, every `cloudfunctions.net/<fn>` call forwarded to `server.py`, SheetJS from `node_modules/xlsx` (0.18.5, as on the page) and a slow-enough fake GPS. Any other external request is answered empty and recorded (`external`) — the tests check that nothing goes to `script.google.com`.
- **`main.test.js`** — firm owner (workers, schedule, documents and uploads to Storage, accounting: salary, daily pay, accountant report, upload hours, punch log filters and CSV), super-admin summary, a supplier sent to its portal, the supplier portal (and its Hours approval tab), the client portal (approve a day, dispute, propose a fix, the owner's Hours approvals and accepting the fix, the unified user form, the redirect), the punch link (punch, My Schedule, My Hours and Pay, revoked and unknown links, language); on each of the four pages, that the shift pairing and pay come from `payroll.js` (`payrollCheck`). **`hr.test.js`** — the HR role (own workers only, assigning, rules, pay view, its Hours approval in Accounting).
- **Writing a check:** `ok(condition, 'area: what is expected ' + JSON.stringify(details))` — prints `PASS`/`FAIL` (on GitHub Actions a `FAIL` is also printed as an `::error::` annotation, so the check run shows it without opening the log); the file ends with "ALL PASSED" or "N FAILED" and exits non-zero on a failure. Most checks run code in the page (`p.evaluate`) and read the page's own globals. Add the check next to the area it covers; a new feature gets a check in the same PR.
- **Screenshots** go to `tests/e2e/out/` (git-ignored; `E2E_OUT` overrides). In CI they are uploaded as the artifact `e2e-screenshots` when the job fails.
- **A fixed "today"** (`E2E_NOW`, set by `run.sh`): the latest Wednesday or Thursday from the 3rd of a month on, 12:00 UTC. `server.py` seeds from it and every page's clock starts at it (`ctx.clock.install`), so "yesterday" is always a weekday of the same week and month and the checks give the same result on any day (a run on a Sunday used to see yesterday's shift as last week's Shabbat).
- **Options:** `CHROMIUM_PATH` — a Chromium binary to use instead of Playwright's own; `E2E_NOW` — another "today" (ISO, e.g. `2026-09-03T12:00:00Z`).
- **When a check fails:** read the `FAIL` line (it carries the details), reproduce with `npm run test:main` (or `test:hr`), fix the code — or the check, only when the behaviour change was intended. A check is never deleted or skipped to make the run green.
