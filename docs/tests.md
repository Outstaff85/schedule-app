# Tests

Everything runs on the Firebase emulators — never against the live project, no secrets. On every pull request into `main` the workflow `.github/workflows/tests.yml` runs all of it (about 5–10 minutes; a new push to the same PR cancels the run still in progress, so only the latest commit is tested); a red check on the PR means something below failed — fix it before merging.

## Browser tests (`tests/e2e/`)

- **`package.json`** — `npm test` = `build` (bundles the Firebase web SDK 12.19.0 from `firebase-entry.js` into `build/firebase-all.js` with esbuild) + `test:next` + `test:main` + `test:hr`. `test:next` (`next.test.js`) needs no emulators: it serves `dist/` itself on `127.0.0.1:8766` (with the `/next` rewrite) and checks the component gallery (docs/components.md: every block, the account menu among them) on a computer (1280px, mouse) and a phone (390px, touch) — and the **light theme** (`theme()`): Dark by default, the switch (the gallery's, the account menu's on a computer, `ThemeButton`'s window on a phone) turns Light on and keeps it on the device and before the first draw after a reload, every text on plates, badges and figures is ≥ 4.5:1 against what is really behind it and every plate's coloured bar ≥ 3:1, System follows the device live, Dark switches it back: every component block is drawn; plates and fonts carry the `og.css` tokens; tabs on a computer, the bottom bar with More on a phone; a list shows 10 rows and "Show more (4 left)"; a scroll that no user input started and a wheel up load nothing, a wheel down with the row in view loads the next page; tap opens a plate's details, double click (computer) and long press (phone) open the edit window — a Dialog on a computer, a Drawer on a phone, no ✕ or Cancel, closed by the backdrop; a swipe left shows Edit / Delete; ⋮ holds Delete last in red-soft; Delete shows the Undo snack and Undo restores; Select mode (tick boxes, "2 selected", the bulk delete); a figure filters; a second window goes back to the first; Select, Combobox search and the Date Picker; the form's field errors; the Language window, Hebrew from `i18n/he.json`, the layout left to right and the choice kept in `uiLang`; no script errors; the old manager page comes out of `dist/` unchanged. Screenshots of every section on both sizes go to `out/` (`next-computer-*.png`, `next-phone-*.png`). It stops with a message when `dist/` is not built. Each test file runs in its own `firebase emulators:exec --only firestore,auth,storage`, so each starts from clean data.
- **`run.sh <file>`** — serves `dist/` on `127.0.0.1:8765` (what Hosting serves; the repo root when `dist/` is not built), starts `server.py`, waits for "ready", runs the file with node, stops both.
- **`server.py`** — the real `functions-auth/main.py` functions (`login`, `users_admin`, `punch`, `supplier`, `hours`, `ai_read`, `weather`) behind one local HTTP server on `:5055`, on the emulators. It seeds two firms (`seed()`: owner `owner1`, supplier `sup1`, super-admin `boss`, supplier `sup1` with hours ticks hours / approve / export, client login `client1` (client c2, every hours tick), workers Avi `tok-avi` and Dana `tok-dana`, clients, punches yesterday and 9 days ago) and replaces the Anthropic call and OpenWeatherMap (light rain, 14°) with stand-ins. It also serves `contract_templates` (`functions/contracts.py` behind the same gate as `functions/main.py`, on the emulators' Firestore and Storage). Test hooks: `POST /seed` (reseed), `/aicalls`, `/revoke` (gives Avi a new link token), `/lang/<code>`, `/punches` (count and ids), `/signed` (the client's signed month: its record and the PDF from Storage, also saved to `out/client-signed-month.pdf`), `/contractPdf` (a contract template with marks), `/contractTemplates` (the firm's stored templates).
- **The pages see the emulators** through `localStorage.fsEmulator`, a fake `FIREBASE_WEB_CONFIG`, the SDK served from the bundle in place of gstatic, every `cloudfunctions.net/<fn>` call forwarded to `server.py`, SheetJS from `node_modules/xlsx` (0.18.5, as on the page), pdf.js from `node_modules/pdfjs-dist` (3.11.174, as the scanner loads it), the scanner's ONNX Runtime as a stand-in whose models never start (the models are fetched at deploy, not in the tests' build — the lab page's own script still runs) and a slow-enough fake GPS. Any other external request is answered empty and recorded (`external`) — the tests check that nothing goes to `script.google.com`.

- **Writing a check:** `ok(condition, 'area: what is expected ' + JSON.stringify(details))` — prints `PASS`/`FAIL` (on GitHub Actions a `FAIL` is also printed as an `::error::` annotation, so the check run shows it without opening the log); the file ends with "ALL PASSED" or "N FAILED" and exits non-zero on a failure. Most checks run code in the page (`p.evaluate`) and read the page's own globals. Add the check next to the area it covers; a new feature gets a check in the same PR.
- **Screenshots** go to `tests/e2e/out/` (git-ignored; `E2E_OUT` overrides). In CI they are uploaded as the artifact `e2e-screenshots` when the job fails.
- **A fixed "today"** (`E2E_NOW`, set by `run.sh`): the latest Wednesday or Thursday from the 3rd of a month on, 12:00 UTC. `server.py` seeds from it and every page's clock starts at it (`ctx.clock.install`), so "yesterday" is always a weekday of the same week and month and the checks give the same result on any day (a run on a Sunday used to see yesterday's shift as last week's Shabbat).
- **Options:** `CHROMIUM_PATH` — a Chromium binary to use instead of Playwright's own; `E2E_NOW` — another "today" (ISO, e.g. `2026-09-03T12:00:00Z`).
- **When a check fails:** read the `FAIL` line (it carries the details), reproduce with `npm run test:main` (or `test:hr`), fix the code — or the check, only when the behaviour change was intended. A check is never deleted or skipped to make the run green.
