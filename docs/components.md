# Components of the new stack

The React components every new page is built from (archive/docs/react-migration-plan.md → stage 1). Two folders:

- `src/components/ui/` — **shadcn/ui** components, restyled once to Odinson Glass. They are the shadcn source (Radix primitives, vaul, sonner, react-day-picker, cmdk, React Hook Form), the first ones written into the repo by hand because the shadcn registry (`ui.shadcn.com`) was not reachable from the cloud sessions. **A new one is always added with `npx shadcn add <name>` first** (owner, 2026-10-18; the owner allows `ui.shadcn.com` in the cloud environment's network settings); this is done only when a task needs a component the repo doesn't have yet (never as a check at session start), and the session tells the owner in chat and in the PR which component it took from shadcn; only when that command fails is it written from the shadcn source, and the session says so in chat and in the PR, with the error. Either way the result is restyled to Odinson Glass the same way.
- `src/components/shared/` — the app's own template pieces (plates, paged lists, the Undo snack, Select mode, the frame and the bottom bar, the Language button…), built on the ui components.

**Before writing a component, look here first.** A new one is written only when nothing in these two folders fits (CLAUDE.md → New code goes to the new stack). The gallery at `/next` (`src/next/App.tsx`) shows every component in its states, its section **Frame (V7)** (`/next#frame`) shows `Shell` with `app` around a Today-like page, and its section **Scanner** (`/next#scanner`, `src/next/scanner-demo.tsx`) shows the full-screen scanner (`src/scan/ui/` — the same `ScannerScreen` the site's scan window and the scanner lab at `/scan-lab/` draw; [scan-plan.md](scan-plan.md) → S9) at a phone's size on a fake session — the camera with the status line, the pages' strip, the bar and Done; a page opened large; the corner editor — and in a full `Window`; `tests/e2e/next.test.js` checks it on a computer and a phone.

## How they are styled

- **Colours and sizes come from the tokens** (`og.css`, docs/build.md → The tokens in the new stack): Tailwind classes such as `bg-plate`, `text-ink-2`, `text-muted-foreground`, `border-border`, `bg-ok`, `text-fig`, `rounded-lg` (16px). No raw colour or redefined token in a component.
- **What `og.css` already draws is used through its class**, so the old and new pages share one copy of the look: the glass button (`.og-btn`, with its shine and underline), plates (`.og-plate`, `.og-sw`), the ⋮ (`.og-kb`), swipe actions (`.og-acts`), the tick box (`.og-box`), the Undo snack (`.og-snack`), Select's bulk bar (`.sel-bar`), the underline (`.og-uline`), the Language button and list (`.lang-btn`, `.lang-li`, `.lang-search`).
- **Surfaces as Tailwind utilities** (`src/styles/globals.css`): `og-glass-menu` (popovers, menus, Select lists, tooltips, toasts — the windows' own glass since 2026-10-26, owner: the same `--glass-sheet` fill with the `--sheet-grad` gradient and the `--glass-edge` frame as `og-glass-sheet`, plus `--shadow-pop`), `og-glass-sheet` (windows), `og-field` (a window's input: 38px, faint glass, cyan focus ring, red when `aria-invalid`), `og-label` (11/600 uppercase section label).
- `og.css` is not in a cascade layer, so it wins over Tailwind's utilities: to change an `og.css` property on such an element, the Tailwind class needs `!` (e.g. `!h-[34px]` on a small button).
- **Icons:** Tabler Icons from `@tabler/icons-react` (`<IconPencil />`), sized by the component (17–18px). The manager page's own markup keeps the self-hosted subset (`icons/`).
- **Motion:** `motion/react` for heights that open and close (Section, a plate's details) and a removed plate collapsing (`AnimatePresence`); the rest are CSS (`tw-animate-css`'s `animate-in` / `animate-out`, the og.css keyframes `og-flow` / `og-pop`). All of it stops under `prefers-reduced-motion` (og.css).
- **Texts:** every UI text through `tr()` (`src/lib/i18n.tsx`, docs/translations.md → New stack); data (names, sites) never.
