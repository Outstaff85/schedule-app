# Document scan (passport / Israeli ID)

Turns photos or PDFs of an ID or passport into a filled worker form. Two parts (owner, 2026-10-18): **the scanner** finds, cuts and straightens the documents — the camera, the frame, the corners, the page kinds (`src/scan/`: the full-screen scanner and its engine on the phone; The scan window below); **the scan process** reads them — the AI reads, the zoomed re-reads and check digits, merging the pages into one record, the worker form (`src/scan-process/`; Reading below). Both are on the new stack, bundled into the manager page's module. The old pipeline (`scan-pipeline.js`: its own scan window, corner editor, queue and review screens, client-side alignment and tightening) was removed in S5 (2026-10-19, docs/scan-plan.md); a frozen copy, `tests/scan/legacy.js`, is kept only for the comparison test.

The worker window that the scan opens is in [workers.md](workers.md); the PDF built from the result is in [form101.md](form101.md).

## Entry points (`src/manager/page/scan.ts`)

- **`startNewScan()`** — the Workers tab's create button **New worker** (its main part).
- **`rescanFromWorkerModal()`** (`worker-window.ts`) / **`rescanFromWorkerCard(wi)`** — "Scan / Rescan" in the worker window and card, keeping the window's form as a draft (`ManagerIsland.editorDraft()`, the React window — [workers.md](workers.md)). When the window came from a scan still in memory (`__aiScanImage`, the same worker), the scanner opens with this session's pages already in it (Scan again below).

Each warms the Cloud Functions (`warmCloudFunctions(SCAN_WARM_URLS())` — `{"ping":true}` to `fill_form_101` and `ai_read`; at most once per URL every 4 min) and calls **`openNewScan(sameSession?)`**: `openScanner({initial, read})` (`src/scan/open.tsx`) with the scan process as its `read`; once the pages are read, `openWorkerModalFromScan(record, reads)`. A new scan (`sameSession` false) first forgets the last one (`resetScan()`, `src/scan-process/session.ts`); so does New worker (`openAddWorker`).

## Upload preparation (`src/manager/logic/uploads.ts`, shared by every upload)

| Function | What it does |
|---|---|
| `downscaleForUpload(b64, mediaType)` | Shrinks to `UPLOAD_MAX_DIM` = 1800 px (JPEG 0.9). Never upscales; any failure returns the original. |
| `fileToUploadPages(file)` | → `[{b64, mediaType, text, fileName}]`. An image is one page. A PDF goes through pdf.js (`loadPdfJs()`, cdnjs 3.11.174) at scale 2.5, all pages in parallel, keeping the text layer in `text`. |
| `filesToUploadPages(files)` | All files in parallel, as one ordered list. |
| `fileForStorage(file)` | One file kept whole: an image is shrunk, anything else is sent as-is. Used by worker documents. |

**Rule:** a new upload feature must go through these and send its per-page requests in parallel.

## The AI calls

All of them are sent as `fetch(API_URL, …)`; the dispatcher passes them to the `ai_read` Cloud Function ([backend.md](backend.md) → `ai.py`). Independent calls are sent in parallel, and `ai_read` serves them from one instance — the pattern, client and server, is in [backend.md](backend.md) → Parallel AI calls.

| Action | Model | Used for |
|---|---|---|
| `aiDetectAlign` | `ANTHROPIC_ALIGN_MODEL` (Haiku) | The page `kind` (`id_front` / `id_back` / `sefach` / `passport` / `contract` / `other`) and its upright turn (0 / 90 / 180 / 270), no corners — asked by the scan window for every cut page the firm's document type model is not sure of (`src/scan/doctype.ts`; S7), and by the reading only for a page with no face and no kind |
| `aiReadDoc` | `ANTHROPIC_MODEL` | Full read of the main page: `type` (`israeli_id` / `passport`), names, numbers, dates, sex, address, children, spouse; for the name cross-check also `latinSurname` / `latinGiven` (the holder's Latin spelling when the page prints one) and `mrzName` (MRZ line 1 from its 6th character); `fieldBoxes` (boxes of the digit fields and of given name, surname, address, house number, city) |
| `aiReadSefach` | `ANTHROPIC_MODEL` | An extra Israeli-ID page (ספח or card back): address, house number, city, marital status, sex, spouse, children; `idNo`, `given` and `surname` of the holder for cross-check; `fieldBoxes` for address, house number, city. Always `type:'israeli_id'`. With `part:'holder'` / `part:'family'` it returns only the holder's fields (names, ID, address, marital status, sex, `fieldBoxes`) or only `spouse` + `children` |
| `aiVerifyFields` | `ANTHROPIC_MODEL` | Batched zoomed re-read of several fields of one page (kinds `digits9`, `date`, `passportNo`, `hebrewText`, `latinName`, `houseNumber`) |
| `aiVerifyField` | `ANTHROPIC_MODEL` | One zoomed re-read (the ID number's retry) |
| `aiFindField` | `ANTHROPIC_MODEL` | Missing fields searched for on the worker's page photos, from the worker window or card ([workers.md](workers.md) → field search) |

A failed request is "nothing read" (the field keeps what it had); `aiDetectAlign` / `aiReadSefach` errors go to Admin → Errors as `console.warn(…)`. The prompts live in `functions-auth/ai_prompts.json` — see [backend.md](backend.md).

## The scan window (`src/scan/`)

**The scanner is the full-screen scanner on the new stack** (docs/scan-plan.md → S9, owner 2026-10-24: one scanner for the site and the lab, by one template), in site mode. Its engine is `src/scan/engine/` — the scanner lab's working code ported into typed modules with the same logic (proven equal by `tests/scan/engine.test.mjs`, `runtime.test.mjs`, `session.test.mjs`, `files.test.mjs`): the live frame, Auto, the shot cut at once and then refined by the accurate model, the other documents on a photo (up to 4, then a document lying on one — `MAX_DOCS`), a white page cut into its photos, a computer-made PDF page taken whole, the upright turn by the face, the readers (document type, passport zone, Hebrew fields), the ways to run the models (the CPU pool, GPU live + CPU capture, one thread, the page; the 25 s watchdog; the GPU layout that worked first; the way failures kept on the phone), picked files on threads in the files' order, the training attempts. Its screen is `src/scan/ui/` (`ScannerScreen`, mode `'site'`). It runs on **the site's own surface**: `/scan/`, its models, `models.json`, `he-layouts.json` and ONNX Runtime (`ort/`, `ort130/` — `ort.wasm.min.mjs` for the CPU alone, `ort.all.min.mjs` otherwise, imported at run time) put there at deploy by `scripts/scan/fetch-models.sh` at the site's model version (`scripts/scan/models-version`), its own browser cache (`scan-models`); it never loads anything from `/scan-lab/` (the browser test checks the requests). `scan/` holds nothing in the repo: the deploy fills it. **The lab** is the same scanner in lab mode at `/scan-lab/` (`scan-lab/index.html` → `src/scan/lab/`, Admin → Scanner lab; docs/scan-plan.md → Scanner lab): the same screen and engine with the pull-up Lab tools drawer (the figures, Errors, Settings, the readouts), "Show what the models read" in Done's place and the lab's training collection, on the lab's own surface (`/scan-lab/`, its models at `scripts/scan-lab/models-version`, its cache `scan-lab-models`) — so a change to the scanner reaches both, and only the models differ.

**The engine's modules** (`src/scan/engine/`): `geometry.ts` (the corners picked from the heatmaps — mirrored in `scripts/scan-train/docfind.py` —, the homography and warp, the quad checks, a document's shape, a document on a document), `steady.ts` (the sticky green frame, Auto's countdown, the status hint), `track.ts` (the Lucas–Kanade follow between the model's answers), `pictures.ts` (the photos on a white page, a page white to its edges), `readers.ts` (the document type, passport zone and Hebrew field readers — their pure parts mirrored in `scripts/scan-train/mrzmodel.py`, `hemodel.py` and `synth.py`), `fails.ts` and `log.ts` (the way failures kept on the phone, the status line, the log and the errors), `surface.ts` (the site's `/scan/`; the lab's is `src/scan/lab/surface.ts`), `ort.ts` and `models.ts` (ONNX Runtime imported at run time from the surface's folder, the models kept in the Cache API, the sessions with the GPU self-test, its pass remembered on the device — docs/scan-plan.md → Where they run), `upright.ts` (the turn by the face), `worker.ts` (the module worker), `engines.ts` (the ways to run the models, the pool, the capture and file threads, the watchdog), `camera.ts` (the back camera at 30 frames a second), `live.ts` (the live frame and its follow), `shot.ts` (the shot, its refine, the other documents on it), `files.ts` (picked photos and PDFs on threads, in the files' order), `attempts.ts` (the training attempts and their queue), `session.ts` (`ScanSession`, what the screen drives).

**The shutter** (`src/scan/ui/shutter.ts`, owner 2026-10-26; the site and the lab alike): the moment a shot is taken — the session's status `captured`, the shutter tapped or Auto, never a look Auto refused — the screen plays a camera's click (drawn with Web Audio: two short bursts of band-passed noise, no sound file) and a 30 ms buzz (`navigator.vibrate`, where the phone has one). A browser starts audio only from a person's gesture, so the first tap on the scanner's screen unlocks it (`unlockShutter`) and Auto's shots after it are heard too; a picked file is not a shot and makes no sound. `tests/e2e/scanner.test.js` checks one click per Auto shot (`<html data-shutters>`).

the type for a page with no %; a spinner while it is read or typed; a tick once looked at); the bottom bar (`scan-bar`) — **Photos/PDF** (`scan-pick`: one file input, `scan-files`, with no file type set, so the phone's chooser shows photos and PDFs side by side; several files at once, each pick a batch of its own), the big **shutter** (`scan-shutter`: only the shutter — there is no Next) and **Done · n** (`scan-done`) at the bottom right (in the lab **Models read**, named "Show what the models read"); each side has at most a third of what the shutter leaves, and Photos/PDF and Models read are an icon over a short label (`BAR_SIDE`), so none runs under the shutter on a phone of 360 px. **A tap on a photo makes it grow in place** (about 190×124 for a card, its own shape for a page): its type and % on top (`scan-thumb-open` — a tap there opens the page large), a round **Edit corners** button on its left (`scan-thumb-fix`: the corner editor straight from the strip; not on a page kept from before) and a round red **Delete** on its right (`scan-thumb-delete`: no question, the Undo snack); a tap on it again, or on another photo, shrinks it. The page opened large (`page-view`): its type as chips (the model's answer marked with how sure it is), **Fix corners**, **Delete** and **Looks good**. **After a shot the live frame goes on by itself** (no Next), its frame kept where it was — on the document just taken, green while it is held there (it is not wiped and found again red) —, and Auto does not take the same document again — it waits until the documents the shot took have left the frame (none found for 0.7 s) or another document lies away from them (`src/scan/engine/steady.ts` `Taken`); the shutter takes the same document again on purpose. A picked picture is shown in place of the camera while it is worked on, with the green frame of every document found on it so far (`scan-preview`, `data-frames`), and stays 2.5 s after the pick (`PICK_SHOWN_MS`), then the camera comes back; a camera that gets ready meanwhile does not start the live frame over the picture. While a page is opened large or its corners are being fixed, the live frame is paused under it. Every page can be deleted or fixed the moment it is found; a new pick never marks the pages before it as looked at.
- **The session stays 3 minutes** after the window closes (`keep.ts`, owner 2026-10-20): its engines and the models they loaded are kept, so the next worker's scan opens at once, without the models starting again (4–8 s); the camera stops the moment the window closes (`session.sleep`), and when the time is up the session is stopped — its background threads terminated, the readers' sessions released. A window closed without Done discards the scan (`session.discard`: nothing sent).
- **What Auto takes** (owner, 2026-10-31; the site and the lab alike; `autoTakes` and `look`, `src/scan/engine/session.ts`): only a document — what has a document's shape on the live answer (`goodQuad` and `docShape`, `src/scan/engine/geometry.ts`), and only after a full `STEADY_MS` of the model's own answers — a frame only held up by the sticky frame does not count, and at least `SURE_SHARE` (4 in 5) of the answers of the last second must be real ones, so a lone blur or glare does not start the second again and a model that only flickers never gets there (`Steady.sureSince` / `sureFor`, `steady.ts`; `autoShot` is unchanged and compared with the frozen lab) —, and that the document type model calls a document (below). With Auto on the status line does not promise what Auto will not take: "Hold still" counts until Auto's own second is over, a green frame with no document's shape says "Not a document's shape — Auto waits" (the status `not_document`, amber; the hint under the frame: hold the phone straight or use the shutter, or "A little closer" for a small one), so "1 document found" means it shoots now. **After `AUTO_MAX` (5) of its shots in a row with no touch Auto turns itself off**: the session's `auto` event, an amber line on the screen (`scan-auto-stopped`, "Auto stopped after 5 shots in a row — tap Auto to go on") until Auto is tapped. The shutter, the Auto button, `wake`, `hold` and a new open (`markOpen`: the session outlives its window by 3 minutes) start the count again, and a new open also brings back an Auto that turned itself off — one a person turned off stays off. The shutter takes whatever the live frame holds, as before.
- **Auto asks the document type model** (owner, 2026-10-31: a keyboard's key has a document's shape and the edges model was 99 % sure of it): when `autoTakes` says yes, before the shot, the video frame is frozen and cut flat by the frame's corners (`freeze`, `engine.warp` with no face finder — the same pixels the shot's first cut is made of) and the `Readers`' `doctypeAnswer` is asked (`look` / `lookAt`). **Auto shoots only when `documentAnswer` says yes**: a type other than `other`, sure of the type and of the turn (both ≥ `SURE`, 0.9 — `src/scan/turn.ts`, the same bar as Mixed and the exam's "sure"). Anything else takes nothing — no shutter sound, no accurate model, no training attempt, nothing towards `AUTO_MAX` — and the status line says **"Not an ID, passport or contract — Auto waits"** (`not_document` with `type`, amber; the hint under the frame: "Another paper? Tap the shutter to take it"). One question at a time (`checking`, "Checking it is a document…"; the frame goes on being followed under it), and a frame refused is asked about again only when it moved `LOOK_MOVE` (0.06, the jump at which the sticky frame takes it for a new document, which also needs its own second) or after `LOOK_AGAIN_MS` (3 s): a keyboard held in front of the camera costs a run every 3 s, not a run a frame. The model's runs go one after another (`Readers.typeRuns`). After the answer the frame must still be there: a document taken away, a shutter tap, a hold, a pick or Auto turned off while it answered take nothing more. The shutter and picked files never ask. **Real documents outside the five types — a visa, a work permit, a bank letter — count as `other`: Auto does not take them and the shutter does**; that is what the status line and the hint say.
  - **No model:** Auto goes on as it did when the surface's version has no document type model (`models.json` `"doctype": false`, `Readers.doctype` null once they loaded) — **today that is the site: its version, `base-v1`, has no document type model (the lab's v5 has), so on the site Auto still takes anything of a document's shape; the check starts there when the site moves to a version with the model** (the code is the same). A model that fails to load, or fails on a run (said in the errors), is the same. While the readers load Auto waits (`checking`), at most `READERS_WAIT_MS` (20 s, from its first look of this open), so a download that hangs does not stop it.
  - **Measured on the lab's v5** (`doctype-lite.onnx`, the phone's input path mirrored with OpenCV on a PC, 2026-10-31; not on a phone, not on the owner's keyboard): the share of frames Auto would take at type ≥ 0.9 alone / with the turn ≥ 0.9 too: frames of a document's shape on 12 public photos of keyboards (1440 cuts) 2.0 % / 0.4 % (the worst photo, a laptop close-up: 10.0 % / 0.8 %; `other` at any confidence 77 %); on 60 of the training's desk backgrounds with no document (600 cuts) 19.8 % / 3.5 %; the 22 real pages of `H:\israeli-docs` at the four turns (88 cuts) 77 % / 74 % (5 pages never or seldom pass, ID card fronts: their type is a weak answer on these flat copies, while the v5 exam report has 99.3 % sure on 278 photos of held-out pages); 300 MIDV ID cards and passports photographed 99.7 % / 99.7 %; 120 drawn contracts 100 % / 100 %; 900 SmartDoc papers (letters, tax forms, datasheets, patents, magazines) 0 % — all `other`, so a firm's real contract on plain A4 needs trying (none was on hand). The size of the cut made no difference (a page 200 to 900 px long), and a page at a wrong turn none that matters (at 90 / 270° an ID card front often reads as a passport, still a document): so the live cut is enough, it is not set upright, and the turn the model reports is not used, only how sure it is of it. Lower bars buy little: at type ≥ 0.7 and turn ≥ 0.9 real pages 83 %, keyboards 1.7 %.

Put away meanwhile, the camera stays off; if the models fail, it is turned off again and the status says so (`camera_failed`). The shutter stays off until the session's first status (`ready`, `useScanSession.ts`), with what the engine is doing in the status line: there is nothing to shoot with until the models are up; Photos/PDF stays on (a pick waits for the accurate model). The lab waits only for a pick in work.
- **A new listener of the pages hears the ones held now** (`ScanSession.on('page')`, as the screen's fake session does): the scan window listens in its effects, a moment after it shows, so a page given in between (the browser tests give one as soon as the window shows) is still shown in the strip and typed; a scan ended (Done or closed: `endScan`) holds none, so a window opened later shows nothing of an earlier scan. Checked by `tests/scan/session.test.mjs`.
- **Started early on the Workers tab and for a new worker** (owner, 2026-10-27; `keep.ts` `prepareEarly` / `earlyWanted`, `src/scan/open.tsx` `prepareScanEarly`): when the manager opens the **Workers tab** (`switchTab('workers')`, `src/manager/page/nav.ts` — its first drawing, and the landing tab after sign-in when it is the login's home tab; its main New worker button opens the scanner itself) or a new worker's window (`openAddWorker` — Enter by hand, Add a worker), the scanner's chunk is loaded and a scan session is made and its models started in the background (`session.prepare(true)`: the light model first — the live frame's, then the accurate one right after it —, the readers beside them — no camera, nothing on the screen), kept the same 3 minutes as after a closed window; the scan window opened meanwhile takes that session, so Preparing… is short or gone. Never a second session (nothing is started while one is kept or in use; a kept one not in use is given a fresh 3 minutes, so a session kept from a scan 2½ minutes before is still there when Scan is tapped — the Workers tab opened again only refreshes it the same way), never while the scan window is open, never for an existing worker's window, only for a login that may add workers (`canAddWorkers`, `src/manager/logic/access.ts`: the Workers section and Edit workers — the right the New worker button needs; never a supplier or client login, whose tabs are the portal's, nor a staff / HR login without Edit workers), and not on a phone with under 4 GB of memory (`navigator.deviceMemory`; unknown counts as 4, as for the picked files' second thread). A computer with no camera starts it too: photos and PDFs picked in the scanner need the same accurate model.
- **The start order** (owner, 2026-10-27: the light model first; 2026-11-01: the frame first; docs/scan-plan.md → The light model first, The CPU first): the live frame's model starts first, on three CPU threads, so the camera and its frame come as soon as it is ready; behind a gate — the first model answer, 1.5 s after the live models ended, or a pick — the readers' sessions start one after the other, then the accurate model — never two loading at once. A camera shot taken before the accurate model is up is shown at once by the live frame's corners and refined once it is up; a photo or PDF picked meanwhile waits for it ("Preparing the accurate model…", the session's status `preparing_accurate`) and is worked by it alone. The GPU check of a model is skipped on a later open when it passed before on this device with the same model file, ONNX Runtime and browser; a run-time failure of that GPU session removes the pass (docs/scan-plan.md → Where they run).
- **The models kept on the phone** (`models.ts` `fetchModel`): each model file is kept in the surface's own browser cache with the stamp it was downloaded under — its fingerprint from `models.json` (sha256, 16 hex, written by the surface's fetch script), else the surface's model version. `models.json` is read once per open (`Engines.modelsInfo`, shared with the readers; again after the session is stopped), and a kept model whose stamp matches is used **with no request at all** (until 2026-10-27 every model asked the server for its ETag with a HEAD on every open); a new deploy changes the stamp, and the model is downloaded again, once. A kept copy that can no longer be read (its stored body gone) is removed from the cache and downloaded again. A kept copy of another version is used only when the network gives no answer at all (offline); a server error or a download broken half-way is tried once more and then fails that model's start, so an old model never runs beside a new deploy's other files. With no `models.json` — or none within 4 s for the threads (`STAMPS_WAIT_MS`; the readers still wait for it) — the old ETag check is used.
- **The start timed** (the lab's log, in the browser's console, `console.debug`; Lab tools keeps one figure of it, **first frame, s** — the session's `readyMs`): `Time: …` lines for each start step with its milliseconds and when it came after the open — `models.json` read, ONNX Runtime loaded (per thread, on the page way and for the readers), the wait for `models.json`'s stamps in a thread, each model's kept copy or download, each session started, its warm-up, the GPU check (or `GPU check skipped — passed before on this device (<layout>)`), the accurate model's wait for the live frame's, the face finder (in a thread and on the page way), the readers, the accurate model and the live frame's models ready, the camera started — one `Ready: first frame after N ms` from the scanner's open to its first live answer, one `First frame: bitmap N ms, model N ms, back N ms` (where that answer's time went: scaling the frame, the model, the wait and the messages), and one `Time: next loads begin (first frame | no frame | a pick) — N ms` when the gate opens and by what (data lines in English; the site's window says nothing of them).
- **Each page's kind** — once its readouts are there (a camera shot's once the shot has settled: its refined cut would be typed again), as Admin → Scanner's document type mode says (`doctypeMode()`, the `mode` call, read when the window opens; shadow when it cannot be read): **Off** — Haiku's (`detectDoctype`, `aiDetectAlign`, on the page as JPEG 0.9); **Shadow** — Haiku's, the model's answer kept beside it (`doctypeShadow`) for the example only; **Mixed** — the model's (the session's readers' `doctypeAnswer`) when it is sure of the type (≥ 0.9, `SURE`), else Haiku's. **Each page's turn** (`src/scan/turn.ts`: `modelPick` before Haiku, `finalTurn` after it; every turn clockwise, as `turned` turns): a page the face finder set upright (its `turn` ≥ 0) keeps that turn — Haiku's never turns it again; a page with no face (a ספח, a card's back, any other page) takes the model's turn when the model is sure of the turn (≥ `SURE`, in Shadow and Mixed — whatever it says of the type, as `scripts/scan-train/docfind.py` `with_doctype` set such a page upright; a sure 0 leaves it as it is), else Haiku's (90, 180 or 270°). Haiku is asked when the model's type is not taken, or when neither the face nor the model gave the turn — Mixed sure of the type on a page with a face or a sure turn asks nothing. A page so turned is turned upright (`turned`, JPEG 0.92) and given back to the session under its id (`session.inject`, which takes back only a page the scan still holds: a turn that comes after the window closed or after Done gives nothing to the next scan — the page is still kept on the phone, turned), and what the zone and field readers read on it is dropped (read on its side, it says nothing). A page whose JPEG the phone cannot make is tried again lighter (0.7) and, failing that, recorded with no picture (Done makes it again from the cut, or leaves it out), so no page is left untyped. A page cut again (refined, or Fix corners) is typed again on its new cut. The kind the user picks on the chips wins, and is kept on the phone with the page (`onChoose`). Each page carries who set the turn it is at (`turnBy`, sent with its example): `face` when the face finder set it upright, `model` when the model's sure turn was taken, else `haiku`.
- **The model's chip** (`scan-model`, super-admin only — `superAdmin` from `src/scan/open.tsx`), under each photo in the strip with an answer from the document type model: **model** (Mixed took the model's own type), **model ✓** (the model said what the AI said) or **model ≠ AI** (it did not; `modelSaid` against `doctypeModel`).
- **Page kinds**: ID card, ID card back, Appendix (ספח), Passport, Contract, Other; an **Other** page says **Not saved** (`scan-not-saved`) and is not counted in Done nor given to the reading unless its kind is changed. A **Contract** page goes to the worker's documents as one PDF (`saveScanContract`, `src/scan/pdf.ts`).
- **The passport zone reader in shadow** (docs/hf-plan.md → H8b-2): when the site's version has `mrz.onnx` (`models.json` `"mrz": true`), the session reads the line boxes across each page (`mrzFind`, `mrzRead` — the same line finding, input and decoding as `scripts/scan-train/mrzmodel.py`) and gives their text with the page's readouts (`mrz.lines`); the window keeps them on the page (at most 2, 60 characters) and hands them with the pages to the scan process; the primary page's lines are parsed (`src/scan-process/mrz.ts` `parseMrz`: misreads mended by position — O → 0 where a digit must be — and the number by its check digit; a value only where its check digit is right) and go with the full document on the save (`mrzShadow`, H8a) — never into the worker window. Admin → Scanner shows how often the reader got the passport's number, dates and sex the user kept, against the AI.
- **The Hebrew field reader in shadow** (docs/hf-plan.md → H8c): when the version has `he.onnx` and `he-layouts.json` (`models.json` `"he": true`), the session reads each page cut to an ID card's shape at the boxes of each card layout (`heRead`, the layout whose ID number's check digit agrees and whose dates read) and gives `{layout, surname, given, idNo, dob, expiry, idOk}` with the readouts; the window keeps them on the page (`cleanHe`) and hands them to the scan process; the primary page's go with the full document on the save (`heShadow`, `src/scan-process/he.ts`: the worker fields' forms) — never into the worker window. Admin → Scanner shows how often the reader got the ID card's fields the user kept, against the AI.
- **Every attempt goes for training** (S8, docs/scan-training.md → 2; `src/scan/engine/attempts.ts`, source `site`): a camera shot or a picked picture is an attempt — the photo at most 1600 px, the first document's corners and the others found, the model version and the way. It is **kept** once Looks good was tapped on every page of it still shown, or at Done (the ones left alone too) — **held on the phone until Done** (owner 2026-10-21: a window closed without Done sends nothing) —; a page deleted goes with it as a deleted page (`pageDeleted`; told by its folder, `attemptOutcome`, once sent) — except the last page shown of a camera shot still undecided: the shot is then **retaken** (`session.remove`, as the old lab's Retake: sent at Done as a hard example with no label, the next shot in its group), never kept with every page deleted ("nothing here" on a photo that holds a document). Sent with the signed-in user's token; with no network the attempts wait on the phone (IndexedDB `scanAttempts`), 5 at most, an hour at most, and the window says **In queue: N / 5** (`scan-queue`, under the status line). **When the worker is saved** after the scan, every attempt of the scan is told `saved` with the worker's id (`attemptOutcome`; the server takes it only from the attempt's own firm, by the owner note it keeps for each attempt in Firestore `scanAttempts`), so the deletion of a worker's data on request finds them: `src/scan/server.ts` keeps this scan's attempts — each page's attempt id (`scanAttempts`, as the session gives its pages) and the folders the server gives them back (`attemptFolders`, told by the engine's `Attempts.onDirs` whenever a batch is sent, even after the window closed); a scan is one session — a new scan starts one, `resetScan` → `newScanSession`, "Scan again" keeps it; the last three are kept, as a folder may come back after the next scan began — and `sendScanDocument` → `attemptsSaved` tells them on the save (a folder that comes back later is told at once). The same session id goes with the scan's page examples and its full document, and the page examples carry the worker's id when the scan is of a known worker (a rescan from their window, `openScanner({workerId})`) and who set each page's turn (`turnBy`; docs/scan-training.md → 1).
- **The corner editor** (S8-3, `CornerEditor`): Fix corners on a page opens its photo (every attempt not sent yet keeps it: the newest six at full size, the older ones as their 1600 px training picture; never sent for this) with the corners the model found, the photo outside them dimmed and a 3×3 grid inside them to line the document's text up with (the owner's template pair 6, 2026-10-26). A corner (an L-bracket) is dragged alone to the document's corner; a whole side — both its corners — moves along its normal by the short bar at its middle or by its line itself (a press within 24 px of it); a press within 48 px of a corner or a bar picks the nearest up (a corner wins a tie), and everything stays on the photo — a side stops as a whole where one of its corners reaches the edge, keeping its direction. The picking and the moves are `src/scan/ui/quad-edit.ts` (pure, checked by `tests/scan/quad-edit.test.mjs`; the side moves by `tests/e2e/next.test.js` on the gallery's editor); there is no Straighten slider. **Apply** makes the moved corners the attempt's answer (`edgesFixed`, or `edgesMoreFixed` for another document on the photo); the page is cut again from them and given again under its id. Once its attempt was sent (every page looked at, or Done) a page can no longer be fixed (the window says so).
- **Batches** (owner, 2026-10-20): every page belongs to a batch — a camera shot (`s<n>`), the pictures of one pick (`f<n>`), the pages before a Scan again (`before`). They are **kept on this phone** (`store.ts`, IndexedDB `scanner` / `batches`, key `current`) a moment after every change, until Done has read them: a window closed by mistake (or a page the phone reloaded) opens again within 3 minutes with them first in the strip (`kept` pages: their type — the one picked by hand on them too — and Delete; their photo is gone, so no Fix corners); older than 3 minutes they are not brought back and are cleared.
- **Done · n** (n: the pages to be saved) — the camera stops, the bar and the pages are closed (no new page, no change Done would miss), the window waits for the pages' kinds — reading the pages as they are while it waits (a kind given or picked meanwhile counts; a page with no readouts yet is typed by Haiku now), at most 30 s (`WAIT_MS`; a page still untyped then goes untyped and the scan process types it), and not at all once the window is closed — sends the scan's attempts (`attempts.done`), sends the pages' document type examples in the background (`examples` → `sendFeedback`, see Training examples below), then runs `read` — the scan process — **in the same window**, with its progress (`scan-reading`); when it succeeds the scan ends (`session.done`), the batches on the phone are cleared, the window closes and the worker window opens with what was read; an error keeps the window open with the pages and the error under the status line (`scan-error`), the camera started again.
- **The phone's back** (`src/scan/ui/back.ts`, the site and the lab alike): the Android back gesture and the browser's Back button go **one step back inside the scanner**, the innermost first — the corner editor (as Cancel), then the page opened large, then (the lab) the Lab tools drawer or the sheet of what the models read, then (the site) **the scan window itself, closed as by hand** (`close`: the scan discarded, the session kept 3 minutes) — back to where it was opened from (the worker window, the page under it); it never leaves the site. Every step open has one history entry (`history.pushState`, the URL unchanged, its state `{scanBack: depth}`; `useBack(on, close)`: the scan window in `Scanner.tsx`, the page and the editor in `ScannerScreen`, the drawer in `LabDrawer.tsx`, the sheet in `LabApp.tsx`); on `popstate` every step above the depth landed on is closed, the top first. The manager page has no history handling of its own; the `/next` gallery's scanner screens set `back={false}` (its pages keep their own hash). Checked by `tests/e2e/scanner.test.js` (the site: back closes the editor, the page, then the window, the worker window under it as it was; the lab: back closes the drawer, then stays).
- **Starting pages** (`initial`, Scan again): the batch `before`, first in the strip; its pages can be deleted or have their kind changed.

## Reading (`src/scan-process/`)

`readScan(pages, progress)` (`session.ts`) runs `readPages()` (`read.ts`) over the scanner's pages `{b64, mediaType, kind, upright, mrz?}` (`upright`: turned by its face, or with a kind — Haiku turned it; `mrz`: the passport zone reader's lines on the page, from the page's readouts (`mrz.lines`) — only kept for the shadow below):

1. **Turn:** a page with no face and no kind asks `aiDetectAlign` for its turn and kind (all such pages at once) and is turned (`rotateImage`).
2. **Primary:** the first page that is not a contract / other (`isNonIdKind`) and that `aiReadDoc` reads as an `israeli_id` or `passport` is the primary. Page 1's read starts as soon as it is upright; as soon as it says ID card or passport, the following pages' reads start too (in the background, `extraReadWanted` with that read), while page 1's digits and text are re-read zoomed (`verifyDigitFields`, `verifyIdChecksum`, Zoomed re-reads below). Then `initPrimary()`.
3. **Extra pages**, merged strictly in page order (`mergePage`, Merging pages below). Which pages get a read is `extraReadWanted(primary, kind)`: after an Israeli-ID primary, every page of kind `sefach` (the ספח is a folded sheet, often photographed in parts, and the children or spouse can be on a later part), and any page while the primary still misses a core field (`missingCore`: dob, sex, address, city); after a passport, only `sefach` or `id_back`. The reader is `extraPageReader(kind)` (`ai.ts`):
   - `passport` → no AI read;
   - `id_front` → `readFrontPage` (`aiReadDoc`);
   - everything else (`sefach`, `id_back`, `contract`, `other`, unknown) → `readSefachPage` (`aiReadSefach`) — `contract` and `other` too, because the align model often files the paper ספח (a printed form) under them. It sends `part:'holder'` and `part:'family'` at once (writing the long answer is what takes the time; two halves are written in parallel) and merges them; if either half fails, one full read. Its text fields are re-read zoomed (`verifySefachFields`).
   
   A page read before the primary is found (a contract first) is kept, unread.
4. **Result:** `{record, pages}` — every page with its kind, its own read, `primary`, and `contract` (a page the AI calls a contract whose read has no ID number and no names: the worker's contract, Contracts below). No ID card or passport → null, and nothing is stored. Otherwise the primary page goes to `window.__aiScanImage` and the others (with `kind`, `contract`) to `window.__aiPacketOtherPages` — what Form 101's upload reads ([form101.md](form101.md)).

- **Progress:** `progress(text, pct)` — Straightening the pages, Reading the document (page i of n), Checking the digits again, Reading the appendix, All pages read — shown by the scan window.
- **Cache** (`imageKey`: a fingerprint of the page's image): every step of a page (its turn, its read, the primary's verified read, an extra read) is kept for the session, and a fresh copy is used each time (the merge never changes a kept read). A failed step is not kept. So reading again after Scan again reads only the pages that changed (a new page, a re-cut one); a page read twice in one run (a page 1 that is not a document) is read once.
- **Timing:** one `scan` entry (Admin → Timings): pages, kinds, `primaryReadMs`, `verifyMs`, `extraWaitMs`, `docType`, `aborted: no-document`.
- **Not done here any more** (S5): the page is not aligned, enhanced or tightened on the phone — the scanner's cut (DocAligner's corners, the user's correction) is final; there is no high-resolution twin for the zoomed crops (the server's page, ≤ 1800 px, is the source); a blurry page does not stop the reading.

### Zoomed re-reads (`verify.ts`, `crop.ts`)

- **Normalizing** (`ids.ts`): `normDigits(s)` joins grouped digits (`0 1234567 8` → `012345678`); `normDate(s)` pads to `DD/MM/YYYY`; `isValidIsraeliId(id)` — the check digit.
- **`verifyDigitFields(parsed, verify)`** builds jobs from `fieldBoxes`:
  - Israeli ID: `idNo` and `dob` (re-read every time in the same call; `__idZoomed` is set, so `verifyIdChecksum` does not read the same box again);
  - passport: `passportNo`, `dob`, `expiry` (a field taken from the MRZ with a right check digit — `passportNoFromMrz` / `dobFromMrz` / `expiryFromMrz`, set by `ai_read` — has no box and is not re-read; without an MRZ, `ai_read` swaps a reversed issue / expiry pair back and marks an implausibly short validity as "check");
  - both (`textJobs`): every boxed `given`, `surname`, `address` and `city` (`hebrewText`; a passport's names `latinName`) and `houseNumber` (`houseNumber`). All in the same one call. A field left empty is searched for after the scan instead (`autoFindMissingScanFields`, [workers.md](workers.md)).

  `verifierFor(page)` (`ai.ts`) cuts each box with a margin out of the page (`cropField`: 15 % sideways, 50 % up and down; enlarged to at least 500 px wide, at most 1100 px), then sends one `aiVerifyFields` for all of them. `applyZoomedRead` keeps only a readable value of the right shape (9 digits, `DD/MM/YYYY`, an uppercased passport number, a house number without spaces, text with single spaces):
  - **digits and dates** — the zoomed value replaces the first read. For the ID number the check digit decides: a first read that passes it is kept over a zoomed one that does not, and a zoomed one that passes it is taken without a mark;
  - **text** (`hebrewText`, `latinName`, `houseNumber`) — the zoomed value is kept beside the first read in `parsed.__zoom` and never replaces it on its own. The names are picked later from all their readings (Merging pages → holder's name); street, house number and town keep the first read.

  When the zoomed value differs from the first read (names aside), the field goes into `parsed.__uncertain`.
- **`verifySefachFields(parsed, verify)`** does the same for the ספח read's text fields.
- **`verifyIdChecksum(parsed, verifyOne)`**: if the ID number fails its check digit, one `aiVerifyField` retry of its box follows, unless it was already re-read zoomed. The result is `parsed.idChecksumOk`; a still-failing number shows an amber warning in the worker window.
- **"Check this" marks:** `workerFields` (`worker.ts`) collects the uncertain fields whose value is the one on screen (`uncertainKeys` over the record and the pages' reads) into `__scanCheck`. The worker window frames them in amber with a note (`markScanUncertain`) until the field is edited; the note's 🔍 link reads that field again (the editor's recheck in `WorkerEditor.tsx`, [workers.md](workers.md) → field search). Display only, never saved.

### Merging pages (`merge.ts`, `names.ts`)

The record is a pure function of the pages' own reads, in page order (`initPrimary` + `mergePage`; `rebuild(reads)` replays it).
- **Fields:**
  - `ID_CORE_FIELDS` = dob, sex, address, houseNumber, city, maritalStatus — filled only where the primary is empty (`mergeIsraeliIdFields`);
  - children — from every page, each child once (by ID number, else name);
  - spouse — taken from the first page that has one;
  - an ID number only where the primary has none.
- **Front page after the ספח:** it also fills an empty `given`, `surname` and `expiry`.
- **Passport + ספח** (per user decision 2026-10-04): a ספח or ID card back merged into a passport primary (`passportHolderIsIsraeli`) makes the holder an Israeli resident, recorded like an Israeli ID, as Form 101 needs. `type` becomes `israeli_id`; the Hebrew names, ID number, address and family come from the ספח. The passport's Latin names and MRZ name line become the name references; its dates, sex and `passportNo` stay. The ID number has only its check digit as a check (`idChecksumOk`). An Israeli passport itself is read as `israeli_id` by `aiReadDoc` (Hebrew names, Latin ones as `latinSurname` / `latinGiven`, `idNo` from its Identity No., `passportNo`), and then reads its ספח like an ID card.
- **The holder's name** (`resolveNames`, run by `initPrimary` and `mergePage`). `addNameReads` collects on the primary (`__names`) every reading of `given` / `surname`: the front's first read (`full`, kept in `__full`), its zoomed re-read (`zoom`), and the ספח / card back's copy (`sefach`, pages read by `readSefachPage` are tagged `__fromSefachReader`); and the references: the Latin spelling (`latinSurname` / `latinGiven`, Hebrew names only) and the MRZ names (`mrzName` → `mrzNames`). `pickName` then:
  1. all readings agree → that value; marked "check" only when a reference does not match it;
  2. a reference decides — the reading whose letters match it best, clearly better than the others (for Hebrew, consonant classes of the Hebrew letters vs the Latin spelling, `hebSkeleton` / `latSkeleton` aligned by `skeletonAlign`, so a ד misread as ר no longer matches D; for a passport, the letters against the MRZ). Usual spelling noise is allowed: ו spelled V, ח spelled H, צ as Z, כ as CH. A different consonant, or one missing or extra, counts as suspicious, and marks even a reading all sources agree on. Vowel letters (ו, י) are not compared: names are written with and without them (משה = MOSHE);
  3. two readings agree against a third → the majority;
  4. otherwise the first read stays and the field is marked "check" (`__uncertain`).

### Into the worker window (`openWorkerModalFromScan(record, reads)`, `src/manager/page/scan.ts`)

`workerFields(record, reads)` (`worker.ts`) gives only the values this scan actually found, so a rescan never blanks existing data:
- `docType`, `docGiven`, `docSurname`, `docId`, `docDob`, `docSex`, `docExpiry`;
- Israeli ID: address, house number, city, marital status (from `single` / `married` / `divorced` / `widowed`), children, spouse. A spouse sets married when no status was read;
- `idChecksumOk` and `__scanCheck` (display only).

Which worker it opens:
- a rescan (`__aiRescanWorkerId`) opens that worker;
- a new scan whose document number matches an existing worker opens **that** worker instead of a new one (toast);
- in both cases `__aiRescannedWorkerId` is set, so `saveWorker()` rebuilds Form 101 from this scan;
- otherwise a blank new worker opens.

Either way, a draft from `rescanFromWorkerModal()` is then put back (`applyWorkerDraft()`): typed values stay, empty fields take the scan's; then the empty fields are searched for (`autoFindMissingScanFields`).

### Scan again

`sessionPages()` (`session.ts`) gives this session's pages, the primary first, as the scanner's starting pages; Done reads the whole set again through the same cache, so only the added or re-cut pages cost AI calls, and the record is rebuilt from every page's read — a page removed takes its data with it.

**The passport zone reader in shadow** (`mrz.ts`, docs/hf-plan.md → H8b): `readScan` keeps the primary page's zone lines; `scanDocument` (the save after a scan, H8a) parses them — `parseMrz` finds the two TD3 lines (the last two that look like one: long, with fillers, the first starting with P), mends misreads by position (a letter where a digit must be: O → 0, I → 1…; a run of K / C among fillers → <; the number by one look-alike swapped until its check digit agrees) and gives a value only where its check digit is right (`mrzCheck`, ICAO weights 7 3 1) — the sex, which has no check digit of its own, only when the composite check digit is right (as `scripts/scan-train/mrzmodel.py` `fields`; `tests/scan/mrz-sex.test.mjs`); `mrzFields` turns it into the worker fields' forms (`docId`, `docDob` / `docExpiry` DD/MM/YYYY, `docSex`, names, `nationality`, `allChecks`) — sent as `mrzShadow` with the document, never put into the worker window.

**The Hebrew field reader in shadow** (`he.ts`, docs/hf-plan.md → H8c): `readScan` keeps the primary page's fields (`he`); `scanDocument` sends them as `heShadow` (`heShadowFields`: `layout`, `idOk`, `docSurname`, `docGiven`, `docId` — digits only —, `docDob` / `docExpiry` DD/MM/YYYY by `heDate`, the empty ones left out) when the reader found a layout — never put into the worker window.

## Contracts

An extra page that the scanner calls `contract` and whose read has no ID number and no names is marked `contract` in `__aiPacketOtherPages`. `aiFillForm101` (`src/manager/page/form101.ts`) leaves those pages out of Form 101 and, once the worker's documents are saved, `saveScanContract()` puts them together as one PDF (`imagesToPdf`, `src/scan/pdf.ts` — a page per photo, A4 wide; a JPEG up to 1654 px wide (A4 at 200 dpi, `MAX_W`) goes in as it is, a wider one — a camera page, ~3000 px — is scaled down to it, JPEG 85; a contract of 8 camera pages is ~2 MB instead of ~15) and saves it to the worker's documents as type `contract` (`saveWorkerFile`, one retry). Its end date is not read. A failure is a toast and an Admin → Errors entry, and marks the worker `contractUploadFailed`: a red **Contract not saved** notice on the plate and card (`workerNotices`, `src/manager/page/workers.ts`, with Add document as its action) until a contract document is added (`ManagerBridge.addDocs` clears it). Browser tests: "scan contract", "scan contract not saved".

## Training examples (`scan_feedback`, `functions/feedback.py`)
