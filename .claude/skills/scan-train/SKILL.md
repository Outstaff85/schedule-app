# /scan-train — retrain the scanner (owner's PC)

The whole process (what is collected, where it is kept, why each step): docs/scan-training.md.

The site collects every page whose corners a user corrected (`scan_feedback`, Firestore `scanTraining`, Storage `training/scan/`). This skill turns them into a new model version. **The lab learns first, the site follows**: a new version is only ever given to the lab here; the site gets it later, after the owner tried it in the lab (step 7). Talk to the owner in Russian.

Three kinds of training, run one or more (the bell says which is due; the passport zone reader when the owner asks):
- **Document edges** (S6, "Time to retrain the document edges model") — steps 2–4.
- **Document types** (S7, "Enough pages to train the document type model") — step 4b.
- **Passport zone reader** (docs/hf-plan.md → H8b, made-up lines only) — step 4c.
All end in the same step 5: one new version holds whatever was trained; the rest is carried over.

## 1. Check the PC
- The copies go to `~/.scan-train`; with little space on C:, the owner sets `SCAN_TRAIN_HOME` to a folder on another disk (`setx SCAN_TRAIN_HOME D:\scan-train`, a new terminal after).
- `nvidia-smi` — the RTX 4070 must be listed (training on the CPU works but takes hours; say so and ask).
- Python 3.11+ in `scripts/scan-train/.venv` (create it if missing):
  `python -m venv scripts/scan-train/.venv`, then in it
  `pip install torch --index-url https://download.pytorch.org/whl/cu124` and `pip install -r scripts/scan-train/requirements.txt`.
- Google access under the owner's own account: `gcloud auth application-default login` (once; the owner signs in in the browser). Never ask for keys or passwords in chat.
- Hugging Face, the models' home (`OutStaff/scanner-models`, public; docs/hf-plan.md): the owner's token on the PC — `hf auth whoami` must say `OutStaff` (else the owner runs `hf auth login`; the token is never pasted in chat). The owner's PC keeps it in `H:\hf\home` (`HF_HOME`).
- Once, before the first training on Hugging Face: `python scripts/scan-train/move_to_hf.py --apply` (the versions still in Storage go to Hugging Face as tags) and `python scripts/scan-train/rename_fields.py --apply` (the records collected before H0 get today's names). Each says what it would do without `--apply`; both are safe to run again.

## Stopped in the middle
Every training saves its progress after each epoch (`~/.scan-train/checkpoints/`; the passport zone reader in `~/.scan-train/mrz-ckpt/`). If one stopped (Ctrl+C, a crash, the PC turned off), run the same command again with `--resume` (only with the same data: drawn again or pulled again, it is refused — start without it); to train the edges, document type or Hebrew model further from where its last run ended, `--more` (the zone reader starts from its best weights by itself; `--fresh` for random ones). `--more` is refused when the class table or `heldout.json` changed since, when examples it trained on are on the exam side today (a record moved there), or the checkpoint is from before Training 4 or its review fixes (no data fingerprint, no training ids): train fresh, or `--more-anyway` only on the owner's explicit call; the edges' `--more` builds the network from the saved weights' own base by itself (docs/scan-training.md → Stopped and picked up again).

## 2. Download the examples
`python scripts/scan-train/pull.py` — prints how many examples (and how many came from the scan attempts, S8), how many kept apart for the exam. Fewer than ~100 to train on: tell the owner it is early and ask whether to go on. Then, in `scripts/scan-train`, `python -m gen real` — every real labelled picture in one index, labelled only from what a person did (read-only; tell the owner the counts by `labelBy` and split, never a name) — and `python -m gen mix --model edges --synth-run <a made-up set> --real-repeat 30` (tell the owner the real share of an epoch: 20–30 % is the aim); train on it with `train.py --from-mix ~/.scan-train/models/edges` (docs/scan-training.md → Real data and its weight). When `gen real` ran again after the mix, the training refuses it ("real index changed since the mix", or rows on the exam side today): run `gen mix` again.

## 3. Train
With few examples (or when the owner asks), made-up photos first: `pip install -r scripts/scan-train/requirements-synth.txt` once. The scenes (one camera for the table and the documents; docs/scan-training.md → Scenes, The background bank), in `scripts/scan-train`: `python -m gen bg pull`, `python -m gen bg add ~/.scan-train/backgrounds --category auto` (once; the owner's own shots with `--owner`), `python -m gen bg check` (tell the owner the counts by category and the rejected photos; a photo the edges model sees a document in is never used) and `python -m gen bg split`, then `python -m gen build --model edges --count 8000` and `python -m gen qa --run ~/.scan-train/gen/runs/edges-s1-n8000` — train on it with `train.py --synth N --synth-run ~/.scan-train/gen/runs/edges-s1-n8000`. Today's flat photos stay available: `python scripts/scan-train/synth_docs.py --count 20000` (on the bank's training-side photos once `bg split` has run; add `--backgrounds <folder>` if the owner has photos of tables and floors; `--count 40 --show` to look at them first, `~/.scan-train/synth/docs/show/`), and MIDV — real photos of mock documents (once: `python scripts/scan-train/midv.py --download midv2020 --drop-raw` — the sets made, the download deleted; then `python scripts/scan-train/datasets_hf.py push` keeps them in the private bucket, and on another PC `datasets_hf.py pull` brings them back instead of downloading again). Before the first version trained with MIDV goes to the site, remind the owner of its terms (docs/scan-training.md → MIDV). Paper pages from SmartDoc (CC BY 4.0; once: `python scripts/scan-train/smartdoc.py --download --drop-raw`, then `datasets_hf.py push`). The firm's own pages as templates: `python scripts/scan-train/pull_templates.py`, then `synth_docs.py --templates` (the pages `heldout.json` keeps for the exam are never laid; `python -m gen sources --check` in `scripts/scan-train` shows nothing the exam keeps is on the training side) and `synth_docs.py --templates --exam` (the exam photos of those pages; their face and text washed out; they are workers' documents and stay on the PC). Every made-up set needs its QA sheet before training: `python -m gen qa --run ~/.scan-train/synth/docs` (in `scripts/scan-train`; also `synth/pages`, `synth/he-fields/train`) — it draws a sample again byte for byte and writes `qa/index.html`; open it, show the owner the line "intersection with held-out = 0", and only then train (the trainings refuse a set without a passed QA; docs/scan-training.md → Made-up sets: build, verify, QA). Train with `--synth N --midv M --smartdoc K` — together about as many as the real examples up to a few times as many, and with thousands of them `--epochs 3`–`5` (docs/scan-training.md → Made-up document photos, MIDV).

`python scripts/scan-train/train.py` — both document edges models (`edges-lite.onnx` for the phone's live frame, `edges.onnx` for the server), starting from the lab's current version (`scripts/scan-lab/models-version`). ~15–30 min on the 4070. Each epoch prints its loss; it must go down. It prints its seed (fresh unless `--seed`; give it again to repeat a run), the counts per source and the real share; it warns when `examples.json` is older than the newest scan attempt — run `pull.py` / `gen real` again then.

## 4. Exam
`python scripts/scan-train/exam.py` — the pages never trained on, **the parent** (the version the training started from; `--base` names another) **and the lab's version vs new**, set by set: E1 the users' pages kept apart, the exam photos of the owner's real pages kept apart (`synth_docs.py --templates --exam`), E2 the held-out templates on the exam backgrounds (`python -m gen build --model edges --exam` first), E3 MIDV-2020's and SmartDoc's exam documents when those sets are on the PC (no-regression checks only: the base model saw them), E4 the phone's input path, E5 a card on its sheet (mixed corners): mean corner error, share within 2 %, share not found, the extra pages found where the user deleted one and the retaken pages. Show the owner this report in plain words (parent → new, and each rule that failed), and point them to the picture report it opens in the browser (`~/.scan-train/report.html`: the 10 exam pages where the models differ most, the parent's corners red, the new blue, the right ones green — it stays on the PC). "unchanged model — nothing to publish": the new file is the parent's or the lab's. "heldout.json changed since these exam sets were drawn": run the command it prints, then the exam again. If it says "NO — do not publish", say so and recommend `clean.py`.

## 4b. Document types (S7)
1. `python scripts/scan-train/pull_doctypes.py` — the page copies with their kinds; prints how many per kind. A kind with fewer than ~80 to train on: say it is early, ask whether to go on.
2. `python scripts/scan-train/train_doctypes.py` — the phone's model (EfficientNet-Lite0, `doctype-lite.onnx` — the only one trained and published; owner, 2026-10-24), from ImageNet weights (downloaded once by timm). A server's Lite2 only when the owner asks (`--only server`); it is never published. ~10–20 min on the 4070. The loss must go down.
3. `python scripts/scan-train/exam_doctypes.py` — the exam pages, the new model beside the lab's doctype-lite: kind right (by type, by document, contract / other), how many it is sure of (≥ 90 %) and how right those are, **the turn exam** (only pages whose turn is known; sure turns right ≥ 98 %), "your documents" both editor-cut and phone-cut (the lab's own shot), and **the site's way** (the model where sure of type and turn, Haiku elsewhere) against **Haiku alone**, weighed by how the pages were sampled. Show the owner this in plain words, with each rule that failed.
4. When it says a model is worse, it prints the next size up (owner, 2026-10-19: Lite0 → Lite1 → Lite2… until the result is right): run that `train_doctypes.py --phone tf_efficientnet_lite1`, then `exam_doctypes.py` again (after every training: the training deletes the old report). At Lite4 and still worse: more page copies are needed — `clean.py`, and wait for the bell.

   Before the site has its own page copies (or beside them): `python scripts/scan-train/synth_pages.py --count 6000` (made-up pages of every kind — drawn, the owner's real pages made other people's, SmartDoc, MIDV), then `python -m gen qa --run ~/.scan-train/synth/pages` (in `scripts/scan-train`; open the sheet) and `train_doctypes.py --synth 6000`. Pages cut the phone's own way (the lab's edges model, the face's turn; docs/scan-training.md → The phone's own cuts): `python -m gen build --model doctype,mrz,he,face --count 2000` and `python -m gen qa --run ~/.scan-train/gen/runs/cuts-s1-n2000` (show the owner the IoU histogram, the editor share and the short classes), then `train_doctypes.py --synth N --synth-run ~/.scan-train/gen/runs/cuts-s1-n2000` (and `train_he.py --phone-run` the same folder). A new edges version: draw it again (the cache is per edges model). With no page copies from the site the exam has nothing to measure: say so, and that the lab (then the site's shadow against Haiku) shows how it does.

## 4c. Passport zone reader (H8b)
1. Once: `pip install --no-deps trdg==1.8.0` and `pip install -r scripts/scan-train/requirements-synth.txt` in the same `.venv`.
2. `python scripts/scan-train/synth_lines.py mrz --count 100000` — the made-up zone lines (OCR-B, on every core but the first, at low priority; ~5–10 min) into `~/.scan-train/synth/mrz/`. Nothing of it is uploaded.
   With MIDV downloaded (step 3), also `python scripts/scan-train/midv_mrz.py` — real zone lines of MIDV-2020's mock passports for training (documents 00–69), the real check lines that pick the epoch and keep `best.pt` (70–79, `midv-mrz/select/`; run it again when that folder is missing), and exam pages (docs/scan-training.md → The passport zone reader); then train with `train_mrz.py --midv` — the first time after `midv_mrz.py` kept 70–79 apart, with `--fresh` (a `best.pt` from before learned those lines: `train_mrz.py` refuses to be picked on them from it, and compares it on the made-up lines only).
3. `python scripts/scan-train/train_mrz.py` — the small CRNN (`mrz.onnx`), ~10–20 min on the 4070; each epoch prints the lines read right on the check lines — it must go up to ≥ 93 % (the exam also needs ≥ 95 % of MIDV's real exam passports with every check-digit field right). It starts from the best weights of the trainings before (`~/.scan-train/mrz-ckpt/best.pt`, kept by `clean.py` / `publish.py`; `--fresh` from random weights); a stopped training goes on with `--resume`.
4. `python scripts/scan-train/exam_mrz.py` — the made-up check lines, the real passports collected (H8a; a field not read counts wrong), MIDV-2020's exam passports (real photos never trained on: it stops without `midv-mrz/exam` — `datasets_hf.py pull midv-mrz`, or `--no-midv` on the owner's word) and the phone's path (a cut exam run: `python -m gen build --model doctype,mrz,he,face --exam --editor-cap 1 --bad-share 1`), each set against the AI and **the lab's reader**; say plainly when no real passport was examined (realExamined false). Show the owner in plain words; "NO" → more lines (`--count 200000`) or more epochs (`train_mrz.py --epochs 20`), then the exam again.

## 4d. Hebrew field reader (H8c — on the PC only for now; when the owner asks)
1. `python scripts/scan-train/pull_templates.py` (the owner's marked pages; `template_fields.json` names them).
2. `python scripts/scan-train/synth_fields.py --count 3000` and `python scripts/scan-train/synth_fields.py --count 300 --check`, then `python -m gen qa --run ~/.scan-train/synth/he-fields/train` (in `scripts/scan-train`; open the sheet — `train_he.py` refuses the set without it).
3. `python scripts/scan-train/train_he.py` (~10–20 min on the 4070; `--phone-run <run>` adds the fields cut the phone's own way) — the check pages split in two (select picks the epoch, exam is the gate): the gate is the 5 roles the phone reads on the held-out ID card fronts (each ≥ 90 %) and the ID numbers' check digit (≥ 95 %), on unseen values (`--phone-exam <cut exam run>` adds the phone's own cuts of the held-out cards); every field by kind is for information. Show the owner; "NO" → more pages (`--count 6000`) or epochs (`--epochs 30`). On "YES" `publish.py` puts `he.onnx` with `he-layouts.json` into the version; the lab reads ID cards with it, the site in shadow beside the AI (Admin → Scanner → Hebrew field reader).

## 5. The owner decides
- **Yes** → name exactly the models the owner said yes to: `--edges`, `--doctypes`, `--mrz`, `--he` (with no flag `publish.py` only lists the reports it found). First `python scripts/scan-train/publish.py <flags> --dry-run` and show the owner its plan (the files of the version — new or carried over —, the counters, the attempt folders to move; nothing is written). Then `python scripts/scan-train/publish.py <flags>`: the new version goes to Hugging Face as one commit tagged `v<N>` (https://huggingface.co/OutStaff/scanner-models/tree/v<N>, with the reports of the models named; every model not named is carried over from the lab's version), the counters of the models published are reset (`edgesSince` with the edges, `doctypesSince` with the document type model), `scripts/scan-lab/models-version` names `v<N>`, the scan attempts leave `attempts/new/` (only with `--edges`: the ones trained on to `attempts/used/v<N>/`, the exam ones to `attempts/exam/`; `attemptsSince` lowered by the folders really moved), the exam reports of the models published (and `attempts.json` with `--edges`) are deleted — the other reports and `report_mrz_train.json` stay —, and the other copies on the PC too (`--keep-copies` keeps those when another training still needs them). It refuses a report written for another file than the one in `new/` ("is for a different model; run the exam again" — run that exam again), and a model whose file is the very one of the lab's version (nothing new). A model whose exam said "not worth publishing" is left out unless the owner explicitly says to publish it anyway (`--force-edges`, `--force-doctypes`, `--force-mrz`, `--force-he`); `--force-doctypes` is refused while the only exam is "your documents" with a document type or the turn not measured (or its sure turns right on less than 98 %).
- **No** → `python scripts/scan-train/clean.py` (deletes the copies; nothing changes on Hugging Face).

## 6. Give the new version to the lab
Commit `scripts/scan-lab/models-version` (and `scripts/scan-train/heldout.json` when `publish.py` said it marked the new version not held-out clean — its models carried over or trained from v3–v5's) on the work branch and deploy it the usual way (CLAUDE.md → Git workflow: Tests workflow, PR, merge with the owner's OK). The lab (`/scan-lab/`, Admin → Scanner lab) then runs `v<N>`; the owner tries it on the phone — with document type models in the version, every shot also shows the document type, how sure, and the turn it needs.

## 7. Later — give it to the site (only when the owner says the lab is better)
Set the same version in **both** `scripts/scan/models-version` (the phone's models) and `functions/scan_models_version.txt` (written into each training example; a test keeps them equal), then deploy. The site's scanner is the lab's page (`scan/`), so it runs the version the way the lab does. Rolling back = the previous version in the same files.
